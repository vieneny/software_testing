# 环境准备与学习方法

本页说明最低环境、隔离原则和学习方法。需要从零安装 Python、PyCharm、MySQL、
Node.js、Conda、抓包工具、接口工具、Appium、性能工具和报告工具时，请直接进入
[Windows / macOS 测试工具安装与快速使用知识库](./05-测试工具安装与快速使用/README.md)。
该知识库将 Windows 与 macOS 分开讲解，并提供安装验证、最小实践、自检脚本和故障排查。

本仓库的命令示例覆盖 Windows PowerShell、macOS 终端、Linux 和 WSL。执行前先确认
当前平台与 shell，不要在 Windows PowerShell、CMD、zsh 和 Bash 之间机械复制命令。

## 最小环境

- Git；
- Python 3.11 或更高版本；
- 能执行命令的终端；
- 一款代码编辑器；
- Chrome / Chromium；
- Docker（进入 CI、依赖服务和可复现环境章节时再安装）；
- Node.js（运行 k6 之外的部分前端工具或 promptfoo 时按需安装；k6 本身不是 Node 包）。

先检查，不要急着全局安装大量工具：

```bash
git --version
python3 --version
python3 -m pip --version
docker version
node --version
```

版本号会变化，本教程尽量使用稳定的主版本范围而非绑定某个补丁版本。若官方文档与教程命令冲突，以官方当前文档为准，并提交勘误。

## Python 项目隔离

每个实验使用独立虚拟环境：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

Windows PowerShell 激活命令通常为：

```powershell
.venv\Scripts\Activate.ps1
```

始终用 `python -m pip` 明确 pip 所属解释器。不要把 `.venv`、密钥和本地报告提交到 Git。

## 建议掌握的终端能力

```bash
pwd                     # 当前目录
ls -la                  # 包含隐藏文件的目录内容
find . -name '*.log'    # 查找文件
rg 'error|timeout' .    # 快速搜索文本
ps aux                  # 查看进程
lsof -i :8000           # 查看端口占用（macOS/Linux）
curl -i http://127.0.0.1:8000/health
```

不要在不理解目标范围时执行递归删除、批量替换或清理命令。教程中的清理步骤也要先列出目标，再执行。

## 从“看懂”到“掌握”的五步法

### 1. 最小成功

按照文档运行一个最小示例，确认环境和心智模型基本正确。记录命令、输出和版本。

### 2. 主动失败

改变一个条件制造失败，例如错误状态码、缺少字段、超时、定位器变化、阈值未达标。观察错误是否能帮助定位。

### 3. 解释机制

不用术语堆砌，回答三个问题：

- 输入经过了哪些关键步骤？
- 哪一层负责当前行为？
- 如果结果错误，最小的定位证据是什么？

### 4. 工程化

消除硬编码、重复、顺序依赖和敏感日志，把命令放入 README 或 CI。工程化不是先造框架，而是让下一位使用者能可靠复现。

### 5. 迁移

换一个公开或虚构场景重新实现。只能在原示例中成功，通常说明记住了步骤，还没有掌握方法。

## 提问与排错模板

高质量问题应包含：

1. 目标：期望完成什么；
2. 环境：操作系统、运行时和关键依赖版本；
3. 最小复现：尽量少的公开示例；
4. 完整命令和错误文本；
5. 已尝试的验证及结果；
6. 去除 Token、Cookie、域名、账号和公司数据后的日志。

截图通常不可搜索，也可能泄露信息。优先提供经过检查的文本错误和最小代码。

## AI 辅助学习的正确姿势

可以让 AI：

- 解释陌生概念并给出反例；
- 从公开的虚构需求生成第一版风险清单；
- 对测试代码做可维护性审查；
- 根据脱敏失败日志提出多个可验证假设；
- 生成合成边界数据；
- 把复盘整理为清晰结构。

但必须：

- 先界定数据能否发送给该服务；
- 要求 AI 区分事实、推断和未知；
- 运行代码、核对协议与官方文档；
- 主动加入反例和对抗样本；
- 记录人工修改，而不是把生成结果直接当答案；
- 对最终测试结论承担责任。

## 每周复盘

每周只回答四个问题：

- 我现在能独立完成什么？证据在哪里？
- 哪个失败最有价值？我如何定位的？
- 哪个知识点仍只能复述、不能迁移？
- 下周最小的可验收成果是什么？

持续产出小而可靠的证据，比一次搭建庞大但不可维护的“万能框架”更接近真实工作能力。
