# 工具选择与安装顺序

## 1. 先确认学习任务

| 任务 | 最小工具组合 | 暂时不需要 |
|---|---|---|
| 学 Python 接口自动化 | Python 3.12、venv、PyCharm 或 VS Code、Git、Apifox | Conda、Appium、JMeter |
| 学 Web UI 自动化 | 上述组合 + Playwright | 手工下载 ChromeDriver |
| 学 Android 自动化 | Node.js LTS、JDK 21、Android Studio/SDK/ADB、Appium 3、Inspector、Python 客户端 | Xcode、XCUITest |
| 学 iOS 自动化 | macOS、Xcode、Node.js LTS、Appium 3、XCUITest Driver、Inspector | Windows 环境 |
| 学 Java 测试开发 | JDK 21、Maven Wrapper、IntelliJ IDEA 或 VS Code、MySQL/Docker | 全局安装多个 Maven |
| 学接口探索与 Mock | Apifox；Mockoon 作为本地独立 Mock 选修 | 同时装所有 API 客户端 |
| 学 HTTP(S) 抓包 | Reqable、Fiddler Everywhere、Charles 三选一 | 同时信任多张代理根证书 |
| 学性能测试 | k6 或 JMeter + 本机 Mock 服务 | 直接对公网演示站加压 |
| 学报告 | pytest 自带报告起步；需要展示时加入 Allure | 一开始设计复杂报告平台 |

## 2. Python 与 Conda 的关系

Python 官网安装器和 Miniconda 都能提供 Python 解释器，但管理方式不同。

### 选择官网 Python + venv

适合：

- Web、接口、App 自动化；
- 常规后端和脚本；
- 想理解标准 Python 工具链；
- 项目依赖主要来自 PyPI。

每个项目：

```bash
python -m venv .venv
```

### 选择 Miniconda

适合：

- 数据科学、机器学习、需要原生科学计算包；
- 同时维护多个差异较大的 Python 版本；
- 团队已经使用 `environment.yml`。

每个项目：

```bash
conda create -n testlab python=3.12
conda activate testlab
```

### 可以共存，但不要混用

电脑上可以同时存在 CPython 和 Conda，但一个项目只选择一个解释器：

- `where python`（Windows）或 `which -a python3 python`（macOS）确认实际解释器；
- `python -m pip --version` 确认 pip 安装目标；
- PyCharm 中确认项目解释器路径；
- 不要在已激活 Conda 环境中再创建 `.venv`，除非你清楚两层环境的意义。

## 3. IDE 的关系

### PyCharm

- Python 项目体验完整，调试、测试运行、虚拟环境管理直观；
- 统一版核心功能免费，专业功能是否可用以当前授权为准；
- 自带 JetBrains Runtime，运行 PyCharm 不需要另装 JDK；
- 它仍然需要一个独立 Python 解释器。

### VS Code

- 轻量、跨语言，适合同时学习 Python、JavaScript、Java 和 YAML；
- 需要按项目安装扩展；
- 编辑器本身不是 Python、Node.js 或 Java 运行时。

只要能清楚解释“编辑器、解释器、包管理器、项目虚拟环境”的差异，先用哪一个都可以。

## 4. 接口工具的关系

| 工具 | 更适合 | 注意 |
|---|---|---|
| Apifox | 国内团队的 API 设计、调试、Mock、场景测试一体化 | 默认只使用公开/合成数据；敏感项目用离线或批准的私有化方案 |
| Postman | 国际生态、公开集合、多协议 API 探索 | 分清本地值、云同步、Vault 和团队工作区 |
| Reqable | API 调试与抓包结合、移动端协同 | 安装 CA 后具备读取 HTTPS 明文的能力 |
| Fiddler Everywhere | 跨平台 Web 调试、规则和重放 | 账号与商业授权；Classic 仅 Windows 且不作为新项目主线 |
| Charles | 稳定的跨平台代理抓包、Map Local/Remote | 商业软件，有试用期；只对必要域名启用 SSL Proxying |
| Wireshark | TCP/TLS/DNS 等网络层分析 | 不是 HTTP API 客户端；抓包范围可能非常大 |

## 5. Web 自动化的驱动策略

### Playwright

安装 Python 包后还要安装匹配的浏览器：

```bash
python -m pip install pytest-playwright
python -m playwright install
```

Playwright 版本与其下载的浏览器二进制绑定。升级包后通常需要重新执行浏览器安装命令。

### Selenium

现代 Selenium 自带 Selenium Manager。一般只需：

```bash
python -m pip install --upgrade selenium
```

代码使用 `webdriver.Chrome()` 或 `webdriver.Edge()` 时，Selenium Manager 会在需要时发现、下载和缓存匹配驱动。不要再把旧 `chromedriver` 永久放到 `PATH`，否则它可能覆盖自动管理结果。

### Safari

Safari 使用 macOS 自带的 `/usr/bin/safaridriver`，不下载 ChromeDriver。首次执行：

```bash
safaridriver --enable
```

Playwright 的 WebKit 是测试版 WebKit 构建，不等于真实 Safari；验证真实 Safari 兼容性时用 Safari WebDriver。

## 6. Appium 3 的依赖链

```text
测试代码（Python / Java）
        ↓ WebDriver 请求
Appium 3 Server（Node.js）
        ↓
平台 Driver
  Android: UiAutomator2 → Android SDK / ADB → 模拟器或真机
  iOS: XCUITest → Xcode / WebDriverAgent → 模拟器或真机
```

关键结论：

- Appium Server 不自带平台 Driver；
- Appium 3 要求满足官方范围的 Node.js 和 npm，当前课程使用 Node.js LTS；
- Android 可在 Windows 和 macOS 上做；
- iOS 主线必须使用 macOS + Xcode；
- Appium Inspector 是独立客户端，不是 Appium Server；
- Appium 2 存量项目不能无脑安装最新版 UiAutomator2 Driver。

## 7. 最小安装路线

### 第一天：基础

```text
Git → Python 3.12 → IDE → 建立 .venv → 执行一个 pytest
```

### 第二天：接口

```text
Apifox → 公开 Echo API → 环境变量 → 状态码/JSON 断言 → 导出结果
```

### 第三天：Web

```text
Playwright → 浏览器安装 → example.com → 定位元素 → 截图/Trace
```

### 第四天：数据与服务

```text
Docker Desktop → MySQL 容器 → 数据库客户端 → 建库/增删改查 → 删除容器
```

### 第五至第六天：Android

```text
Node LTS + JDK → Android Studio/SDK/ADB → 模拟器或个人测试手机
→ Appium 3 + UiAutomator2 → Doctor → Inspector → 首个脚本
```

### 第七天：性能与报告

```text
本机 Mock → k6/JMeter 低负载 → 阈值 → 结果解释 → Allure 报告
```

## 8. 何时不要安装

- 公司设备策略禁止自行安装软件或根证书；
- 操作系统低于官方支持范围；
- 不确定 CPU 架构；
- 现有项目已经通过版本管理器固定运行时；
- 只是为了“工具越多越专业”；
- 目标环境没有明确授权，尤其是抓包和性能测试。

遇到这些情况，先读项目说明和官方系统要求，再决定安装方式。
