# 升级、卸载与版本冲突

## 1. 更新不是越快越好

工具更新分为：

- 安全补丁：优先评估并及时更新；
- LTS 小版本：通常风险较低，仍需回归；
- 大版本：可能改变配置、协议、Driver 和插件；
- Current / Preview / Canary：只用于独立试验环境。

生产式学习项目应该固定：

- Python 包锁定或约束；
- `package-lock.json`；
- Maven/Gradle Wrapper；
- Docker 镜像标签和必要时 digest；
- Appium Server 与 Driver 主版本；
- CI 运行时版本。

## 2. 一次只升级一层

推荐流程：

```text
1. 记录旧版本、安装来源和配置路径
2. 阅读官方 Release Notes / Migration Guide
3. 备份公开学习配置，不备份公司数据
4. 只更新一个组件
5. 运行版本命令
6. 运行最小用例
7. 运行项目回归
8. 记录结果或回滚
```

不建议：

```text
同时更新 Python、Playwright、浏览器、pytest 和 IDE
```

这会让失败无法归因。

## 3. 常见版本冲突

### Python

```text
系统 Python
Python 官网安装
Conda Python
项目 .venv
IDE 配置解释器
```

处理：

- 不删除 macOS `/usr/bin/python3`；
- Windows 用 `py list`，macOS 用 `which -a python3`；
- 每项目一个 `.venv` 或 Conda 环境；
- 用 `python -m pip`；
- IDE 显式指向项目解释器。

### Node.js / npm

冲突来源：

- 官方安装器；
- Homebrew；
- nvm / nvm-windows；
- Rosetta x64 与 Apple Silicon arm64；
- 旧的全局 npm prefix。

处理：

```bash
node -p "process.execPath"
node -p "process.arch"
npm config get prefix
```

不要使用 `sudo npm install -g` 修复权限。选择一种 Node 管理方式，记录并迁移全局工具。

### Java

```bash
java -version
javac -version
```

版本一致仍不代表路径一致。Windows 查 `where.exe java`；macOS 查 `/usr/libexec/java_home -V`。构建工具可能使用自己的 Toolchain，继续检查 Maven/Gradle 输出。

### Browser / Driver

- Selenium 主线使用 Selenium Manager；
- Playwright 使用它自己的浏览器构建；
- Safari 使用系统 `safaridriver`；
- 手工固定 Driver 时与浏览器版本严格匹配；
- PATH 中旧 Driver 会覆盖自动管理结果。

### Appium

Appium Server 与平台 Driver 独立：

```bash
appium --version
appium driver list --installed
```

- 项目本地安装时，在 Appium 项目目录把上述命令写成 `npx appium ...`；
- Appium 3 使用兼容的当前 UiAutomator2/XCUITest；
- Appium 2 存量项目固定其兼容 Driver；
- 不在一个全局 npm 环境反复覆盖 2/3；
- 升级前保存 `npm list -g --depth=0` 和 Driver 列表。

### MySQL

MySQL Server、客户端、Connector、Workbench 的版本线不同。升级前：

- 读官方升级路径；
- 备份自己的公开学习数据；
- 测试应用 Connector；
- 不把 Workbench 能连接等同于所有管理功能兼容；
- 不跨大版本直接覆盖数据目录。

### Allure

Allure 2 和 3 都可能提供 `allure` 命令：

```bash
allure --version
```

Windows 查 `where.exe allure`，macOS 查 `which -a allure`。新项目优先 `npx allure` 使用项目本地 Allure 3，避免全局命令冲突。

## 4. 更新命令速查

以下命令只说明机制，执行前仍阅读项目迁移说明。

### Python 项目

```bash
python -m pip list --outdated
python -m pip install --upgrade <明确的包>
python -m pip check
python -m pytest
```

### Node 项目

```bash
npm outdated
npm update
npm test
```

大版本不要直接 `npm update` 代替迁移阅读。

### Homebrew

```bash
brew update
brew outdated
brew upgrade <明确的包>
brew cleanup --dry-run
```

### WinGet

```powershell
winget upgrade
winget upgrade --id <明确ID> -e
```

### Appium Driver

```bash
appium driver list --installed
appium driver update <driver-name>
appium driver doctor <driver-name>
```

先确认更新后的 Driver 支持当前 Appium 主版本。

## 5. 卸载原则

1. 记录明确目标；
2. 用原安装器或原包管理器；
3. 先卸载应用，再决定是否清理配置/缓存；
4. 配置、项目、数据库数据和凭据分开判断；
5. 不对用户目录执行递归删除；
6. 删除证书前核对颁发者、指纹和用途。

## 6. 平台清理重点

### Windows

- 设置 → 应用 → 已安装的应用；
- `winget uninstall --id <明确ID> -e`；
- 用户/系统 PATH；
- Windows 服务；
- 系统代理；
- 当前用户/本机证书库；
- WSL 分发版、Docker 容器/卷；
- `%USERPROFILE%\.appium` 和 Android AVD；
- Playwright 浏览器缓存。

### macOS

- 原 DMG/PKG 的官方卸载说明；
- `brew uninstall <明确formula>` / `brew uninstall --cask <明确cask>`；
- `~/.zprofile`、`~/.zshrc` 中 PATH；
- LaunchDaemon / Login Item；
- Network Proxies；
- Keychain 中临时抓包 CA；
- `~/.appium`、Android SDK/AVD、Xcode DerivedData；
- Docker 镜像/卷和 Playwright 缓存。

把 `.app` 拖入废纸篓不一定会删除 PKG 安装的服务、数据或证书。按厂商卸载文档操作。

## 7. 证书和代理复原

抓包工具升级/卸载后一定检查：

```text
[ ] 工具已停止
[ ] 系统 HTTP/HTTPS 代理恢复
[ ] 移动设备 Wi-Fi 代理恢复
[ ] 工具 CA 已从测试电脑和设备删除
[ ] 浏览器/Java 独立证书库无残留
[ ] HAR/SAZ/Session/PCAP 已清理
```

不要批量删除不认识的根证书。
