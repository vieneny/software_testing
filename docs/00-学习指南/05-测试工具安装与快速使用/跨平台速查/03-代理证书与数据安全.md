# 代理证书、抓包与数据安全

## 1. 为什么 HTTPS 抓包需要根证书

HTTPS 正常链路是客户端直接验证服务端证书。Reqable、Fiddler 或 Charles 要查看明文时，会在本机充当调试代理：

```text
测试客户端 ← TLS A → 调试代理 ← TLS B → 目标服务
```

代理为目标域名动态签发一张本地证书。只有测试设备信任该工具生成的根证书，TLS A 才能建立。因此，信任代理 CA 等于授予工具解密经过它的 HTTPS 流量的能力。

## 2. 允许的实践范围

只捕获：

- 本机 Mock 服务；
- 专用练习应用；
- 专门用于测试的公开 API；
- 你自己开发的应用；
- 已获得明确授权的测试环境与测试账号。

禁止捕获或保存：

- 公司生产、预发布或内网业务流量；
- 真实客户、同事或第三方账号；
- 银行、支付、医疗、身份认证等私人会话；
- Cookie、Token、密码、客户端私钥；
- 未经授权设备上的任何流量。

## 3. 安全安装 CA 的步骤

1. 先关闭邮箱、网银、IM 和其他无关应用；
2. 在抓包工具中确认 CA 是当前安装实例生成的；
3. 只安装到当前个人测试用户或专用测试设备；
4. 只对目标测试域名启用 HTTPS 解密；
5. 完成最小实验；
6. 停止系统代理；
7. 从系统信任库和移动设备删除该 CA；
8. 删除包含敏感字段的会话和导出文件；
9. 再次访问普通 HTTPS 页面，确认系统代理已恢复。

不要从聊天群、网盘或教程附件导入别人提供的根证书。

## 4. 证书钉扎不是“工具坏了”

以下情况可能导致安装 CA 后仍无法解密：

- App 使用证书钉扎；
- Android 7+ 应用默认不信任用户安装的 CA；
- 应用使用双向 TLS；
- 流量不走系统 HTTP 代理；
- QUIC/HTTP/3、VPN 或安全软件改变了链路；
- App 自己带有独立证书库。

对自己开发的 Debug 构建，可由开发在调试配置中允许测试 CA。不要为了抓第三方 App 而绕过证书钉扎、Root/Jailbreak 设备或修改安全机制。

## 5. Android 测试注意

- 个人测试手机与电脑应在可信的同一网络；
- 开启 USB 调试后只授权自己的电脑；
- 无线调试结束后在设备中“忘记”该工作站；
- 测试完成关闭 USB / 无线调试；
- Android 7+ 的自有 Debug App 应通过 `network-security-config` 显式信任用户 CA；
- 不在日常主力手机长期保留代理 CA。

## 6. iOS 测试注意

- 安装描述文件后，还需要在证书信任设置中显式开启信任；
- 只在专用测试设备或模拟器使用；
- 练习完成同时删除描述文件和根证书；
- 真机自动化还涉及开发者模式、签名和 Provisioning Profile，它们与抓包 CA 是不同概念。

## 7. 导出文件的风险

| 文件 | 可能包含 |
|---|---|
| HAR | URL、Header、Cookie、请求体、响应体、耗时 |
| SAZ | Fiddler 完整会话 |
| Charles Session | Charles 抓包会话和内容 |
| PCAP / PCAPNG | 网络数据包、地址、DNS、协议元数据 |
| Appium 日志 | Capability、包名、设备标识、页面结构 |
| ADB logcat | App 日志、设备与账号相关信息 |
| 测试报告 | 截图、响应、路径、环境信息 |

处理规则：

- 默认不提交 Git；
- 默认不上传云盘、在线分析工具或 AI 服务；
- 分享前逐字段脱敏，不能只修改文件名；
- 练习使用合成账号，如 `learner@example.test`；
- Token 只使用短时、低权限测试 Token；
- 报告附件只包含复现所需最小证据。

建议 `.gitignore` 至少覆盖：

```gitignore
*.har
*.saz
*.chls
*.pcap
*.pcapng
allure-results/
allure-report/
test-results/
playwright-report/
*.log
.env
```

## 8. SaaS API 工具注意

Apifox、Postman、Fiddler Everywhere 等工具可能提供账号、团队协作或云同步能力。个人学习时：

- 使用公开、合成 API 项目；
- 私密值只保存在本地值或经过批准的 Secret/Vault；
- 不把公司 OpenAPI、集合、环境、数据库连接导入个人空间；
- 不复用公司邮箱、SSO 或组织许可证；
- 不确定数据流向时选择离线工作区或本地开源 Mock。

## 9. 性能测试授权

性能测试会主动制造负载。即使目标是“公开演示站”，也不代表允许压测。

允许：

- `127.0.0.1` 本机服务；
- 自己创建的 Docker / Mock 服务；
- 明确声明允许负载测试的靶场；
- 有书面范围、时间窗口和停止条件的授权环境。

公共站点只做 1 个虚拟用户的功能性烟雾验证，不做持续并发。

## 10. 练习结束检查

```text
[ ] 抓包已停止
[ ] 系统代理已关闭或恢复原值
[ ] 测试设备 Wi-Fi 代理已恢复
[ ] 临时 CA 已从电脑和设备删除
[ ] USB / 无线调试已关闭或撤销授权
[ ] 会话、HAR、PCAP、日志和截图已检查
[ ] 无公司域名、账号、Cookie、Token、证书或内部数据
[ ] 临时容器和测试账号按需清理
```
