# Windows 性能测试与测试报告

## 1. 安全前提

所有负载实验只对：

- `127.0.0.1` 本机服务；
- 本机 Docker / Mockoon；
- 你自己部署的公开练习服务；
- 有明确授权、范围、时间窗口和停止条件的环境。

公共演示站不用于并发压测。下面默认目标是：

```text
http://127.0.0.1:3001/health
```

先按[数据库与容器工具](03-数据库与容器工具.md)启动 Mockoon。

## 2. JMeter

### 安装

[JMeter 官方下载页](https://jmeter.apache.org/download_jmeter.cgi)提供 Binary ZIP，没有 Windows 安装器：

1. 确认 JDK：

```powershell
java -version
javac -version
$env:JAVA_HOME
```

2. 下载 Binary ZIP；
3. 核对 SHA-512 或 PGP；
4. 在当前用户目录建立工具目录，将解压后的版本目录重命名为
   `apache-jmeter`：

```powershell
$ToolsRoot = Join-Path $HOME "tools"
$JMeterHome = Join-Path $ToolsRoot "apache-jmeter"
New-Item -ItemType Directory -Force -Path $ToolsRoot
```

解压完成后，确认 `$JMeterHome` 指向实际目录。若不想重命名，就把变量改为实际
版本目录，例如 `apache-jmeter-5.x.x`。

5. 启动 GUI：

```powershell
$JMeterHome = Join-Path $HOME "tools\apache-jmeter"
& (Join-Path $JMeterHome "bin\jmeter.bat")
```

6. 验证：

```powershell
$JMeterHome = Join-Path $HOME "tools\apache-jmeter"
& (Join-Path $JMeterHome "bin\jmeter.bat") -v
```

### GUI 只用于编写和调试

建立：

```text
Test Plan
└─ Thread Group
   ├─ HTTP Request Defaults: 127.0.0.1:3001
   ├─ HTTP Request: GET /health
   ├─ Response Assertion: 200 / 包含 ok
   └─ Summary Report（仅调试）
```

先用 1 用户、1 次循环确认。

把计划保存到当前用户 `workspace\performance-smoke\health-smoke.jmx`，真正运行
使用非 GUI：

```powershell
$JMeterHome = Join-Path $HOME "tools\apache-jmeter"
$PerformanceRoot = Join-Path $HOME "workspace\performance-smoke"
$TestPlan = Join-Path $PerformanceRoot "health-smoke.jmx"
$ResultFile = Join-Path $PerformanceRoot "result.jtl"
$ReportDirectory = Join-Path $PerformanceRoot "report"
New-Item -ItemType Directory -Force -Path $ReportDirectory

& (Join-Path $JMeterHome "bin\jmeter.bat") `
  -n `
  -t $TestPlan `
  -l $ResultFile `
  -e `
  -o $ReportDirectory
```

负载阶段删除 View Results Tree 等高开销监听器。先阅读 [JMeter Best Practices](https://jmeter.apache.org/usermanual/best-practices.html)。

### 常见问题

- `JAVA_HOME` 指向 `bin`；
- 解压路径有空格/过长；
- 用 GUI 承载压力；
- JTL 和报告目录混有旧结果；
- 只看平均值，不看 p90/p95/p99、错误率和吞吐；
- 录制 HTTPS 时缺 JDK `keytool`；
- 把协议级 JMeter 当成真实浏览器渲染。

## 3. k6

### 安装

按 [k6 官方安装页](https://grafana.com/docs/k6/latest/set-up/install-k6/)：

```powershell
winget install k6 --source winget
k6 version
where.exe k6
```

也可使用官方 MSI 或独立二进制。Chocolatey 包不是 Grafana 官方维护渠道，教程不作为首选。

### 十分钟实践

新建 `health-smoke.js`：

```javascript
import http from "k6/http";
import { check } from "k6";

export const options = {
  vus: 1,
  duration: "5s",
  thresholds: {
    http_req_failed: ["rate==0"],
    http_req_duration: ["p(95)<500"],
  },
};

export default function () {
  const response = http.get("http://127.0.0.1:3001/health");
  check(response, {
    "status is 200": (r) => r.status === 200,
    "body contains ok": (r) => r.body.includes("ok"),
  });
}
```

执行：

```powershell
k6 run .\health-smoke.js
```

先保持 1 VU。只有本机服务具备资源监控且已定义目标后，才逐步增加：

```powershell
k6 run --vus 5 --duration 15s .\health-smoke.js
```

k6 使用自己的 JavaScript runtime，不是 Node.js。不要假设任意 npm 包都能直接运行。

## 4. 如何选择 JMeter 和 k6

| 维度 | JMeter | k6 |
|---|---|---|
| 脚本方式 | GUI/JMX + 插件 | JavaScript 代码 |
| 运行时 | JDK | 独立 k6 runtime |
| 资源消耗 | GUI/监听器容易变重 | CLI 较轻 |
| 适合 | 传统企业协议、存量计划、录制 | 代码化、CI、阈值 |
| 主线建议 | 会读写并能 CLI 运行 | 新项目性能代码主线 |

二者都不能代替负载模型、服务端指标和瓶颈分析。

## 5. Allure Report 3

Allure 把框架结果转为 HTML 报告。新项目推荐 [Allure Report 3](https://allurereport.org/docs/v3/)；它通过 Node.js 安装，不依赖 Allure 2 的 Java CLI。

### 项目本地安装

```powershell
Set-Location (Join-Path $HOME "workspace\python-smoke")
npm init -y
npm install --save-dev allure
npx allure --version

.\.venv\Scripts\Activate.ps1
python -m pip install allure-pytest
python -m pytest --alluredir allure-results --clean-alluredir
npx allure generate allure-results
npx allure open
```

项目本地安装比全局安装更易固定版本。报告目录加入 `.gitignore`：

```gitignore
allure-results/
allure-report/
```

### Allure 2 存量项目

Allure 2 仍成熟且集成广，但 CLI 需要 Java。按照[官方 Windows 安装说明](https://allurereport.org/docs/v2/install-for-windows/)使用 Scoop 或官方归档。

不要让 Allure 2 和 3 的全局 `allure` 命令互相覆盖。先执行：

```powershell
where.exe allure
allure --version
```

再决定迁移。

### 报告隐私

Allure 可能自动收集：

- stdout / stderr / log；
- HTTP 请求与响应；
- 截图、视频、Trace；
- 环境信息；
- 参数、文件路径和设备标识。

附件发布前必须脱敏。即使 HTML 报告是静态文件，也不能上传公司数据。
