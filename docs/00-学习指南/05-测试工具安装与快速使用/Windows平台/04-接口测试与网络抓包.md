# Windows 接口测试与网络抓包

## 1. 先理解工具层次

```text
API 客户端：构造并发送请求
  Apifox / Postman / curl

HTTP(S) 调试代理：观察、重放、改写经过代理的流量
  Reqable / Fiddler / Charles

网络数据包分析：观察更底层的 DNS、TCP、TLS 等协议
  Wireshark
```

它们不是同一种工具。接口返回 401 时先看请求和鉴权；连接建立不了时再看 DNS/TCP/TLS；不要一上来安装根证书抓全机流量。

## 2. Apifox

### 安装

从 [Apifox 官方下载文档](https://docs.apifox.com/download)选择 Windows 10/11 64 位稳定版。桌面版比 Web 版完整，支持本地请求、数据库和部分本地能力。

安装后新建独立练习项目。涉及受限接口、数据库或凭据时，应使用组织批准的存储和隔离方案。

### 十分钟实践

1. 新建“公开接口练习”项目；
2. 新建环境变量：
   - 名称：`baseUrl`
   - 本地值：`https://postman-echo.com`
3. 新建 `GET {{baseUrl}}/get?course=software-testing`；
4. 发送请求；
5. 检查：
   - HTTP 状态为 200；
   - JSON 中 `args.course` 等于 `software-testing`；
6. 添加状态码和 JSONPath 断言；
7. 保存为接口用例；
8. 建立测试场景并运行一次；
9. 把 `baseUrl` 改成错误端口，观察连接错误，再恢复。

后续按[Apifox 快速上手](https://docs.apifox.com/getting-started)练习：接口定义 → 请求 → 断言 → Mock → 场景 → 报告。

### 常见问题

- 环境没有切换，变量实际取了另一个值；
- 本地值和远程值混淆，凭据被同步；
- 忽略响应 Schema，只断言状态码；
- 关闭 SSL 校验后忘记恢复；
- 将测试数据、运行日志或数据库连接上传个人空间。

## 3. Postman

Postman 是国际 API 生态的常见对照工具。按 [Postman 官方安装指南](https://learning.postman.com/docs/getting-started/installation/install-app/)下载 Windows Intel 64-bit 或 ARM64 原生包。

桌面 App 功能最完整；Web App 需要 Desktop Agent，代理、Interceptor、导出和部分性能能力受限。

十分钟实践：

1. 新建 Collection；
2. 新建 `GET https://postman-echo.com/get?course=software-testing`；
3. 在 Post-response / Tests 中添加：

```javascript
pm.test("状态码为 200", function () {
  pm.response.to.have.status(200);
});

pm.test("参数被原样返回", function () {
  const body = pm.response.json();
  pm.expect(body.args.course).to.eql("software-testing");
});
```

4. 保存并用 Collection Runner 执行；
5. 把期望值改错，确认测试确实失败。

敏感值使用本地变量或 Vault，并先理解工作区是否云同步。学习项目只用合成 Token。

## 4. curl 与 PowerShell

Windows PowerShell 中明确使用 `curl.exe`，避免与 `Invoke-WebRequest` 的历史别名混淆：

```powershell
curl.exe -i "https://postman-echo.com/get?course=software-testing"

$response = Invoke-RestMethod `
  -Uri "https://postman-echo.com/get?course=software-testing" `
  -Method Get

$response.args.course
```

失败时加详细日志，但分享前检查 Header：

```powershell
curl.exe -v "http://127.0.0.1:3001/health"
```

## 5. 三种 HTTP(S) 抓包工具怎么选

| 工具 | Windows 结论 | 账号/授权 | 推荐场景 |
|---|---|---|---|
| Reqable | 现代跨平台，API + 抓包结合 | Community/付费功能以官网为准；不是开源项目 | 初学移动/接口联调 |
| Fiddler Everywhere | Windows 10 22H2+/Windows 11 x64 | 需要账号；试用/订阅 | 规则、重放、跨平台团队 |
| Fiddler Classic | 仅 Windows，维护状态和协议能力弱于 Everywhere | 免费使用条件以官方条款为准 | 只为存量团队兼容 |
| Charles | Windows/macOS 常见 | 30 天试用，商业许可证 | Map Local/Remote、跨平台联调 |

一次只运行一个会修改系统代理的工具。

## 6. Reqable

从 [Reqable 官方 Windows 下载页](https://reqable.com/en-US/windows/)选择 x86_64 安装器。其[官方仓库](https://github.com/reqable/reqable-app)明确说明产品不是开源软件，仓库用于需求与反馈。

最小实践：

1. 关闭其他代理/VPN；
2. 启动 Reqable；
3. 暂不解密 HTTPS，先捕获本机 `http://127.0.0.1:3001/health`；
4. 在流量详情核对方法、URL、状态码和耗时；
5. 保存为 API 请求并重放；
6. 需要练 HTTPS 时，仅给个人测试用户安装 Reqable CA；
7. 只捕获 `https://example.com` 或自有服务；
8. 完成后关闭系统代理并删除 CA。

如果绿色盾牌/证书状态异常，按[官方安装与证书文档](https://reqable.com/en-US/docs/getting-started/installation/)处理，不关闭系统安全功能。

## 7. Fiddler Everywhere 与 Classic

### Fiddler Everywhere

[Windows 官方快速开始](https://www.telerik.com/fiddler/fiddler-everywhere/documentation/installation-and-setup/quickstart-windows)当前要求 Windows 10 x64 22H2+ 或 Windows 11 x64、约 400 MB 空间。默认代理端口为 `8866`；HTTPS 解密需要管理员权限安装并信任本地 CA。

最小实践：

1. 登录个人学习账号；
2. 开启 Live Traffic；
3. 捕获 `https://example.com`；
4. 查看请求和响应；
5. 用 Composer 重放一个 GET；
6. 用 Rules 对本机 Mock 返回一个合成错误；
7. 停止捕获、退出并确认系统代理恢复；
8. 不再使用时删除 Fiddler CA。

Fiddler Everywhere 是商业订阅产品。离线模式、SSO 等功能可能属于特定套餐。

### Fiddler Classic

Classic 仅适用于 Windows 存量学习。[官方对比](https://www.telerik.com/fiddler/classic-vs-everywhere)显示 Everywhere 在跨平台、HTTP/2、TLS 1.3、gRPC、SSE 等方面更现代。新学习路线不把 Classic 作为主线。

## 8. Charles

按 [Charles 官方安装说明](https://www.charlesproxy.com/documentation/installation/)运行 Windows 安装器。官方页面当前提供试用和商业许可，但未明确列出所有稳定版最低 Windows/架构要求；以下载器提示和官方支持为准，不自行猜测。

最小实践：

1. 启动 Charles，确认默认端口；
2. 打开浏览器访问 `https://example.com`；
3. 只对目标域名启用 SSL Proxying；
4. 安装并信任 Charles Root Certificate；
5. 查看请求并 Repeat；
6. 练习 Map Local 时只替换本机/公开测试响应；
7. 退出后检查 Windows 系统代理；
8. 完成后按 [SSL Certificates](https://www.charlesproxy.com/documentation/using-charles/ssl-certificates/)删除 CA。

有些 `localhost` 流量绕过代理，可按[官方 FAQ](https://www.charlesproxy.com/documentation/faqs/)使用 `localhost.charlesproxy.com` 对照验证。

## 9. Wireshark

Wireshark 用于网络层诊断，不负责构造 API 请求。

### 安装

1. 从 [Wireshark 官方下载页](https://www.wireshark.org/download.html)下载 Windows 安装器；
2. 保留稳定渠道；
3. 安装 Npcap，以便捕获网络接口；
4. 不启用不理解的兼容/原始无线抓包选项；
5. 启动 Wireshark。

### 十分钟实践

1. 选择当前活动网络接口；
2. 开始捕获；
3. 执行：

```powershell
Resolve-DnsName example.com
curl.exe -I https://example.com
```

4. 停止捕获；
5. 依次使用显示过滤器：

```text
dns
tcp.port == 443
tls
ip.addr == 目标IP
```

HTTPS 正文仍是加密的，这是正常现象。Wireshark 能帮助判断 DNS、握手、重传、RST 和 TLS 元数据，不应为了看正文导入生产密钥。

PCAP/PCAPNG 可能记录大量无关网络元数据，默认不保存；确需保存时只捕获最小时间窗口和测试接口。

## 10. 抓包故障矩阵

| 现象 | 首要检查 |
|---|---|
| 完全没流量 | 是否选对接口/捕获模式；应用是否走系统代理 |
| HTTPS 只有 CONNECT/TLS | CA 未安装/未信任，或未对域名开启解密 |
| App 安装 CA 后仍失败 | 证书钉扎、Android 用户 CA、mTLS、QUIC |
| 启动第二个工具后都异常 | 多个系统代理竞争端口 |
| 退出工具后断网 | Windows 系统代理残留 |
| localhost 不出现 | 应用绕过代理，使用本机 IP 或工具官方 workaround |
| 浏览器可抓，App 不可抓 | App 自定义代理/证书库或不走 HTTP 代理 |

## 11. 本章验收

```text
[ ] Apifox 或 Postman 能执行公开 GET 和断言
[ ] 能解释 API 客户端、调试代理、Wireshark 的差异
[ ] 只选择一个 HTTP(S) 抓包主工具
[ ] 能重放一个公开/本机请求
[ ] 能确认系统代理端口和恢复状态
[ ] 能安装并安全删除个人测试 CA
[ ] 没有保存或同步任何公司会话、凭据或接口资料
```
