# Windows 安装前准备与包管理

## 1. 更新系统

先完成 Windows Update 并重启。驱动、WSL、虚拟化、根证书和安装器问题经常来自过旧系统。

PowerShell 查询版本：

```powershell
Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion, OsBuildNumber, OsArchitecture
```

教程主线使用 Windows 11 x64。受公司策略管理的电脑应先遵循 IT 软件白名单，不尝试绕过管理员、终端防护或证书策略。

## 2. 认识三种终端

| 终端 | 适合 | 注意 |
|---|---|---|
| PowerShell 7 / Windows PowerShell | 本教程 Windows 命令 | PowerShell 与 CMD 的环境变量语法不同 |
| CMD | 旧安装脚本和 `.bat` | 不支持 PowerShell 的 `$Env:` 语法 |
| WSL | Linux 工具链、Docker Linux 容器 | WSL 内外是两套 PATH、Python、Node 和文件权限 |

除非章节明确写 WSL，否则 Windows 教程命令在 PowerShell 中运行。

查看当前命令来源：

```powershell
Get-Command python -All
Get-Command node -All
Get-Command java -All
where.exe python
where.exe node
where.exe java
```

在 PowerShell 中 `where` 是 `Where-Object` 的别名，查可执行文件必须写 `where.exe`。

## 3. WinGet

[WinGet](https://learn.microsoft.com/windows/package-manager/winget/) 随现代 Windows 的 App Installer 提供，可用于发现、安装和升级常见工具。

```powershell
winget --version
winget source list
winget search Git.Git
winget install --id Git.Git -e --source winget
winget upgrade
```

规则：

- 安装前用 `winget show --id <ID> -e` 核对发布者、版本和来源；
- 不从搜索结果中凭相似名称随便安装；
- 安装器包含驱动、证书或系统服务时，仍阅读其图形界面选项；
- 受控设备可能禁用 WinGet，应使用组织批准的软件中心。

## 4. PATH 和环境变量

`PATH` 是按顺序搜索可执行文件的目录列表。常见故障不是“没安装”，而是旧版本排在前面。

查看用户和进程 PATH：

```powershell
[Environment]::GetEnvironmentVariable("Path", "User")
$env:Path -split ";"
```

修改原则：

1. 优先让官方安装器修改；
2. 只加入包含可执行文件的目录，不加入具体 `.exe`；
3. 修改后关闭并重新打开终端；
4. 用 `where.exe` 验证；
5. 不把整个 Git `usr\bin`、多个 JDK `bin`、多个 Python 目录全部堆入 PATH。

不要全局设置 `PYTHONHOME`、`PYTHONPATH` 或不明来源的证书变量。它们会让所有项目产生隐蔽冲突。

## 5. 文件扩展名和隐藏文件

在资源管理器开启：

- 查看 → 显示 → 文件扩展名；
- 查看 → 显示 → 隐藏的项目。

这样才能区分：

```text
.env
.env.example
requirements.txt
requirements.txt.exe
```

不要双击运行来源不明的 `.exe`、`.msi`、`.ps1`、`.bat`。

## 6. 校验下载文件

官方提供 SHA-256 / SHA-512 时先校验：

```powershell
Get-FileHash .\下载文件.exe -Algorithm SHA256
Get-FileHash .\apache-jmeter.zip -Algorithm SHA512
```

把输出与官网逐字符比较。数字签名可在文件“属性 → 数字签名”中核对发布者。

## 7. 长路径

Git 和 Node 项目可能产生深层目录。教程默认使用 `$HOME\workspace`；有专用数据盘
时也可使用 `D:\workspace` 或 `C:\workspace`。确需启用 Windows 长路径时，先确认
系统版本、组织策略和使用的软件都支持，不把它当作所有路径问题的通用修复。

## 8. WSL 2 与虚拟化

Docker Desktop Windows 主线使用 WSL 2。管理员 PowerShell：

```powershell
wsl --version
wsl --status
```

缺失时按照 [Microsoft WSL 官方安装文档](https://learn.microsoft.com/windows/wsl/install)执行：

```powershell
wsl --install
wsl --update
```

命令可能要求重启。Docker Desktop 当前官方要求 WSL 2.1.5 或更高，并需要 BIOS/UEFI 虚拟化和足够内存；以[官方系统要求](https://docs.docker.com/desktop/setup/install/windows-install/)为准。

## 9. 防火墙、代理和杀毒

不要为了安装工具长期关闭防火墙、杀毒或 TLS 校验。下载失败时记录：

- 使用的 URL；
- HTTP 状态或完整错误；
- 系统代理；
- DNS 是否能解析；
- 是否使用 VPN；
- 公司设备是否需要官方代理和 CA。

个人知识库禁止保存公司的代理地址、内网域名或根证书。

## 最小验收

```powershell
$PSVersionTable.PSVersion
winget --version
wsl --version
Get-ComputerInfo | Select-Object WindowsProductName, OsBuildNumber, OsArchitecture
```

WSL 暂未安装不影响 Python/接口/Web 起步；等 Docker 或 Linux 章节再完成即可。
