# 学习路线与阶段验收

这条路线以“能交付可复现的质量证据”为目标，不以看完视频或背完面试题为完成标准。建议每周固定 8～10 小时：40% 学概念，50% 做实验，10% 复盘。

## 先做能力盘点

给每项标记 0～3 分：

- 0：不了解；
- 1：看得懂，但不能独立操作；
- 2：能独立完成常规任务；
- 3：能设计方案、解释权衡并排查复杂问题。

| 能力 | 自评分 | 可验证证据 |
|---|---:|---|
| 从需求识别风险并设计测试 |  | 风险清单、测试模型、评审记录 |
| HTTP、浏览器、网络与鉴权 |  | 能用 curl 重现并解释请求 |
| SQL 与测试数据构造 |  | 查询、约束、事务和清理脚本 |
| Python 与 pytest |  | fixture、参数化、标记、报告、失败诊断 |
| Web UI 自动化 |  | 稳定定位、等待、隔离、trace |
| 移动端测试 |  | 真机/模拟器、权限、网络、兼容性方案 |
| 性能工程 |  | 负载模型、阈值、监控证据、容量结论 |
| CI/CD 与容器基础 |  | 分层流水线、缓存、制品和门禁 |
| AI 系统评测 |  | 版本化数据集、评分器、安全用例、回归报告 |
| 沟通与复盘 |  | 简洁缺陷报告、测试总结、决策依据 |

已有 2 分的模块可以直接挑战阶段验收；通过后跳过基础练习。

## 阶段 0：环境与基础（第 1～2 周）

先按自己的系统完成
[Windows / macOS 测试工具安装与快速使用知识库](./05-测试工具安装与快速使用/README.md)
中的基础环境与自检；其余工具在进入对应阶段时按需安装，不必第一天全部装完。

### 学习内容

- Git：工作区、暂存区、提交、分支、合并、恢复与差异审查；
- Linux / macOS 终端：路径、进程、端口、权限、管道、退出码、日志；
- 网络：DNS、TCP、TLS、HTTP、代理、Cookie、跨域；
- SQL：查询、连接、聚合、索引概念、事务和约束；
- Python：数据结构、函数、异常、文件、模块、虚拟环境、类型提示。

### 阶段验收

- 能找出占用 8000 端口的进程，并解释安全的处理方式；
- 能用 curl 发送 GET / POST、请求头、JSON 请求体并读取状态码；
- 能从一张订单表写出分组统计和重复数据检查 SQL；
- 能写一个 Python 脚本读取 JSONL、校验字段并以非零退出码报告失败；
- 提交前会检查 `git status`、`git diff`，不会提交 `.env`。

## 阶段 1：功能测试（第 3～5 周）

### 学习内容

- 需求澄清：对象、角色、规则、状态、依赖、数据、异常和非功能目标；
- 风险分析：影响、发生概率、可发现性、变更范围和历史缺陷；
- 设计方法：等价类、边界值、判定表、状态迁移、场景法、组合测试；
- 探索式测试：charter、时间盒、观察、调整和证据；
- Web / App 专项：兼容性、可访问性、弱网、权限、中断、升级、时区和国际化。

### 阶段项目

选择 `demo-shop` 的“下单”能力，交付：

1. 一页测试对象与不在范围说明；
2. 至少 10 条按优先级排序的风险；
3. 一张订单状态迁移图和一张价格规则判定表；
4. 三个 45 分钟探索式测试 charter；
5. 一份包含复现、期望、实际、环境和证据的缺陷报告；
6. 测试总结：覆盖、未覆盖、残余风险和上线建议。

## 阶段 2：接口测试（第 6～8 周）

### 学习内容

- HTTP 语义、状态码、缓存、重试、超时、分页和内容协商；
- 常见鉴权：Session、Bearer Token、OAuth 2.0 概念、签名；
- OpenAPI / JSON Schema、向后兼容和契约；
- 正常、边界、异常、权限、幂等、顺序、并发和数据一致性测试；
- Postman / curl 用于探索，代码用于可维护回归。

### 阶段验收

- 不依赖 UI，完成“查商品 → 下订单 → 查询结果”的接口调用；
- 对每个接口至少覆盖协议、业务规则、权限和数据四个层次；
- 证明重复提交同一个幂等键不会创建两个订单；
- 区分 400、401、403、404、409、422、429 和 5xx 的测试含义；
- 从 OpenAPI 发现一次实现与契约不一致，或写出可自动检查的契约断言。

## 阶段 3：接口自动化（第 9～11 周）

### 学习内容

- pytest 收集、断言、fixture、参数化、标记和插件边界；
- 配置、客户端、业务动作、数据工厂、断言和测试用例分层；
- 测试隔离、可重复运行、并行执行与失败取证；
- 日志脱敏、重试限制、随机性控制和 flaky test 治理；
- CI 中的快速回归、报告、制品与退出码。

### 阶段验收

- 任意机器按 README 能在 15 分钟内运行项目；
- 单个失败能从报告定位请求、响应和业务步骤，但不会泄露令牌；
- 测试可乱序运行，重复三次结果一致；
- 把 smoke 与 regression 分层，合并请求只运行必要集合；
- 至少一个测试使用数据驱动，而不是复制粘贴多个函数。

## 阶段 4：UI 自动化（第 12～14 周）

### 主线原则

只把跨层、用户可见、业务价值高的关键旅程放到 UI 层。字段规则、错误组合和大量数据优先在 API / 单元层验证。

### 阶段验收

- 用 Playwright 覆盖一条购买主路径和一条失败路径；
- 优先使用 role、label、test id 等面向用户或稳定契约的定位器；
- 禁止固定 `sleep`；能解释自动等待和断言等待；
- 每个用例拥有独立数据或可靠清理；
- CI 失败时保存 trace / screenshot / video 中最有诊断价值的制品；
- 说明哪些场景不应该做 UI 自动化，以及原因。

移动端方向可在本阶段加入 Appium：覆盖权限、后台/前台、旋转、网络切换和系统弹窗等 Web 不具备的风险。

## 阶段 5：性能测试（第 15～16 周）

### 学习内容

- 业务指标与 SLI / SLO；吞吐、并发、响应时间分位数、错误率和资源饱和度；
- 基线、负载、压力、峰值、耐久和容量测试；
- 到达率与虚拟用户模型；数据唯一性、连接复用和思考时间；
- 服务端、数据库、缓存、队列与依赖监控；
- 协调遗漏、客户端瓶颈、预热、噪声和结果可重复性。

### 阶段验收

- 从业务量推导场景比例和目标到达率，不拍脑袋给并发数；
- 在脚本中声明 p95、错误率等阈值，失败能返回非零退出码；
- 报告同时包含负载、用户体验指标、资源指标和时间线；
- 明确环境限制，测试环境结果不伪装成生产容量结论；
- 给出可证伪的瓶颈假设和下一轮实验，而非只说“接口慢”。

## 阶段 6：质量工程（第 17～18 周）

建立分层反馈：

```text
本地秒级检查 → 提交级单元/API smoke → 合并级回归/契约
→ 定时 UI/性能/安全检查 → 发布后合成监控与真实指标
```

验收标准：流水线失败能阻止合并；失败有负责人和证据；不稳定用例不会被无限重跑掩盖；测试数据和环境有所有者、版本与清理策略。

## 阶段 7：AI 测试与综合项目（第 19～20 周）

### 学习内容

- 非确定性系统的风险、评测数据集与版本控制；
- 确定性规则、代码评分器、模型裁判、人工评价的组合；
- RAG 的检索与生成分层评测；
- Agent 的轨迹、工具选择、权限、停止条件和副作用测试；
- 提示注入、越权、敏感信息泄露、过度依赖与安全拒答；
- AI 辅助测试的输入边界、验证闭环和成本治理。

### 阶段验收

- 创建至少 30 条合成评测样本，包含正常、边界、对抗和拒答场景；
- 每条样本有预期行为与评分依据，不只存一个“标准答案”；
- 至少使用一种确定性评分和一种人工或模型评分，并抽样校准；
- 分别报告任务质量、安全、延迟和成本；
- 对一次模型/提示词/知识库变更运行回归并解释差异；
- 在作品说明中清楚写出限制、未知风险和人工兜底。

### 综合项目选择

完成 `demo-shop` 入门闭环后，从[复杂系统测试实战](../../labs/复杂系统测试实战/README.md)选择一条主线，另一条作为对照阅读：

- Python 方向：FastAPI + React 社区问答系统，重点练习内容状态、投票并发、搜索、缓存和 AI 摘要/审核；
- Java 方向：Spring Boot + Vue 企业智能客服系统，重点练习多租户、RBAC、工单状态机、SLA、事务和 AI 回复建议；
- 两条路线共用 Python AI 中间件，统一练习契约、超时、降级、黄金集、安全与人工复核。

先证明核心业务在 AI 服务不可用时仍然成立，再测试模型质量。不要把“接口返回了一段文本”当成 AI 能力验收。

## 作品集的证据结构

每个项目保留以下内容，面试时先讲决策，再展示代码：

```text
目标和范围
├── 系统与用户背景（全部为公开或虚构）
├── 风险与优先级
├── 测试策略和为什么这样分层
├── 可运行代码与数据
├── CI / 报告 / 诊断证据
├── 发现、权衡与残余风险
└── 下一步改进
```

不要用用例数量、脚本行数或截图页数证明能力。更有价值的是：你识别了什么风险、为何选择这种方法、证据是否可信、结论如何影响决策。
