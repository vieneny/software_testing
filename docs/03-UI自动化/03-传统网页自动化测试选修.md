# Selenium 4 选修：兼容既有生态

> 新建本仓库 Web UI 主线使用 Playwright。Selenium 4 仍是重要市场技能，适合既有 Selenium 资产、标准 WebDriver 生态、Grid 或特定浏览器基础设施。示例只操作本地虚构 Demo Shop。

## 学习目标

完成本章后，你应当能够：

1. 判断项目应使用 Playwright 还是 Selenium 4。
2. 使用 Selenium Manager、pytest fixture 和显式等待运行可靠冒烟。
3. 选择稳定定位器，避免隐式等待与固定睡眠。
4. 理解 Grid 与 WebDriver BiDi 的适用范围。

## 1. 选型而不是站队

| 维度 | Playwright | Selenium 4 |
|---|---|---|
| 新项目开箱体验 | 自动等待、Trace、网络控制集成度高 | 组合灵活，需要自行约定框架 |
| 浏览器协议 | Playwright 自身驱动 | W3C WebDriver，正在扩展 BiDi |
| 既有资产 | 迁移需评估 | 大量企业存量和语言生态 |
| 分布式执行 | 常见 CI/容器方案 | Selenium Grid 成熟 |
| 本仓库定位 | Web 主线 | 市场兼容选修 |

如果团队已有大量稳定 Page Object、Grid 和运维能力，继续演进 Selenium 往往比重写更有价值。新项目则应先用真实试点比较维护成本、调试证据和目标浏览器支持。

## 3. pytest fixture 与显式等待

```python
from __future__ import annotations

import os

import pytest
from selenium import webdriver
from selenium.webdriver.chrome.options import Options
from selenium.webdriver.common.by import By
from selenium.webdriver.support import expected_conditions as EC
from selenium.webdriver.support.ui import WebDriverWait


@pytest.fixture
def driver():
    options = Options()
    options.add_argument("--headless=new")
    options.add_argument("--window-size=1280,900")

    browser = webdriver.Chrome(options=options)
    browser.set_page_load_timeout(10)
    yield browser
    browser.quit()


def test_user_can_buy_a_product(driver) -> None:
    base_url = os.getenv(
        "DEMO_BASE_URL",
        "http://127.0.0.1:8000",
    )
    wait = WebDriverWait(driver, 5)

    driver.get(base_url)

    status = wait.until(
        EC.visibility_of_element_located((By.ID, "status"))
    )
    wait.until(lambda current: "已加载" in status.text)

    buy_button = wait.until(
        EC.element_to_be_clickable(
            (
                By.XPATH,
                "//button[normalize-space()='购买 星光马克杯']",
            )
        )
    )
    buy_button.click()

    wait.until(lambda current: "订单创建成功" in status.text)
    assert "金额 ¥39.00" in status.text
```

关键点：

- fixture 用 `yield` 保证 `quit()`。
- 设置页面加载超时，显式等待业务条件。
- `status` 有稳定 `id`；按钮没有 id 时用明确可见文案的短 XPath。
- 不使用 `time.sleep()`。
- 不同时设置很长的隐式等待和显式等待，否则超时行为难以预测。

更大项目可让开发提供稳定的可访问名称或 `data-testid`，避免脆弱 DOM 路径。

## 4. 封装原则

Page Object 应封装页面行为：

```python
class ShopPage:
    def __init__(self, driver, base_url: str) -> None:
        self.driver = driver
        self.base_url = base_url
        self.wait = WebDriverWait(driver, 5)

    def open(self) -> None:
        self.driver.get(self.base_url)
        self.wait.until(
            lambda current: "已加载"
            in current.find_element(By.ID, "status").text
        )

    def buy(self, product_name: str) -> None:
        button = self.wait.until(
            EC.element_to_be_clickable(
                (
                    By.XPATH,
                    f"//button[normalize-space()='购买 {product_name}']",
                )
            )
        )
        button.click()
```

不要再包一层 `click(xpath)`、`wait(3)` 的“通用框架”。它会隐藏 Selenium 的原始异常、截图和元素上下文。

## 5. Grid 与 WebDriver BiDi

### Selenium Grid

当确有以下需求时评估 Grid：

- 多浏览器/多版本并行。
- 集中管理浏览器节点。
- 复用现有容器或设备基础设施。

先解决测试独立、数据隔离和可观测性，再扩大并发。Grid 不会自动修复 flaky 测试。

### WebDriver BiDi

WebDriver BiDi 为浏览器与客户端提供双向事件能力，逐步覆盖日志、网络、脚本等现代自动化场景。支持范围会随 Selenium 和浏览器版本演进；使用前查阅当前官方文档并做目标浏览器验证，不要把实验 API 当成全平台稳定契约。

## 6. 失败证据

fixture 可在用例失败时保存本地虚构页面截图。真实项目要对截图、HTML 源码、Console/网络日志设访问权限和保留期。

手工调试：

```python
driver.save_screenshot("test-results/demo-shop-failure.png")
```

不要提交公司页面截图、浏览器 Profile、Cookie、下载文件或未经脱敏的日志。

## 7. 常见错误

1. 仍使用 Selenium 3/旧 Desired Capabilities 教程。
2. 手工固定 Driver 二进制并与浏览器版本漂移。
3. 绝对 XPath、`nth-child` 或随机 class 定位。
4. 混用长隐式等待、显式等待和固定睡眠。
5. 所有 UI 测试共享浏览器和登录状态。
6. 上 Grid 前未解决数据冲突和用例顺序依赖。
7. 仅因工具流行就重写成熟套件，未测算收益。

### 验收标准

- [ ] 使用 Selenium 4 与 Selenium Manager，不提交 Driver 二进制。

- [ ] 无固定睡眠、绝对 XPath 或执行顺序依赖。
- [ ] 等待的是业务可观察条件，而非仅“元素存在”。
- [ ] 能基于现状说明 Playwright/Selenium 选型，而非简单比较语法。
- [ ] 所有证据只包含本地虚构 Demo Shop。
