# Appium 3 移动端自动化

> Appium 是移动端选修主线，适用于原生 App、混合 App 和真实移动浏览器链路。Demo Shop 是 Web 实验；验证其响应式页面优先使用 Playwright。只有目标确实涉及 App/设备集成时才引入 Appium。

## 学习目标

完成本章后，你应当能够：

1. 解释 Appium 3 的服务端、客户端、驱动和设备四层架构。
2. 安装 Appium 3 与 UiAutomator2 驱动，并完成环境自检。
3. 使用 Python 客户端和 W3C `appium:` capability 运行 Android 冒烟测试。
4. 使用稳定定位器和显式等待，正确回收 Driver。
5. 识别 Appium 1 旧教程、坐标点击和不安全服务器参数。

## 1. 什么时候使用 Appium

| 目标 | 首选 |
|---|---|
| 桌面浏览器 Web | Playwright |
| 移动视口下的响应式 Web | Playwright 设备模拟 |
| Android/iOS 原生 App | Appium |
| Hybrid App 的 Native ↔ WebView | Appium |
| 真实设备上的系统权限、通知、深链等集成 | Appium + 设备实验室 |

浏览器设备模拟不能证明真实设备上的键盘、系统权限、WebView、性能和厂商差异；Appium 也不应替代快速的 Web 浏览器测试。

## 2. Appium 3 架构

```text
pytest 测试
  ↓ Appium Python Client
Appium Server 3（协议与扩展管理）
  ↓ 已安装的 Driver
UiAutomator2 / XCUITest / 其他平台驱动
  ↓
模拟器或真实设备
```

Appium Server 核心不再捆绑平台驱动。必须按目标平台安装驱动；插件也独立管理。Appium 3 对 Node.js 版本有当前要求，安装前以官方 System Requirements 为准，不要照抄多年前的 Node/Appium 1 教程。

## 3. Android 学习环境

准备：

- 官方文档支持的 Node.js/npm。
- JDK 与 Android Studio/SDK。
- 一个 Android 模拟器，或只含虚构测试数据的专用设备。
- Python 3.11+ 虚拟环境。
- 官方公开示例 App，例如 Appium `android-apidemos`。

安装 Appium 与 UiAutomator2：

```bash
npm install --global appium
appium --version
appium driver install uiautomator2
appium driver list --installed
appium driver doctor uiautomator2
```

确认设备：

```bash
adb devices
```

启动只监听本机的服务器：

```bash
appium --address 127.0.0.1 --port 4723
```

不要为省事使用 `--relaxed-security`，不要把 Appium 端口暴露到公网。专用设备上不要保留个人账号、公司应用或真实通知。

## 4. Python 冒烟测试

建立独立学习虚拟环境：

```bash
python3 -m venv .venv-appium
source .venv-appium/bin/activate
python -m pip install --upgrade pip
python -m pip install pytest Appium-Python-Client
```

把公开 ApiDemos APK 的绝对路径放入环境变量，不要提交二进制来源不明的安装包：

```bash
export APIDEMOS_APK='/absolute/path/to/ApiDemos-debug.apk'
```

示例：

```python
from __future__ import annotations

import os

import pytest
from appium import webdriver
from appium.options.android import UiAutomator2Options
from appium.webdriver.common.appiumby import AppiumBy
from selenium.webdriver.support.ui import WebDriverWait


@pytest.fixture
def driver():
    options = UiAutomator2Options().load_capabilities(
        {
            "platformName": "Android",
            "appium:automationName": "UiAutomator2",
            "appium:app": os.environ["APIDEMOS_APK"],
            "appium:noReset": False,
        }
    )
    mobile = webdriver.Remote(
        "http://127.0.0.1:4723",
        options=options,
    )
    yield mobile
    mobile.quit()


def test_open_activity_menu(driver) -> None:
    app_menu = WebDriverWait(driver, 10).until(
        lambda current: current.find_element(
            AppiumBy.ACCESSIBILITY_ID,
            "App",
        )
    )
    app_menu.click()

    activity = WebDriverWait(driver, 10).until(
        lambda current: current.find_element(
            AppiumBy.ACCESSIBILITY_ID,
            "Activity",
        )
    )
    assert activity.is_displayed()
```

注意：

- Appium 3 使用 W3C WebDriver 能力；扩展能力有 `appium:` 前缀。
- 默认服务地址是 `/`，不要从 Appium 1 旧教程机械复制 `/wd/hub`。
- fixture 无论成功失败都执行 `quit()`，释放 session 和设备。
- CI 应通过环境变量或设备服务注入 App 路径和设备配置。

## 5. 定位器优先级

建议从稳定到脆弱选择：

1. Accessibility ID：跨语言、可访问且通常最稳定。
2. Android resource-id / iOS predicate 或 class chain。
3. 平台原生文本/语义定位。
4. 有限、清晰的 XPath。
5. 坐标点击只用于没有元素树的特殊画布，并建立分辨率策略。

避免把长 XPath 和坐标散落在测试里。定位器属于页面/屏幕对象，业务用例表达“打开菜单、完成下单”等行为。

Appium Inspector 是独立工具，可查看元素树和试验定位器。截图、page source 和录屏可能包含敏感信息，采集和共享前应确认授权并最小化内容。

## 6. 显式等待与移动端状态

移动端常见异步来源：

- Activity/页面切换。
- 动画未结束。
- 网络响应。
- 系统权限弹窗。
- WebView Context 尚未出现。

等待可观察条件，不要写固定 `sleep(5)`：

```python
WebDriverWait(driver, 10).until(
    lambda current: current.find_element(
        AppiumBy.ACCESSIBILITY_ID,
        "Activity",
    ).is_displayed()
)
```

Hybrid App 需要等待并切换 Context：

```python
WebDriverWait(driver, 15).until(
    lambda current: len(current.contexts) > 1
)
driver.switch_to.context(
    next(name for name in driver.contexts if name.startswith("WEBVIEW"))
)
```

只有真实被测对象是 Hybrid App 时才使用；不要为了学习把普通 Web 页面包装成无意义的 Appium 用例。

## 7. 设备与数据策略

- 日常 PR：少量稳定模拟器冒烟。
- 主分支/夜间：更多系统版本、分辨率与真实设备。
- 发布前：关键机型、权限、网络切换、升级/安装路径。
- 每条用例拥有可识别的虚构数据，运行后清理。
- 记录 App 版本、OS、设备型号、驱动版本和 Server 版本。

设备矩阵应来自用户分布和业务风险，而不是盲目覆盖所有型号。

## 8. 常见错误

1. 使用 Appium 1 的 `desired_capabilities`、JSONWP 或默认 `/wd/hub` 教程。
2. 安装 Server 后忘记单独安装平台 Driver。
3. 用固定坐标适配所有设备。
4. 混用隐式等待、固定睡眠和显式等待。
5. 每条用例重复安装 App，套件极慢；或始终 `noReset=true`，状态污染。
6. App 崩溃后没有 `quit()`，设备 Session 堆积。
7. 为调试开放不安全能力或公网端口。
8. 在截图、日志、page source 中泄露公司或个人数据。

## 9. 练习与验收

### 练习

1. 安装 Appium 3 与 UiAutomator2，保存 `driver doctor` 的公开环境检查结果。
2. 在模拟器运行上面的 ApiDemos 冒烟。
3. 把固定等待替换为显式条件。
4. 添加一个不存在元素的失败场景，确认 fixture 仍会释放 Session。
5. 写出 Demo Shop 移动视口测试为何优先 Playwright，以及何种新增目标才需要 Appium。

### 验收标准

- [ ] `appium --version` 显示 3.x，UiAutomator2 已安装且 doctor 无阻断项。
- [ ] 测试使用 `UiAutomator2Options` 和 `appium:` 扩展能力。
- [ ] 定位器优先 accessibility/resource-id，无随意坐标点击。
- [ ] 没有依赖固定睡眠，异常时也会 `quit()`。
- [ ] Appium 只监听本地，无 relaxed security。
- [ ] 设备、App、日志和截图只含公开虚构内容。
