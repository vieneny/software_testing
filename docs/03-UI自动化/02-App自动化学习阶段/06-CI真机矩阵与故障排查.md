# 第六章：CI、真机矩阵与故障排查

本章把本地脚本变成分层反馈系统，并覆盖 Android、iOS 与 Hybrid 的平台差异。

## 1. 执行分层

| 通道 | 触发 | 内容 | 失败处理 |
|---|---|---|---|
| PR Offline | 每次提交 | 业务 Flow、Mock、契约、配置 | 阻断合并 |
| Emulator Smoke | 合并后 | Android/iOS 关键页面 | 保留证据并分诊 |
| Nightly Device | 夜间 | 系统版本、权限、中断、异常 | 趋势与 flaky 治理 |
| Release Matrix | 发布前 | 关键真机、升级/安装、弱网 | 按发布风险决策 |

默认 `pytest -q` 只运行离线测试。真机必须加 `--run-mobile`，防止普通 CI 或开发机意外创建 Session。

## 2. 设备矩阵

矩阵来自用户分布和变更风险：

- Android API Level、厂商定制、屏幕和 WebView；
- iOS 主流版本、设备尺寸和升级路径；
- 权限首次/拒绝/永久拒绝；
- 前后台、中断、旋转、语言、时区和网络；
- App 新装、覆盖安装、升级与数据迁移。

不要追求所有组合。为每个组合写选择原因、覆盖风险和未覆盖范围。

## 3. 分层排障顺序

```text
测试代码/依赖
  → Appium Client 请求
  → Server 与 Driver
  → ADB/WDA 连接
  → App 进程与页面状态
  → 定位、等待和断言
```

| 症状 | 先查 | 证据 |
|---|---|---|
| 无法创建 Session | capabilities、Driver、设备 | Server 日志、doctor、devices |
| instrumentation 无法初始化 | 残留 Session/进程 | Appium 进程、设备端进程 |
| 元素偶发找不到 | 页面状态、动画、弹窗 | screenshot、source、Activity |
| 点击后无变化 | 可点击条件、遮挡、业务请求 | 页面前后证据、网络/应用日志 |
| Hybrid 找不到元素 | Context 与 WebView 版本 | `driver.contexts`、WebView/Driver |
| iOS WDA 失败 | 签名、Bundle ID、版本组合 | xcodebuild、设备日志 |

不要先扩大超时或无限重跑。先判断失败层，再做单变量实验。

## 4. Hybrid App

原生页面和 WebView 使用不同元素树。等待 `WEBVIEW` Context，切换后按 Web DOM 定位，返回原生时切回 `NATIVE_APP`。同时验证 JS Bridge、登录态同步、返回键、键盘、白屏和 WebView 版本兼容。

## 5. CI 产物与保留

失败时上传最小证据包；成功时保留摘要、版本和趋势即可。设备池要有占用锁、超时回收、健康检查和隔离账号。公共 App 或公共实例只做低频人工 smoke。

## 6. 阶段最终验收

- [ ] 默认离线套件可重复通过；
- [ ] Android 或 iOS 至少完成一个真实公开 Demo smoke；
- [ ] 一条完整业务 Flow 有正常和负向断言；
- [ ] Session、App 和测试数据均可靠清理；
- [ ] 四类故障能稳定复现并保留第一失败；
- [ ] CI 至少分为 Offline 与 Device 两条通道；
- [ ] 设备矩阵有选择依据和残余风险；
- [ ] 能用证据说明一次失败在哪一层。

完成后进入 [质量工程阶段](../../05-质量工程/README.md)，把同样的配置、证据、门禁和故障分诊原则扩展到 API、Web、性能和 AI 测试。
