# 第二章：元素定位、等待与手势

本章把“能点到元素”升级为“定位契约稳定、等待条件可解释、不同屏幕下行为可控”。

## 1. Inspector 的正确用途

Appium Inspector 用于观察当前元素树、属性和候选定位器。检查前先确认 Inspector 与测试使用同一 App、设备、Activity/Bundle ID 和初始状态。

对每个关键元素记录：

| 字段 | 示例 | 用途 |
|---|---|---|
| 页面 | 登录页 | 确认定位器所属状态 |
| 业务名称 | 提交登录 | Test/Flow 使用的语义 |
| 首选定位 | accessibility id | 跨版本稳定契约 |
| 备选定位 | resource-id | 平台实现细节 |
| 出现条件 | 表单校验通过 | 等待条件 |
| 消失条件 | 页面跳转后 | 反向等待 |

## 2. 定位优先级

1. Accessibility ID；
2. Android resource-id；
3. Android UIAutomator、iOS Predicate/Class Chain；
4. 短且受控的 XPath；
5. 坐标仅用于没有可访问节点的特殊画布。

`resource-id` 重复时先缩小页面区域、组合稳定属性或推动开发增加测试标识。不要立即生成从根节点开始的绝对 XPath。

## 3. 等待页面状态

```python
class LoginScreen(BaseScreen):
    FORM = (AppiumBy.ACCESSIBILITY_ID, "login-form")
    SUBMIT = (AppiumBy.ACCESSIBILITY_ID, "login-submit")
    HOME = (AppiumBy.ACCESSIBILITY_ID, "catalog-screen")

    def wait_loaded(self) -> None:
        self.wait_visible(self.FORM)

    def submit(self) -> None:
        self.wait_clickable(self.SUBMIT).click()
        self.wait_visible(self.HOME)
```

等待条件必须与下一步操作一致：读取等可见、点击等可点击、遮罩等消失、页面跳转等唯一标识。Toast 使用 presence 与较短轮询；Hybrid App 等 `WEBVIEW` Context 出现后再切换。

## 4. 弹窗与分支

权限、更新、广告和系统弹窗分三类：

- 用例目标：显式断言允许/拒绝后的状态；
- 合法前置分支：检测到后按固定策略处理；
- 意外遮挡：保留证据并失败，不能捕获异常后静默继续。

## 5. 手势

手势使用窗口比例、平台原生命令和最大次数。工程中的 `BaseScreen.scroll_until_visible` 会在每次滑动后重新定位，到达预算后抛出明确超时。

```text
查找目标 → 未出现 → 执行一次平台手势 → 重新查找
                     ↑ 最多 N 次，禁止无限循环
```

长按、拖拽、多点触控和画布坐标要单独建立设备/分辨率策略，不应塞进通用 `click()`。
