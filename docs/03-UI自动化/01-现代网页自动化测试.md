# Playwright Web UI 自动化

> 本项目的 Web UI 主线选择是 Playwright Python + pytest。示例只操作本地虚构 Demo Shop，不录制或上传公司页面、账号、截图、视频、Trace 或 HAR。
>
> 配套的 TodoMVC、SauceDemo Page/Flow 代码、24 项递进练习和执行安全门见
> [Web 自动化项目全流程](./04-Web自动化项目全流程.md)。

## 学习目标

完成本章后，你应当能够：

1. 安装 Playwright 浏览器并运行仓库现有 UI 冒烟测试。
2. 优先使用面向用户的定位器和 Web-first 断言，避免固定等待。
3. 同时验证可见结果与关键网络响应。
4. 在失败时保留 Trace、截图等证据，并安全处理产物。
5. 判断哪些用例值得放入 UI 层，哪些应下沉到接口层。

## 1. 安装与第一次运行

终端 A 启动 Demo Shop：

```bash
cd labs/demo-shop
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[test,ui]'
uvicorn app.商城服务:app --host 127.0.0.1 --port 8000
```

终端 B 安装 Chromium 并执行测试：

```bash
cd labs/demo-shop
source .venv/bin/activate
python -m playwright install chromium
export DEMO_BASE_URL='http://127.0.0.1:8000'
pytest tests/ui -q
```

现有冒烟用例会打开首页，等待商品加载，点击第一个“购买”按钮，并确认状态区出现“订单创建成功”。

只安装用到的浏览器可以减少本地与 CI 下载量。需要跨浏览器验证时再执行：

```bash
python -m playwright install chromium firefox webkit
pytest tests/ui -q --browser chromium --browser firefox --browser webkit
```

## 2. 一条可靠的 UI 用例

仓库页面提供了可访问角色和稳定状态区：

- 一级标题：`Demo Shop`
- 商品列表：`aria-label="商品列表"`
- 下单按钮：可访问名称 `购买 <商品名>`
- 状态区：`role="status"`

基于用户可感知语义定位：

```python
from __future__ import annotations

import os
import re

from playwright.sync_api import Page, expect


def test_user_can_buy_a_product(page: Page) -> None:
    base_url = os.getenv("DEMO_BASE_URL", "http://127.0.0.1:8000")

    page.goto(base_url)

    expect(page.get_by_role("heading", name="Demo Shop")).to_be_visible()
    expect(page.get_by_role("status")).to_contain_text("已加载")

    buy_button = page.get_by_role(
        "button",
        name=re.compile(r"^购买 星光马克杯$"),
    )
    expect(buy_button).to_be_enabled()
    buy_button.click()

    expect(page.get_by_role("status")).to_contain_text("订单创建成功")
```

为什么优先 `get_by_role`：

- 更接近用户与辅助技术看到的界面。
- 通常比深层 CSS、XPath 和自动生成 class 稳定。
- 可访问名称变化时，测试会提醒交互语义发生了变化。

`data-testid` 不是禁用项。当元素没有合适语义或文案经常本地化时，可由产品和开发约定稳定 test ID；不要用它掩盖可访问性问题。

## 3. 等待：让条件驱动，而不是让时间驱动

Playwright 的 locator 和 `expect` 会自动等待元素达到目标状态：

```python
expect(page.get_by_role("status")).to_contain_text(
    "订单创建成功",
    timeout=5_000,
)
```

不要这样写：

```python
page.wait_for_timeout(3000)
```

固定睡眠会让快环境白等、慢环境仍失败。只有在明确测试时间行为或调试时，才应短暂使用固定等待。

## 4. 联合验证 UI 与网络

点击成功文案并不必然证明请求正确。可捕获对应 API 响应：

```python
def test_buy_sends_successful_order_request(page: Page) -> None:
    base_url = os.getenv("DEMO_BASE_URL", "http://127.0.0.1:8000")
    page.goto(base_url)
    expect(page.get_by_role("status")).to_contain_text("已加载")

    button = page.get_by_role("button", name="购买 星光马克杯")
    with page.expect_response(
        lambda response: (
            response.url.endswith("/api/orders")
            and response.request.method == "POST"
        )
    ) as response_info:
        button.click()

    response = response_info.value
    assert response.status == 201
    assert response.json()["total_cents"] == 3900
    expect(page.get_by_role("status")).to_contain_text("订单创建成功")
```

这种写法适合一两条关键链路。大量 API 规则应由 `tests/api` 覆盖；不要在 UI 层重复所有边界组合。

## 5. 测试金字塔中的 UI 职责

适合 UI 层：

- 关键用户旅程能否完成。
- 页面路由、组件组合、交互和可见反馈。
- 浏览器兼容性。
- 键盘、角色、名称等可访问性冒烟。
- 前后端集成与少量关键网络行为。

不适合大规模放在 UI 层：

- 数十个参数边界和错误码组合。
- 精确契约 Schema。
- 大量数据准备和清理。
- 性能压测。

Demo Shop 建议保持一条“加载商品—下单成功”UI 冒烟，再把幂等、库存、校验和金额组合放入接口测试。

## 6. 调试定位器

Playwright Codegen 可帮助探索页面：

```bash
python -m playwright codegen http://127.0.0.1:8000
```

录制结果是草稿，不是最终测试。提交前应：

1. 改为角色、名称、label、文本或明确 test ID。
2. 删除多余步骤和固定等待。
3. 增加业务断言。
4. 抽离秘密和真实账号。

调试模式：

```bash
PWDEBUG=1 pytest tests/ui/测试_演示商城网页.py -s
```

这是本地交互调试方式，不应作为 CI 默认。

## 7. Trace、截图和失败证据

保留失败 Trace：

```bash
pytest tests/ui -q \
  --tracing retain-on-failure \
  --screenshot only-on-failure \
  --output test-results
```

查看 Trace：

```bash
python -m playwright show-trace test-results/<trace目录>/trace.zip
```

CI 可上传失败产物，但产物可能包含页面文本、URL、请求和截图。公开仓库只允许上传本实验的虚构数据；真实项目必须按数据分级设置权限和保留期。

## 8. 复用：从行为出发

用例增多后，可把重复的页面行为封装：

```python
class ShopPage:
    def __init__(self, page: Page, base_url: str) -> None:
        self.page = page
        self.base_url = base_url
        self.status = page.get_by_role("status")

    def open(self) -> None:
        self.page.goto(self.base_url)
        expect(self.status).to_contain_text("已加载")

    def buy(self, product_name: str) -> None:
        self.page.get_by_role(
            "button",
            name=f"购买 {product_name}",
        ).click()
```

页面对象封装“打开商店、购买商品”等业务行为，不应建立一个包含 `click(selector)`、`sleep()` 的万能包装层。保持 Playwright 的定位器、等待和报错信息可见。

## 9. 常见错误

1. 使用 `div:nth-child(3) > button` 等结构性定位器。
2. 用 `wait_for_timeout` 修复竞态。
3. 只点击不断言，或只断言元素存在不验证业务结果。
4. 每个 API 边界都通过浏览器执行，导致套件慢且不稳定。
5. 用例共享同一个页面或订单状态，无法并行。
6. Codegen 生成后原样提交。
7. 将真实登录态、`storage_state`、Trace、截图或 HAR 提交到公开仓库。

## 10. 练习与验收

### 练习

1. 将现有用例改为明确购买“星光马克杯”，并断言成功金额。
2. 捕获 `POST /api/orders` 响应，断言 `201`。
3. 增加一个商品列表可访问名称的断言。
4. 故意改错按钮名称，生成并查看失败 Trace。
5. 安装 Firefox，完成 Chromium + Firefox 双浏览器执行。

### 验收标准

- [ ] `pytest tests/ui -q` 可重复通过。
- [ ] 核心定位器使用角色、名称或明确 test ID，无脆弱深层 CSS/XPath。
- [ ] 无用于“碰运气”的固定睡眠。
- [ ] 用例同时验证用户可见结果和至少一个关键网络结果。
- [ ] 失败时可生成 Trace，且产物只含虚构公开数据。
- [ ] UI 套件只覆盖关键旅程，接口规则没有无意义重复。
