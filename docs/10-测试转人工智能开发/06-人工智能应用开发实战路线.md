# 人工智能应用开发实战路线

> 路线方向：软件测试工程师 → Java 后端开发 → 人工智能应用开发  
> 建议周期：24～32 周，每周 10～15 小时  
> 课程参考事实截至：2026-07-27  
> 课程参考：[十指波教育《AI 驱动 Java 全栈》](https://www.itszb.com/java)

## 1. 路线目标

完成本路线后，应能独立交付一个使用 Java 和 Spring 构建的人工智能应用，包含：

- 业务后端；
- 数据库；
- Web 前端；
- 模型接入；
- 结构化输出；
- RAG；
- 工具调用或 Agent；
- 权限和审计；
- 自动化测试；
- 人工智能评测；
- 可观测性；
- Docker 和 CI。

路线不以“看完多少视频”为成功标准，而以以下证据为准：

- 能运行；
- 有测试；
- 有评测；
- 有文档；
- 能解释；
- 能复现；
- 能定位失败；
- 能持续迭代。

### 1.2 为什么不从 Agent 直接开始

Agent 表面上是模型调用和工具组合，实际上依赖：

- Java 编码；
- HTTP；
- 数据建模；
- Spring；
- 并发；
- 异常处理；
- 权限；
- 幂等；
- 测试；
- 监控；
- 安全。

基础不足时，即使示例能运行，也无法判断它是否正确、安全、可维护。

## 3. 第 0 阶段：能力诊断与环境

### 3.1 学习目标

- 明确已有测试能力和开发缺口；
- 建立安全、可复现的本地学习环境；
- 学会记录过程，而不是只记录成功截图；

### 3.2 环境建议

- LTS JDK；
- IntelliJ IDEA；
- Git；
- Maven Wrapper；
- Docker Desktop 或兼容容器环境；
- Node.js LTS；
- Python 仅用于辅助工具，不作为 Java 主线；
- 一个公开代码托管仓库；
- 单独的学习模型 API Key，设置消费额度。

Java 版本应与 Spring Boot、Spring AI 兼容。不要只因为数字最新就直接使用预览版。

官方参考：

- [Dev.java](https://dev.java/learn/)
- [Oracle Java SE 支持路线](https://www.oracle.com/java/technologies/java-se-support-roadmap.html)
- [Spring AI 官方仓库](https://github.com/spring-projects/spring-ai)

### 3.3 基线任务

独立完成：

1. 创建 Maven 项目。
2. 编写一个解析 JSON 的 Java 程序。
3. 为它写三个 JUnit 测试。
4. 用 Git 提交。
5. 在新目录重新 Clone。
6. 用一条命令运行测试。
7. 写明失败时如何排查。

### 3.4 产出

- 环境版本清单；
- 学习目标；
- 每周可投入时间；
- 基线代码；
- 基线测试结果；
- 自评表。

### 3.5 验收

- [ ] 新终端中可以运行。
- [ ] 没有绝对路径依赖。
- [ ] 没有密钥。
- [ ] 没有公司数据。
- [ ] 能解释 Maven 的 `compile`、`test`、`package`。

### 3.6 常见坑

- 花数天美化 IDE，却不写代码。
- 同时安装多个不兼容 JDK。
- 把 API Key 写进 `application.yml` 并提交。
- 使用公司邮箱、公司 Git 或公司数据创建个人项目。

## 4. 第 1 阶段：Java 工程基础

### 4.1 学习目标

掌握：

- 语法和类型；
- OOP；
- 集合和泛型；
- 异常；
- IO；

- Maven；
- JUnit；

### 4.2 学习顺序

#### 第 1 周：语言基础

- 变量、类型和运算；
- 条件、循环和方法；
- 数组；
- 类和对象；
- 封装；
- 单元测试第一步。

练习：

- 统计测试结果；
- 按状态过滤；
- 计算通过率；
- 参数非法时抛出明确异常。

#### 第 2 周：面向对象与集合

- 接口；
- 继承和组合；
- `List`、`Set`、`Map`；
- 泛型；
- 不可变对象；
- 值对象。

练习：

- `测试套件`、`测试用例`、`执行结果`、`失败分类`；
- 去重；
- 分组；
- 排序；
- 聚合。

#### 第 3 周：异常、IO 与序列化

- 受检异常和运行时异常；
- 文件和编码；
- JSON；
- 资源关闭；
- 日志；
- 错误提示。

练习：

- 读取自己生成的 JUnit XML 或 JSON；
- 错误文件隔离；
- UTF-8 中文测试；
- 输出汇总报告。

#### 第 4 周：Stream、并发与调试

- Lambda；
- Stream；
- 线程与线程池；
- Future 或现代并发能力；
- 共享状态；
- 断点和线程 Dump 基础。

练习：

- 并行读取多个合成报告；
- 限制并发；
- 单个文件失败不影响全部；
- 正确汇总失败。

#### 第 5～6 周：测试与重构

- JUnit 生命周期；
- 参数化测试；
- AssertJ；
- Mockito；
- 测试替身；
- 代码覆盖率的正确使用；
- 重构；
- Checkstyle 或 SpotBugs。

### 4.3 实战项目：测试报告聚合器

业务全部虚构。

功能：

- 支持 JSON 与 JUnit XML；
- 统计通过、失败、跳过；
- 按模块和失败类型分组；
- 识别重复用例；
- 导出 Markdown 报告；
- 允许命令行参数；
- 对错误文件给出原因。

推荐目录：

```text
测试报告聚合器/
├── README.md
├── pom.xml
├── src/main/java/
├── src/test/java/
├── 示例数据/
└── docs/
```

### 4.4 必做练习

- 空文件；
- 非法 JSON；
- 重复测试编号；
- 总数为零；
- 中文；
- 超大文件；
- 多文件并发；
- 输出目录无权限；
- 某个文件读取失败。

### 4.5 产出

- 源码；
- 单元测试；
- 示例数据生成脚本；
- 类图；
- 异常设计说明；
- 性能对比；
- 人工智能辅助代码审查记录。

### 4.6 验收

- [ ] `mvn test` 稳定通过。
- [ ] 核心代码无需联网。
- [ ] 能解释每个主要类的职责。
- [ ] 能独立新增一种失败分类。
- [ ] 能定位一个空指针或并发问题。
- [ ] 人工智能生成代码均经过人工审查。

### 4.7 常见坑

- 主方法包含全部逻辑。
- 为提高覆盖率写无意义断言。
- 所有依赖都 Mock。
- 使用固定睡眠测试并发。
- 不处理字符编码。

### 5.3 实战项目：质量学习任务管理服务

不要使用真实公司缺陷或需求，全部生成合成内容。

领域：

- 用户；
- 学习计划；
- 学习任务；
- 通用测试案例；
- 执行记录；
- 标签。

核心规则：

- 用户只能访问自己的计划；
- 任务状态按规则流转；
- 同一计划标题不重复；
- 更新使用版本号防止覆盖；
- 删除采用明确策略；
- 所有写操作有审计时间。

建议接口：

```text
POST   /api/认证/登录
GET    /api/计划
POST   /api/计划
GET    /api/计划/{编号}
PUT    /api/计划/{编号}
POST   /api/计划/{编号}/任务
PATCH  /api/任务/{编号}/状态
GET    /api/执行记录
```

实际 Java 包名和 URL 可以使用符合语言生态的英文标识；“文件名中文化”要求不应破坏 Java、Maven、Git 或框架的强制约定。

### 5.4 必做练习

- 正常 CRUD；
- 参数错误；
- 未登录；
- 越权；
- 唯一约束冲突；
- 乐观锁冲突；
- 事务回滚；
- 分页边界；
- SQL 慢查询；
- 数据库不可用。

### 5.5 产出

- 需求说明；
- 领域图；
- ER 图；
- OpenAPI；
- 数据库迁移；
- 测试金字塔；
- Docker 配置；
- CI；
- 安全说明；
- 故障排查手册。

### 5.6 验收

- [ ] Controller 没有复杂业务逻辑。
- [ ] 实体不直接暴露所有接口。
- [ ] Testcontainers 使用真实数据库引擎。
- [ ] 数据库迁移可从零执行。
- [ ] 关键越权场景有自动测试。
- [ ] 新环境可按 README 启动。
- [ ] 代码仓库没有真实 `.env` 和密钥。

### 5.7 常见坑

- 只写 CRUD，没有业务规则。
- 只使用 H2，忽略 MySQL 差异。
- 为了“解耦”创建大量无意义接口。
- 所有接口都返回 200。
- 日志输出密码、Token 或完整请求。
- 事务注解位置错误。

### 5.8 开源根基

1. [Spring REST Service](https://github.com/spring-guides/gs-rest-service)
2. [Spring PetClinic](https://github.com/spring-projects/spring-petclinic)
3. [Spring Boot 测试文档](https://docs.spring.io/spring-boot/reference/testing/spring-boot-applications.html)
4. [Spring Boot Testcontainers](https://docs.spring.io/spring-boot/reference/testing/testcontainers.html)
5. [Testcontainers for Java](https://java.testcontainers.org/)

对 PetClinic 的学习任务：

- 运行；
- 画请求调用链；
- 找到配置；
- 找到一个实体及其校验；
- 阅读测试；
- 新增一个通用字段；

### 7.3 实战项目：测试点草案生成器

输入：

- 自己编写的虚构需求；
- 业务规则；
- 风险级别；
- 输出语言。

输出结构：

```json
{
  "需求摘要": "虚构需求摘要",
  "风险": [
    {
      "名称": "权限绕过",
      "级别": "高",
      "原因": "用户只能访问自己的学习计划"
    }
  ],
  "测试点": [
    {
      "标题": "访问其他用户计划",
      "前置条件": ["存在两个合成用户"],
      "步骤": ["用户甲请求用户乙计划"],
      "预期": ["返回禁止访问"]
    }
  ]
}
```

Java 侧必须校验：

- 必填字段；
- 枚举；
- 数组上限；
- 文本长度；
- 危险 HTML；
- 重复测试点；
- 空输出；
- 无效 JSON。

### 7.4 测试分层

#### 离线单元测试

- Prompt 参数组装；
- Schema 校验；
- 错误映射；
- 成本计算；
- 会话隔离。

#### Fake 模型集成测试

- 固定正确响应；
- 无效 JSON；
- 超时；
- 限流；
- 空响应；
- 流式中断。

#### 小规模在线测试

- 必须显式启用；
- 设置费用上限；
- 不进入默认 CI；
- 记录模型和时间；
- 不断言完整自然语言完全相等。

### 7.5 产出

- 模型适配接口；
- Spring AI 实现；
- Fake 实现；
- 流式接口；
- 结构化 Schema；
- 测试；
- Token 和耗时指标；
- Prompt 变更记录。

### 7.6 验收

- [ ] 关闭网络时大部分测试仍通过。
- [ ] 模型失败不导致线程无限等待。
- [ ] 输出不合法时不写业务数据库。
- [ ] 会话不串用户。
- [ ] API Key 不进入日志。
- [ ] 能替换一个模型供应商。

### 7.7 常见坑

- 在 Controller 中直接调用 SDK。
- 以自然语言全文相等作为测试断言。
- 所有测试调用真实模型。
- 无限重试。
- 把温度调低误认为绝对确定。
- 日志记录完整 Prompt 和响应。

## 9. 第 6 阶段：Tool Calling、Agent 与 MCP

### 9.1 学习目标

- 理解工具调用与 Agent 循环；
- 让模型只选择工具，不直接获得系统权限；
- 建立审批、预算、幂等和审计；
- 构建一个最小 MCP Client/Server；
- 设计 Agent 测试。

### 9.2 Tool Calling 与 Agent 的区别

Tool Calling：

- 模型选择一个工具；
- 应用校验参数；
- 应用执行；
- 结果返回模型；
- 流程通常受代码控制。

Agent：

- 可能多步规划；
- 可能重复调用多个工具；
- 有状态；
- 可能自我修正；
- 风险、成本和不可预测性更高。

对初学者，先工具调用，后 Agent。

### 9.3 工具设计模板

每个工具必须定义：

```text
名称
用途
允许调用者
输入 Schema
输出 Schema
超时
重试规则
幂等规则
权限
审计字段
敏感性
是否需要人工批准
失败补偿
```

### 9.4 实战项目：测试学习助手

全部工具操作公开或本地合成环境。

只读工具：

- 查询公开教程目录；
- 查询公开项目说明；
- 检索本地公开知识库；
- 查询本地合成测试执行结果。

低风险写工具：

- 生成一份新的虚构学习任务；
- 保存测试点草稿；
- 生成 Markdown 报告。

高风险模拟工具：

- 模拟“执行测试”；
- 模拟“创建缺陷”；
- 模拟“发送通知”。

高风险模拟工具必须：

- 默认不执行；
- 显示计划；
- 等待人工确认；
- 使用合成目标；
- 记录审计。

### 9.5 Agent 测试矩阵

正常：

- 选择正确工具；
- 参数完整；
- 结果正确整合。

异常：

- 工具超时；
- 工具返回错误；
- 空结果；
- 重复调用；
- 达到最大步数；
- Token 预算耗尽。

安全：

- 用户要求绕过审批；
- 网页内容包含恶意指令；
- 参数包含命令注入；
- 请求访问其他用户数据；
- 请求读取密钥；
- 请求执行未注册工具。

可靠性：

- 服务重启；
- 同一请求重放；
- 并发会话；
- 下游限流；
- 人工拒绝审批。

### 9.6 MCP 练习

先实现本地只读 MCP Server：

- 一个 Resource：公开教程索引；
- 一个 Tool：根据关键词检索公开教程；
- 一个 Prompt：生成学习计划草稿。

再实现 Client：

- 连接；
- 列出能力；
- 调用；
- 超时；
- 断线重连；
- 不可信返回处理。

### 9.7 产出

- 工具注册表；
- Agent 状态图；
- 审批流；
- 审计日志；
- MCP Client/Server；
- 安全测试；
- 失败演练；
- 成本和最大步数配置。

### 9.8 验收

- [ ] 模型不能直接执行任意 Shell。
- [ ] 未注册工具不可调用。
- [ ] 高风险操作必须审批。
- [ ] 重放请求不会重复产生结果。
- [ ] 一次调用的每一步可追踪。
- [ ] 达到步数或费用上限会停止。
- [ ] 外部内容不能覆盖系统规则。

### 9.9 常见坑

- 把 Agent 当作普通聊天。
- 工具接收自由文本并直接执行。
- 给 Agent 过大权限。
- 无最大步数。
- 无人工确认。
- 只测试成功演示。
- 把 MCP Server 默认视为可信。
