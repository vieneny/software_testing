# 测试转人工智能开发二十四周计划

> 默认投入：每周 10～15 小时
>
> 示例实现主线：Java/Spring Boot/Spring AI。开始前必须按当前 BOSS 目标岗位选择 Java 或 Python；目标岗位以 Python/FastAPI/LangGraph 为主时，按文末替换表实现相同学习目标。这里的 Java 顺序是可执行课程版本，不代表市场统一默认语言。

## 一、计划使用规则

每周时间建议：

- 20%：官方文档与原理；
- 50%：编码和测试；
- 20%：故障注入、调试和复盘；
- 10%：整理作品证据。

每周必须留下：

1. 可运行 commit；
2. 自动化测试；
3. 一次主动失败；
4. 一页学习/架构笔记；
5. 下一周风险。

如果验收不通过，顺延一周；不要为了赶进度跳过普通后端、数据库和测试。

## 二、第 1～4 周：把测试代码能力转成开发基础

| 周 | 学习与实践 | 必须交付 | 通过标准 |
|---:|---|---|---|
| 1 | 目标岗位、Git、Linux、HTTP、开发环境 | 目标声明、技能自评、环境自检 | 能解释路线选择并完成环境验收 |
| 2 | Java 语法、OOP、集合、异常、IO、Maven | “虚构测试结果解析器” | 能解析 JSON/XML；错误输入有明确异常 |
| 3 | 泛型、Stream、基础并发、JUnit、Mockito、AssertJ | 统计与分类模块、单元测试 | 核心逻辑有正常/边界/异常；测试可重复 |
| 4 | 分层、配置、日志、代码规范、CI | “测试报告聚合器”小项目 | CI 自动检查；新机器按 README 可运行 |

第 4 周关卡：

- 不调用 AI；
- 能独立解释代码结构；
- 测试不是 AI 自动生成后未经核对；
- 至少记录一个设计取舍和一个失败复盘。

未通过就补 Java/工程化，不进入 Spring AI。

## 三、第 5～8 周：普通后端完整闭环

| 周 | 学习与实践 | 必须交付 | 通过标准 |
|---:|---|---|---|
| 5 | Spring IoC、分层、REST、Validation、统一异常 | 合成缺陷创建/查询 API | OpenAPI、状态码和错误模型清晰 |
| 6 | PostgreSQL、表设计、索引、事务、迁移 | 缺陷/测试计划数据模型 | 迁移可重放；事务边界有测试 |
| 7 | Spring Security、认证、RBAC、资源所有权、幂等 | 登录与角色、模拟审批 API | 未认证/越权/重复请求被正确处理 |
| 8 | MockMvc、Testcontainers、WireMock、Docker Compose、CI | 普通后端 v1 | 单元+集成+接口测试；一键启动 |

第 8 周关卡：

- 能在空数据库自动建表；
- 能解释一个索引为什么存在；
- 能模拟数据库或外部服务失败；
- 日志有 Trace ID 且无密钥；
- 普通后端仍不依赖模型。

## 四、第 9～12 周：AI 应用基础

| 周 | 学习与实践 | 必须交付 | 通过标准 |
|---:|---|---|---|
| 9 | LLM 消息、Token、上下文、采样、结构化输出、流式 | 模型协议实验与对比笔记 | 解释非确定性；输出经 Schema 校验 |
| 10 | Spring AI ChatClient/Model、Provider 抽象、配置 | `/test-points` 最小 API | Mock 与本地模型可切换 |
| 11 | 超时、429、退避、断流、取消、Token/成本预算 | 故障测试套件 | 重试有上限；不可重试错误不重试 |
| 12 | Prompt 版本、结构化测试点、简单前端流式展示 | AI 应用 v1 | 版本可追踪；输出不是自由文本拼接 |

第 12 周关卡：

- 没有云 Key 也能跑确定性测试；
- 少量真实 Provider 测试与主 CI 分离；
- Prompt、模型和代码版本进入报告；
- 能展示一次坏 JSON、一次 429 和一次断流的处理。

## 五、第 13～16 周：RAG 与评测

| 周 | 学习与实践 | 必须交付 | 通过标准 |
|---:|---|---|---|
| 13 | 公开资料清单、解析、清洗、Chunk、元数据、许可证 | 可重放导入流水线 | 每条数据有来源、哈希和审核状态 |
| 14 | Embedding、pgvector、精确/近似检索、过滤 | 检索 API 和 Testcontainers 集成测试 | Top-k、过滤、删除有确定性测试 |
| 15 | Query、Rerank、上下文、引用、冲突与拒答 | 带引用知识问答 | 引用可打开；无证据时不编造 |
| 16 | 黄金集、Recall@k、忠实度、人工校准、回归报告 | 30～50 条数据集和基线 | 检索与回答分开评价；失败样本可定位 |

第 16 周关卡：

- 更新/删除原文后索引同步；
- 能说明一次错误来自检索还是生成；
- 模型裁判结果经过人工抽检；
- 报告写明数据集、模型、Prompt、环境和日期。

## 六、第 17～20 周：Tool、MCP 与受控 Agent

| 周 | 学习与实践 | 必须交付 | 通过标准 |
|---:|---|---|---|
| 17 | Tool Calling、Schema、授权、幂等、审计 | 两个只读本地工具 | 服务端重新校验参数和用户权限 |
| 18 | MCP 规范、Java SDK、Client/Server、兼容性 | MCP 工具服务与契约测试 | 超时、取消、错误、恶意结果有用例 |
| 19 | 状态、节点、边、检查点、HITL、终止条件 | 缺陷分诊状态图 | 写操作前强制审批；最大步数有效 |
| 20 | 恢复、补偿、重复事件、模型/工具失败 | 受控 Agent v1 | 服务重启后可恢复；重复请求无重复副作用 |

第 20 周关卡：

- Tool 输出不能提升为系统指令；
- 人工批准不是唯一授权机制；
- 模型不能访问任意 Shell/SQL/文件/URL；
- Agent 每步可追踪、可中止、可恢复；
- 失败后给出明确状态，不伪装成成功。

## 九、有经验学习者如何压缩

只按验收跳级，不按“工作年限”跳级：

- 已能独立交付普通后端且提供证据：从第 9 周开始；
- 已有生产 RAG：从第 17 周开始，但先用本项目公开数据跑第 16 周评测；
- 已有 Agent 项目：直接挑战第 20～24 周的恢复、安全和作品验收；
- 只有自动化测试经验：不能跳过第 5～8 周。

最短也建议保留：

- 普通后端关卡；
- 模型故障测试；
- RAG 分层评测；
- 工具授权；
- 安全与作品复现。

## 十一、中途失速处理

### 卡在语言

暂停框架，做 3～5 个小任务：解析、转换、聚合、并发、异常。每题有测试。

### 卡在 Spring/FastAPI

移除模型，只保留 CRUD、数据库、鉴权和错误处理，直到能独立解释。

### 卡在 RAG

先用 10 篇短公开文档，直接打印 Chunk 和分数；不要同时加 GraphRAG、复杂 Rerank 和多向量库。

### 卡在 Agent

把模型路由替换为固定 `if/else` 状态机，先证明流程、恢复和授权，再逐步开放模型决策。

### 费用不可控

Mock 为主、本地小模型辅助、云模型只跑小型契约和基线；CI 设置预算、并发和手工触发。

### 电脑资源不足

使用 pgvector 和小语料，不部署 RAGFlow/Milvus/vLLM；观测组件可按需启动。

## 十二、24 周后的选修

按岗位需要只选一个：

- Spring Cloud/消息队列/Redis：企业 Java 后端；
- Qdrant/混合检索：RAG 专项；
- LangGraph 深入：Python Agent；
- A2A：Agent-to-Agent 互操作；
- LiteLLM：多模型网关；
- vLLM：有 GPU 的推理服务；
- 微调：有高质量标注数据和明确收益假设时；
- 给 Spring AI、LangChain4j、MCP 或评测框架贡献文档/测试。

不要在毕业项目尚未稳定时同时开启多个选修。
