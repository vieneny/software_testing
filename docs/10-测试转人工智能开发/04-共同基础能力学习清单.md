# 人工智能应用与智能体开发共同基础能力

> 核对日期：**2026-07-27**
>
> 使用方法：把本页当成“能力验收表”，不是名词清单。每项必须有代码、测试、运行记录或口头解释证据。

## 一、基础不是越多越好，而是能支撑交付

两门参考课程分别从 Java 和 Python 出发，但 AI 应用开发的共同底座高度一致：

```text
编程与计算机基础
  → 后端 API 与数据库
  → 测试、配置、日志、CI、容器
  → LLM/RAG/Tool/Agent 原理
  → 评测、安全、可观测、成本与发布
```

最常见的错误是从“Prompt 技巧”直接跳到 Agent。正确顺序是先把普通软件做可靠，再处理 AI 的非确定性。

## 二、编程与计算机基础

### 2.1 一门主语言

Java 主线需要：

- Java 17/21 的语法、OOP、泛型、集合、异常、IO、Stream；
- 基础并发、线程池、锁、超时和 `CompletableFuture`；
- Maven/Gradle 至少熟练一种；
- JVM 内存、GC、线程 Dump 和基本性能定位；
- JUnit 5、Mockito、AssertJ。

Python 主线需要：

- Python 3.11+ 的数据结构、函数、类、异常、上下文管理器；
- 类型标注、`dataclass`/Pydantic；
- 迭代器、生成器、装饰器；
- `asyncio`、任务、取消、超时；
- 虚拟环境、`pyproject.toml`、依赖锁定；
- pytest、fixture、参数化、Mock。

验收任务：

- 不调用 AI，读取一组虚构测试结果并生成统计报告；
- 核心逻辑有边界测试；
- 能解释每个依赖、异常路径和复杂度；
- 代码格式化、静态检查、测试在 CI 中自动执行。

### 2.2 数据结构与算法

应用开发不要求先刷几百题，但必须理解：

- List/Map/Set/Queue/Stack；
- 排序、查找、去重、分组；
- 时间和空间复杂度；
- 树、图与有向无环图；
- 广度/深度遍历；
- LRU、优先队列和滑动窗口的应用场景。

Agent 的状态图、工作流、依赖调度和循环终止都依赖这些基础。

### 2.3 操作系统与网络

必须会：

- 进程、线程、文件描述符、信号；
- CPU、内存、磁盘、网络的基本指标；
- DNS、TCP、TLS、HTTP/1.1、HTTP/2；
- 请求头、状态码、缓存、代理、超时；
- SSE 与 WebSocket 的区别；
- Linux 进程、端口、日志、权限和环境变量；
- Shell 管道和退出码。

验收任务：

- 用命令找到占用端口的进程；
- 解释一次 HTTPS 请求经历的主要阶段；
- 模拟服务连接超时、读取超时和客户端取消；
- 说明流式响应中断后客户端如何处理。

## 三、后端工程基础

### 3.1 API 设计

必须掌握：

- REST 资源与动作建模；
- OpenAPI 和 JSON Schema；
- 输入校验、统一错误模型、关联 ID；
- 分页、过滤、排序；
- API 版本与兼容性；
- 幂等键和重复请求处理；
- 限流、配额与 `Retry-After`；
- 同步、异步任务、轮询、SSE、WebSocket 的选择。

AI 接口还需要：

- 模型和提示词版本；
- 流式事件类型；
- 引用和证据结构；
- Tool Call 的请求、结果和错误；
- Token/成本元数据是否对客户端暴露；
- 取消、超时和部分结果语义。

最低验收：

- OpenAPI 能生成并通过契约校验；
- 相同幂等键不会创建两次任务；
- 非法输入、未认证、无权限、限流和内部错误可区分；
- 日志能用关联 ID 串起一次请求。

### 3.2 数据库与数据建模

必须掌握：

- 表、主键、外键、唯一约束；
- 一对一、一对多、多对多；
- 范式与有意识的反范式；
- 事务、隔离级别、锁和死锁；
- 索引、执行计划和慢查询；
- 连接池、迁移、备份和恢复；
- 乐观锁、审计字段、软删除边界。

RAG/Agent 还要理解：

- 文档、Chunk、Embedding、索引版本之间的关系；
- 会话、运行、步骤、工具调用、审批和 Trace 的持久化；
- 向量与元数据过滤；
- 删除原文时如何同步删除索引；
- 多租户/多用户数据隔离。

默认建议先使用 PostgreSQL + pgvector；只有出现独立扩展、检索特性或容量需求时再学习 Qdrant 等专用数据库。

### 3.3 鉴权与授权

必须区分：

- Authentication：你是谁；
- Authorization：你能做什么；
- OAuth2/OIDC 与简单 JWT 的适用范围；
- RBAC、ABAC、资源所有权；
- Access Token/Refresh Token；
- 密钥轮换、最小权限和审计。

Agent 的工具授权不能只依赖模型判断。服务端必须根据真实用户身份和工具策略再次校验。

## 四、软件工程与交付

### 4.1 Git 和协作

必须会：

- 小步提交、清晰提交信息；
- 分支、合并、冲突处理；
- Pull/Merge Request 描述；
- Code Review；
- Tag、Release 和变更日志；
- 不提交密钥、大文件、生成物和本地环境。

每个作品至少保留：

- 需求/设计 Issue；
- 小步 commit；
- 一次自我 Code Review；
- 一次升级或故障修复记录。

### 4.2 配置、依赖和密钥

必须做到：

- 配置与代码分离；
- 开发、测试、演示环境可区分；
- `.env` 只提供无密钥示例；
- 依赖锁定，记录 JDK/Python/Node/Docker 范围；
- 模型名、Base URL、超时、预算可配置；
- 日志不打印 Token、密钥和敏感正文。

AI SDK 更新很快。Java 用 BOM，Python 用 lockfile；每次升级先读官方迁移说明并跑完整回归。

### 4.3 测试分层

至少具备：

| 层级 | 验证对象 | 是否调用真实模型 |
|---|---|---|
| 单元测试 | 切分、校验、路由、权限、预算、状态转换 | 否 |
| 组件测试 | API、Repository、工具适配器 | 否，模型/工具用 Stub |
| 集成测试 | 数据库、向量库、消息组件 | 通常否 |
| Provider 契约测试 | 模型 API、Embedding API 的实际兼容性 | 少量、受预算控制 |
| 离线 AI 评测 | 黄金集上的质量、检索和任务指标 | 是或固定回放 |
| 端到端测试 | 用户旅程、Agent 执行、审批和恢复 | 小规模 |
| 安全/性能测试 | 越权、注入、资源耗尽、p95 与成本 | 仅自有靶场 |

测试人员转开发要避免两个极端：

- 所有测试都 Mock，导致不知道真实 Provider 已经不兼容；
- 所有测试都调用真实模型，导致慢、贵、波动且难诊断。

### 4.4 CI/CD

流水线至少包含：

1. 格式与静态检查；
2. 单元测试；
3. 组件/集成测试；
4. 依赖和密钥扫描；
5. 构建容器；
6. 小规模 AI 回归；
7. 生成报告与制品；
8. 手工批准后部署演示环境。

AI 回归需要预算、超时和并发上限。不要在每个 commit 上运行全量昂贵评测。

### 4.5 Docker 与运行环境

能：

- 编写最小镜像；
- 使用非 root 用户；
- 健康检查和优雅关闭；
- 用 Compose 启动应用、数据库和观测组件；
- 固定镜像 tag；
- 管理本地 volume；
- 在 ARM64 Mac 上识别镜像兼容问题。

Kubernetes 放到作品稳定后再学，不应成为第一个聊天接口的前置。

## 五、AI 应用共同原理

### 5.1 模型调用

必须能解释：

- System/User/Assistant/Tool 消息；
- Token、上下文窗口与截断；
- Temperature、Top-p 和随机性；
- Stop、最大输出、结构化输出；
- 同步与流式；
- Rate Limit、429、重试和退避；
- 模型能力、价格、延迟和数据政策差异。

练习：

- 同一输入运行多次，观察非确定性；
- 用 JSON Schema 验证结构化输出；
- 模拟 429、500、超时、断流和坏 JSON；
- 给出明确的重试上限和降级策略。

### 5.2 Prompt 与上下文工程

Prompt 不是魔法咒语。需要管理：

- 任务、输入、约束、输出 Schema；
- Few-shot 示例；
- 不可信上下文的分隔；
- Prompt 版本、测试集和变更原因；
- 长上下文裁剪和摘要；
- 用户输入、检索内容、工具结果的优先级。

完成标准不是“主观感觉更好”，而是同一评测集上的质量、延迟、成本和失败类型对比。

### 5.3 RAG

完整链路：

```text
公开原文
→ 解析/清洗
→ Chunk 与元数据
→ Embedding
→ 向量/关键词索引
→ Query 改写
→ 检索与过滤
→ Rerank
→ 上下文组装
→ 生成、引用、拒答
→ 评测与反馈
```

必须分别评测：

- 索引是否完整；
- 相关 Chunk 是否进入 Top-k；
- 元数据/权限过滤是否正确；
- 上下文是否支持答案；
- 回答是否忠实并给出正确引用；
- 无证据时是否拒答；
- 文档更新/删除后是否生效。

### 5.4 Tool Calling

模型只负责提出调用建议，应用负责：

- 工具白名单；
- JSON Schema；
- 参数校验；
- 用户授权；
- 超时、重试和熔断；
- 幂等和补偿；
- 输出大小与内容过滤；
- 审计和人工批准。

第一个工具只允许读取公开/合成数据。写操作先写到内存模拟工单，并必须人工确认。

### 5.5 Agent

Agent 至少包含：

- 明确目标和终止条件；
- 状态；
- 节点与边；
- 工具；
- 记忆/检查点；
- 人工干预；
- 错误与恢复；
- 预算和最大步数；
- Trace 与评测。

先实现确定性状态图，再逐步开放模型决策。自由循环、多 Agent 和高权限工具是后期选修。

### 5.6 MCP 与 A2A

- MCP 主要解决 Agent/应用如何发现和调用工具、资源、Prompt；
- A2A 主要解决 Agent 与 Agent 之间的发现、通信和任务协作；
- 两者都不是自动提供安全的“万能连接器”；
- 远程输入、Tool Schema、Agent Card、返回内容都应视为不可信；
- 学习项目必须固定协议/SDK 版本并做兼容性测试。

官方来源：

- [MCP 规范仓库](https://github.com/modelcontextprotocol/modelcontextprotocol)；
- [MCP Java SDK](https://github.com/modelcontextprotocol/java-sdk)；
- [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk)；
- [A2A 规范](https://github.com/a2aproject/A2A)。

## 六、AI 质量与安全

### 6.1 评测数据集

每条样本至少记录：

- 稳定 ID；
- 输入和场景；
- 期望事实/证据；
- 允许和禁止行为；
- 期望工具与参数；
- 标签和难度；
- 数据来源与许可证；
- 人工审核状态；
- 创建/修改时间。

禁止把公司问题、真实用户对话或生产 Trace 当成个人作品评测集。

### 6.2 指标

| 层 | 典型指标 |
|---|---|
| 检索 | Recall@k、MRR、过滤正确率、引用覆盖 |
| 生成 | 事实一致性、忠实度、相关性、结构合规 |
| 工具 | 工具选择、参数正确、调用成功、幂等 |
| Agent | 任务成功率、步数、恢复率、人工介入率 |
| 安全 | 注入攻击成功率、越权率、敏感数据泄露 |
| 运行 | p50/p95、错误率、Token、单任务成本 |

模型裁判不能作为唯一证据。要组合确定性检查、人工标注、模型评分和失败样本分析。

### 6.3 威胁

至少覆盖：

- Prompt Injection 和间接注入；
- 不安全输出处理；
- 敏感信息泄露；
- 过度工具授权；
- 资源耗尽和无限循环；
- 向量库/知识库投毒；
- 供应链和模型/插件风险；
- Agent 身份与委托权限；
- 日志和 Trace 二次泄露。

参考 [OWASP LLM Applications Top 10 2025](https://genai.owasp.org/llm-top-10/) 和 [OWASP Agentic Applications Top 10 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/)。

## 七、可观测性与可靠性

每次请求至少可关联：

```text
HTTP 请求
→ Prompt/模型调用
→ Embedding
→ 检索与 Rerank
→ Tool Call
→ Agent Step
→ 最终响应
```

记录：

- Trace ID、运行 ID、用户的匿名标识；
- 模型、Prompt、知识库和应用版本；
- 延迟、Token、错误类型；
- 检索文档 ID，不默认记录敏感正文；
- 工具名、状态、授权结果，不记录密钥；
- 评测结果和人工反馈。

Spring AI 官方说明 Prompt 和 Completion 可能包含敏感数据，默认不导出正文。学习项目也应采用相同的最小记录原则：
[Spring AI Observability](https://docs.spring.io/spring-ai/reference/observability/index.html)。

可靠性必须设计：

- 连接/读取/总超时；
- 仅对可重试错误做指数退避；
- 最大重试和最大 Agent 步数；
- 熔断、隔离和 Provider 降级；
- 客户端取消与服务端清理；
- Checkpoint 和幂等恢复；
- Token/金额/时间预算；
- 部分失败和人工接管。

## 八、最小前端能力

即使以后主做后端，也要能交付一个可演示界面：

- HTML/CSS/JavaScript 基础；
- Vue 3 或 React 二选一；
- TypeScript；
- API 客户端、登录态、错误提示；
- 流式消息、取消、重连；
- 引用、工具步骤和审批 UI；
- Vitest/组件测试和 Playwright 关键旅程。

不用成为视觉设计师，但必须让别人能操作、看懂状态和复现错误。

## 九、共同基础验收表

| 能力 | 最低证据 | 未通过时补什么 |
|---|---|---|
| 主语言 | 1000 行以内可维护小项目，测试通过 | 语言与工程化 |
| API | OpenAPI、统一错误、鉴权、幂等 | HTTP 与 Web 框架 |
| 数据库 | ER 图、迁移、事务和集成测试 | SQL、事务、索引 |
| Git/CI | 小步提交、流水线、制品 | Git 与 CI |
| Docker | 新机器按 README 启动 | 容器与配置 |
| LLM 调用 | 结构化输出、流式、故障处理 | 模型 API 基础 |
| RAG | 引用、拒答、分层评测 | 数据流水线与检索 |
| Tool/MCP | Schema、授权、Mock、审计 | 工具协议与安全 |
| Agent | 状态图、恢复、HITL、终止 | 工作流与异步 |
| Eval | 黄金集、阈值、人工校准 | AI 测试方法 |
| Observability | 端到端 Trace、延迟/Token/错误 | OTel/Micrometer |
| Security | 威胁模型和攻击回归 | OWASP GenAI |

至少前五项全部通过，才开始主 AI 项目；所有项通过，才进入毕业作品验收。
