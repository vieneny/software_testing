# 测试转人工智能开发：定位、能力迁移与路线选择

> 核对日期：**2026-07-27**

## 一、先确定要转的不是同一种岗位

“AI 开发”至少包含四类不同工作，学习投入和面试标准差异很大。

| 目标方向 | 主要工作 | 最重要的基础 | 典型交付物 | 本模块覆盖 |
|---|---|---|---|---|
| AI 应用后端开发 | 把模型接入业务系统，开发 API、数据、权限、RAG、工具 | Java/Python 后端、数据库、分布式基础 | 可部署服务、接口、数据模型、测试与监控 | 主线 |
| Agent 应用开发 | 状态管理、任务编排、工具调用、恢复、人工审批 | Python/Java 后端、异步、工作流、安全 | 可控 Agent、工具服务、执行轨迹和评测 | 主线 |
| AI 质量/评测开发 | 数据集、评测器、红队、Trace、回归门禁 | 测试设计、Python、统计、AI 系统原理 | 评测框架、质量看板、门禁与风险报告 | 主线 |
| 模型算法/训练 | 预训练、后训练、微调、推理优化、论文复现 | 数学、机器学习、PyTorch、算法与算力 | 模型、训练流水线、实验和指标 | 仅选修 |

对于测试工程师，最短的可信路径通常不是直接竞争模型算法岗，而是：

```text
软件测试/自动化
    → 能独立交付普通后端
    → 能开发 RAG 与工具调用应用
    → 能证明 AI 应用的质量、安全和可靠性
    → AI 应用开发或 Agent 开发
```

## 二、测试能力不是包袱，而是待转换的资产

### 2.1 可以直接迁移的能力

| 测试经验 | 转成开发能力 | 作品里如何证明 |
|---|---|---|
| 需求分析和风险识别 | 用户故事拆分、领域边界、异常流程设计 | 需求说明、状态图、风险清单 |
| HTTP/API 测试 | REST/OpenAPI 设计、鉴权、错误模型、幂等 | 自己实现 API，而非只调用别人 API |
| SQL 与数据验证 | 数据建模、事务、索引、迁移、一致性 | ER 图、迁移脚本、集成测试 |
| pytest/自动化框架 | 模块化、依赖管理、配置、日志、CI | 单元/集成/契约测试与流水线 |
| Mock 和服务虚拟化 | 外部模型/工具隔离、故障注入、确定性测试 | 429、超时、断流、坏 JSON 用例 |
| 性能测试 | p95/p99、容量、Token 吞吐、成本和降级 | 负载模型与瓶颈证据 |
| 缺陷分析 | 调试、可观测性、根因与修复验证 | Trace、日志关联、故障复盘 |
| 安全测试意识 | Prompt Injection、工具越权、数据泄露治理 | 威胁模型、权限矩阵、攻击回归 |

### 2.2 不能自动迁移的能力

会测试一个系统，不代表已经会：

- 从模糊需求设计领域模型；
- 写出可维护的业务实现；
- 正确划分事务和并发边界；
- 设计 API 兼容性、数据库迁移和回滚；
- 对生产服务的稳定性、成本与安全长期负责；
- 评审代码并处理技术债；
- 在版本升级时理解依赖冲突和框架变更。

转岗时要补的是“建设系统并承担所有权”，不只是再学一组测试工具。

## 三、路线选择决策表

给每项打 0～2 分：

- 0：不会；
- 1：在指导下能做；
- 2：能独立完成并解释取舍。

| 问题 | Java 主线加分 | Python Agent 主线加分 |
|---|---:|---:|
| 能用 Java 独立完成 REST + 数据库服务 | +3 | 0 |
| 当前目标岗位明确写 Spring/Spring Boot | +3 | 0 |
| 能用 Python 维护模块化项目并写类型标注 | 0 | +2 |
| 能独立完成 FastAPI + SQLAlchemy + 鉴权 | 0 | +3 |
| 工作环境或目标行业以 Java 企业系统为主 | +2 | 0 |
| 目标岗位明确要求 LangGraph/FastAPI | 0 | +3 |
| 希望先成为通用后端开发，再进入 AI | +2 | 0 |
| 已经是成熟 Java 后端，只需补 Agent | 0 | +2 |
| 主要优势是 pytest、数据与 AI 评测 | +1 | +2 |

判断：

- Java 分高：走 Java/Spring AI 主线，Python 只用于评测脚本；
- Python 分高：走 FastAPI/LangGraph 主线，但普通后端门槛不能跳过；
- 都低：先完成共同基础和普通后端项目，再选；
- 都高：按目标岗位选择一门作为作品主语言，另一门只做一个对照服务。

不要用“哪门语言更热门”替代具体岗位、已有基础和可交付作品的判断。

## 四、转岗前的三道门

### 门一：普通开发能力

不使用 LLM，独立完成一个服务：

- 用户登录、RBAC 或最小权限；
- CRUD、分页、条件查询；
- 数据库迁移、事务、索引；
- 统一错误响应和输入校验；
- 单元、接口、真实数据库集成测试；
- Docker 启动与 CI；
- README 可让陌生人复现。

未通过时，暂停 Agent 框架学习。

### 门二：AI 应用能力

完成一个 RAG 服务：

- 文档导入、清洗、切分、Embedding、索引和版本；
- 检索、Metadata Filter、引用和无证据拒答；
- 结构化输出、流式响应、超时和限流；
- 模型/Embedding Provider 可替换；
- 30～50 条公开黄金问题；
- 检索和回答分层评测。

未通过时，不进入多 Agent。

### 门三：生产和质量能力

完成一个受控 Agent：

- 只读工具与写工具分离；
- 参数 Schema、鉴权、授权、幂等和审计；
- 每步超时、重试上限、预算与最大循环次数；
- Checkpoint、恢复和 Human in the Loop；
- Prompt Injection、越权与数据泄露用例；
- Trace、延迟、Token、成本、任务成功率；
- CI 中的确定性检查与 AI 回归阈值。

通过后，作品才从“聊天 Demo”升级为开发证据。

## 五、能力分级

### L0：测试自动化基础

- 会 Git 基本操作；
- 会 HTTP、JSON、SQL、Linux；
- 能维护 Python/Java 测试代码；
- 能写稳定断言和失败报告。

### L1：初级后端开发

- 能设计并实现小型 REST 服务；
- 能建模数据库、处理异常和鉴权；
- 能写单元、集成和接口测试；
- 能用 Docker 在新机器复现。

### L2：AI 应用开发

- 理解模型消息、Token、上下文、采样和结构化输出；
- 能做 RAG、Tool Calling 和基础评测；
- 能模拟模型故障并建立降级；
- 能保护密钥与敏感数据。

### L3：Agent 工程

- 能用明确状态、节点和边构建工作流；
- 能控制工具权限和副作用；
- 能处理中断、恢复、长任务和人工批准；
- 能建立任务、轨迹和安全评测。

### L4：生产化与技术影响

- 能设计 SLO、容量、可观测性、发布和回滚；
- 能比较技术方案而非只会一种框架；
- 能阅读官方变更和开源源码；
- 能用指标说明质量、成本和风险；
- 能评审他人代码和推动工程规范。

转初级开发至少达到 L1，并有部分 L2 作品；转成熟 Agent 开发通常要达到 L2～L3。

## 六、什么暂时不学

以下内容很吸引人，但不是第一份 AI 应用作品的前置：

- 从零预训练大模型；
- CUDA Kernel 和多机分布式训练；
- 五种 Agent 框架横向抄写；
- 五种向量数据库安装对比；
- 没有边界的自主循环和“群聊式多 Agent”；
- 高权限浏览器、终端和生产系统工具；
- 没有高质量标注数据就做微调；
- 只因招聘文案出现就全部加入必修的中间件。

原则是“每层一主一备”：主框架学到能解释和调试，备选只做一次迁移比较。

## 七、转岗风险与对策

| 风险 | 典型表现 | 对策 |
|---|---|---|
| 只看视频 | 收藏很多课程，没有可运行仓库 | 每周必须有 commit、测试和复盘 |
| 只会调用 API | 一个 Controller 转发模型响应 | 增加数据、权限、失败处理、评测和观测 |
| 过度依赖 AI 编程 | 代码能跑但无法解释 | 所有生成代码必须过测试、静态检查和口头讲解 |
| 框架追新 | 教程版本与依赖持续冲突 | 固定 BOM/lockfile，记录核对日期 |
| 把低代码当开发 | 只能拖拽 Dify/Coze | 导出配置后，用代码重建关键链路 |
| 作品含公司信息 | 为了“真实”使用工作资料 | 只用公开/合成数据，建立扫描清单 |
| 评测自欺 | 挑几个满意回答展示 | 版本化黄金集、失败样本和阈值 |
| 指标造假 | 简历写无来源的提升百分比 | 只写可复现实验环境与测量结果 |

## 八、开始前的自测任务

用 7 天完成，不使用任何公司资料：

1. 设计“虚构缺陷记录”数据模型；
2. 实现创建、查询、更新状态三个 API；
3. 写输入校验、错误码和数据库迁移；
4. 写至少 10 个自动化测试；
5. 用 Docker 启动；
6. 模拟一次数据库不可用并写故障记录；
7. 录制 5 分钟讲解：架构、测试、失败和改进。

结果判断：

- 能独立完成：进入 AI 应用阶段；
- 代码能跑但说不清：补语言、Spring/FastAPI 和数据库；
- 只能调用现成 API：先完成普通后端路线；
- 测试很强但实现薄弱：这正是最需要转换的能力，不要跳级。

## 九、目标声明模板

在仓库新建自己的学习记录时，用可验收目标：

```text
目标岗位：Java AI 应用开发 / Python Agent 开发 / AI 质量开发
主语言：
目标日期：
每周可投入时间：
已有证据：
最大缺口：
第一个普通后端项目：
第一个 RAG 项目：
毕业 Agent 项目：
明确不使用的数据：
```

不要写“精通 AI”“掌握所有框架”。写“能独立完成什么、如何证明、当前限制是什么”。
