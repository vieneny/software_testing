# 软件测试学习阶段总览

仓库按能力形成顺序组织，而不是按课程名称、工具名称或临时项目单独堆目录。每个阶段都必须包含：前置能力、具体学习任务、对应项目、交付物、主动失败练习和完成标准。

## 1. 主学习路径

| 阶段 | 学习入口 | 实战载体 | 必须交付 |
|---:|---|---|---|
| 0 | [基础与环境](./00-学习指南/README.md) | 本机环境自检 | 版本清单、命令实验、Git 提交 |
| 1 | [功能测试](./01-功能测试/README.md) | `labs/demo-shop` | 风险、模型、用例、缺陷、测试总结 |
| 2 | [接口测试与自动化](./02-接口测试/README.md) | `demo-shop` + `automation-practice` | API 契约、数据链、自动化回归 |
| 3 | [Web 与 App UI 自动化](./03-UI自动化/README.md) | Web 工程 + App 学习工程 | Page/Screen、Flow、证据与真机 smoke |
| 4 | [性能测试](./04-性能测试/README.md) | 本地 Demo Shop | 负载模型、阈值、资源证据和结论 |
| 5 | [质量工程](./05-质量工程/README.md) | CI + 综合工程 | 分层门禁、环境、数据、可观测性 |
| 6 | [AI 测试](./06-AI测试/README.md) | 合成评测数据集 | 评分器、切片、安全用例和回归报告 |

面试题是复习和检验工具，不是学习主线。遇到不会的题，回到对应阶段完成实验，再回离线题库复述。

## 2. 每阶段统一完成方式

```text
明确前置与目标
  → 学原理和边界
  → 跑最小成功
  → 完成阶段项目
  → 主动制造失败
  → 收集证据并定位
  → 对照清单验收
  → 写复盘后进入下一阶段
```

只阅读文档、只运行别人写好的代码或只得到绿色报告，都不算完成。至少要能解释关键判断、修改一次实现、制造一次有效失败并独立定位。

## 3. 新课程和新项目如何进入仓库

后续收到新的课程、代码或项目时统一执行：

1. 盘点它覆盖的能力、版本、练习和缺口；
2. 映射到现有学习阶段，不以课程名新建平行主线；
3. 将可迁移知识重写进阶段章节；
4. 将有价值代码重构进该阶段唯一配套工程；
5. 用公开或合成对象补齐未讲到的测试设计、失败路径和工程化；
6. 迁移完成后删除旧重复项目和失效导航；
7. 更新阶段验收、全局链接和 CI；
8. 面试题只做能力映射，不因项目整理自动改题或答案。

## 4. 三类内容的边界

| 类型 | 位置 | 职责 |
|---|---|---|
| 学习阶段 | `docs/00` 至 `docs/10` | 原理、任务、项目入口、产物、验收 |
| 实战工程 | `labs/` | 可运行代码、合成数据、自动检查 |
| 面试题库 | `docs/08` + `apps/interview-bank/offline` | 离线检索、回答训练和复盘 |

一个项目可以服务多个阶段，但每项能力只能有一个主文档入口。专题之间使用链接引用，不复制大段内容。
