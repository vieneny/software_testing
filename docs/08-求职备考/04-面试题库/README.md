# 软件测试面试题库

> 更新日期：2026-07-29
这个模块不是“背标准答案合集”。它把面试题映射到真实岗位能力，并要求你能说清：

1. 为什么这样判断；
2. 如何在项目中落地；
3. 怎样收集证据；
4. 方案有什么边界与取舍；
5. 发生异常后如何定位和改进。

当前版本包含 **10 个专题、172 道原有核心详解题 + 24 道 2026 公开面经重构题 + 52 道补充评审题 + 62 道小林 Coding 测试/测开资料去重重构题，共 310 道可检索详解题**，另配分层模拟面试、统一评分表、公开来源与岗位能力映射。AI 专题已结合 2026-07 BOSS 公开岗位样本、牛客近期面经、小红书近期题型观察、ISTQB CT-AI v2.0 与 OWASP AI Testing Guide 更新。

除了 Markdown，还提供一个可持续扩展的 [FastAPI + Vue 面试题库网站](../../../apps/interview-bank/README.md)：支持筛选、详细答案、收藏、掌握度、错题笔记、固定随机种子的模拟面试和本地持久化。

## 二、网站学习方式

从仓库根目录执行：

```bash
bash apps/interview-bank/scripts/setup.sh
bash apps/interview-bank/scripts/start.sh
```

浏览器打开 `http://127.0.0.1:8000`。所有运行入口、工程目录和脚本使用英文路径；学习文档继续使用中文见名知意。

网站中的学习记录保存在本机 SQLite，不会上传到网络。首版只适合个人本地使用，没有生产级账号与权限系统。

## 三、一道题应该怎样回答

推荐使用“结论—依据—行动—证据—边界”五段式。

```text
结论：先用一两句话正面回答，不绕圈。
依据：解释原理、风险或判断标准。
行动：给出可以执行的步骤、工具和优先级。
证据：说明日志、指标、测试结果或验收标准。
边界：指出例外、成本、残余风险和需要确认的信息。
```

例如，“时间只剩一天怎么测试”不能只回答“加班、优先测核心功能”。更完整的回答应包括：

- 先确认变更、用户影响、依赖和不可接受损失；
- 按风险分层，保留核心路径、数据一致性、权限与回滚验证；
- 并行开展静态评审、接口检查和少量端到端验证；
- 明确未测范围、阻断缺陷、监控与回滚条件；
- 由有决策权的人接受残余风险，而不是测试人员口头承诺“没有问题”。

## 四、不同层级的答题深度

| 层级 | 合格信号 | 典型失分 |
|---|---|---|
| 初级 | 概念正确，能给出正常/边界/异常用例和清晰缺陷证据 | 只背定义，不会用于具体场景 |
| 中级 | 能按风险选策略，处理数据、环境、依赖和失败定位 | 只谈工具，不谈断言与维护成本 |
| 高级/测试开发 | 能设计质量反馈系统，说明门禁、可观测性、成本和组织协作 | 用覆盖率或用例数代替质量结论 |
| AI 测试专项 | 能拆分模型与系统风险，建立可复现评测并校准不确定性 | 把单次模型输出或单个总分当真值 |

## 五、推荐使用方式

### 第一轮：建立概念

按学习路线阅读对应教程，再口头回答每题。答不上来时先回教程，不急着背答案。

### 第二轮：脱稿表达

每题限制 2～3 分钟。先说结论，再画流程或列证据。录音后检查是否出现大量工具名却没有判断标准。

### 第三轮：追问与实操

让同伴从“为什么、失败怎么办、如何证明、替代方案是什么”四个方向追问。自动化、SQL、Linux、性能和 AI 评测题应配合本仓库实验实际运行。

### 第四轮：岗位定制

从目标 JD 抽取“职责、对象、技术、交付物、协作”五类关键词，只选择相关题目重点练习。不要因为一份 JD 没写某项基础能力，就跳过 HTTP、SQL、Linux、测试设计和缺陷定位。

## 六、内容可信度与更新规则

- 招聘链接只代表公开岗位样本，不代表市场占比；
- 工具行为以官方文档和可复现实验为准；
- 社区题库用于发现候选题，不能作为事实的唯一依据；
- 涉及版本、弃用、法规或安全清单时必须标注核对日期；
- 答案要说明条件，避免“永远、一定、100% 覆盖”等绝对表述；
- 每季度抽查招聘样本，每半年复核官方链接和工具主版本。

## 七、真实性原则

项目题只能讲自己真正做过或明确标记为练习的内容。没有商业项目经验时，可以直接说：

> “下面是我在本仓库虚构的 Demo Shop 实战中完成的练习，我会区分练习结论和生产经验。”

这比虚构公司、用户量、缺陷数量或技术架构更专业。
