# 全流程模拟真实面试脚本

> 更新日期：2026-07-29
>
> 使用方式：独自练习时让网站随机出题；两人练习时，一人只看“面试官脚本”，另一人只看题目。
>
> 真实性要求：本脚本所有项目均为仓库内合成练习。回答时必须主动区分“我实际完成的练习”和“假设在生产环境的方案”。

## 一、完整面试不是随机问十道题

一场真实面试通常会形成连续证据链：

```text
自我介绍
  → 项目深挖
  → 测试基础
  → 专项技术
  → 现场场景/编码
  → 故障排查
  → 行为协作
  → 候选人反问
  → 面后复盘
```

后一道题会检查前一道回答是否真实。例如你在项目介绍中说“做过接口自动化”，面试官可能继续问：

1. 为什么选这个接口？
2. 框架怎样分层？
3. 数据怎样隔离？
4. 断言为什么能发现业务错误？
5. 故意让它失败时报告里有什么？
6. 进入 CI 后怎样处理 flaky？

所以训练目标不是背出孤立答案，而是让“项目—原理—代码—证据—边界”保持一致。

## 二、面试前准备包

每次模拟前准备以下内容：

- 一个目标岗位公开 JD；
- 一个自己实际运行过的仓库练习；
- 一张系统图；
- 一条端到端链路；
- 一个自己定位过的练习故障；
- 一段可现场讲解的代码；
- 三个准备反问面试官的问题。

禁止准备：

- 虚构公司、客户、团队人数、用户量和上线事故；
- 公司内网截图、需求、日志、接口、数据库结构和生产数据；
- 无法复现的“覆盖率 98%”“性能提升 10 倍”；
- 把团队成果全部说成个人完成。

## 三、90 秒自我介绍模板

```text
我目前重点学习软件测试与测试开发，基础方向包括功能、接口、SQL、Linux，
专项方向是 Python/pytest、Playwright/Appium 和 AI 系统测试。

我在这个公开学习仓库中实际完成了【练习名称】，它是从零构造的合成项目，
不是商业项目。我主要完成【自己实际做过的 2—3 项工作】。

其中最有代表性的一个问题是【故障或风险】，我通过【证据和实验】定位，
最终得到【可验证结果】。这个练习也暴露了【尚未解决的限制】。

我希望应聘【目标岗位】，因为岗位中的【两项能力】与我的训练方向匹配。
今天如果需要，我可以现场展示代码、失败报告和复现步骤。
```

评分点：

- 90—120 秒内完成；
- 目标岗位明确；
- 至少一个实际证据；
- 主动说明练习边界；
- 不堆工具名称，不编造商业经历。

## 四、初级软件测试全流程模拟（60 分钟）

### 阶段安排

| 阶段 | 时间 | 面试官目标 |
|---|---:|---|
| 自我介绍 | 5 分钟 | 判断表达、真实性和岗位目标 |
| 测试基础 | 10 分钟 | 判断是否真正理解测试与风险 |
| 功能/接口场景 | 20 分钟 | 判断分析完整性和测试预言 |
| SQL/Linux | 10 分钟 | 判断基本排查能力 |
| 项目与行为 | 10 分钟 | 判断证据与协作 |
| 反问 | 5 分钟 | 判断岗位理解和主动性 |

### 面试官脚本

#### 1. 自我介绍

主问题：

> 请用两分钟介绍自己，并选一个你真正做过的测试练习。

递进追问：

- 这个练习为什么值得测？
- 你个人具体做了什么？
- 给我看一个可以复现的结果。
- 如果它只是练习，与生产经验有什么差距？

#### 2. 测试基础

主问题：

> 软件测试的目标是什么？你如何判断“可以发布”？

合格信号：

- 目标是发现和沟通质量风险，不是证明没有缺陷；
- 发布需要约定范围、通过证据、已知问题和残余风险；
- 决策由有权限的角色作出，测试提供证据和建议。

追问：

> 冒烟通过但有两个低优先级缺陷，可以上线吗？

回答必须询问用户影响、可绕过性、监控和回滚，不能只看缺陷等级名称。

#### 3. 功能场景

主问题：

> 合成音频上传功能只允许 30 秒到 6 分钟，并支持断点续传。请设计测试。

面试官按顺序追问：

1. 精确边界数据是什么？
2. 扩展名正确但文件头错误怎么办？
3. 第 8 个分片重复或丢失怎么办？
4. 上传成功但转码失败是什么状态？
5. 弱网切换和后台恢复怎样测？
6. 你会自动化哪些，不自动化哪些？

高分回答应覆盖客户端、服务端、分片、合并、异步转码、播放、安全和可观察证据。

#### 4. 接口场景

主问题：

> 接口返回 HTTP 200，响应业务码是 `ORDER_NOT_FOUND`，用例算通过还是失败？

候选人必须先问“本用例预期是什么”。若是“不存在订单”负向用例，业务码符合契约可以通过；若是“查询已存在订单”用例，则业务失败。继续追问 Schema、权限和副作用断言。

#### 5. SQL/Linux

SQL：

```sql
-- 合成表
bug(id, owner, severity, status, created_at)
```

> 查询每位负责人的 P0/P1 未关闭缺陷数，并只显示数量大于 2 的负责人。

参考结构：

```sql
SELECT owner, COUNT(*) AS open_high_count
FROM bug
WHERE severity IN ('P0', 'P1')
  AND status <> 'closed'
GROUP BY owner
HAVING COUNT(*) > 2;
```

Linux：

> 发布后接口变慢，你拿到一台合成测试服务器，从哪里开始？

候选人应先确认影响与时间窗口，再用 `top`/`pidstat`、`ss`、磁盘、内存、日志和服务指标建立证据链；不能只背一串命令。

#### 6. 行为题

> 开发说问题无法复现，你怎么办？

追问：

- 没有 trace_id 怎么办？
- 影响很小还要推进吗？
- 开发仍不同意怎么办？

评分看事实、证据、假设、风险升级和沟通，不看是否“说服”了开发。

### 初级场通过线

- 六维评分至少 16/24；
- 没有严重概念错误；
- 场景题能覆盖边界、异常和权限；
- 接口题能区分 HTTP 与业务结果；
- 不编造项目经历。

## 五、自动化/测试开发全流程模拟（90 分钟）

### 阶段安排

| 阶段 | 时间 | 面试官目标 |
|---|---:|---|
| 自我介绍和项目 | 15 分钟 | 验证项目真实性与个人贡献 |
| 接口自动化 | 15 分钟 | 验证框架、数据和断言 |
| Web/App 自动化 | 15 分钟 | 验证定位、等待、跨平台与诊断 |
| 计算机基础 | 15 分钟 | 验证网络、SQL、并发和 Linux |
| 现场设计/编码 | 15 分钟 | 验证把思路变成可运行代码 |
| CI 与故障定位 | 10 分钟 | 验证工程化和恢复能力 |
| 反问 | 5 分钟 | 验证岗位判断 |

### 项目深挖

主问题：

> 画出你练习项目的系统图，并选择一条自动化链路。

连续追问：

1. 为什么在 API 层自动化，而不是全部放 UI？
2. 测试数据怎样创建与清理？
3. Token 过期怎样处理？
4. HTTP 200 业务失败怎样发现？
5. 并行运行会不会互相污染？
6. 失败报告包含哪些证据？
7. PR、每日和发布前各跑哪些？
8. 覆盖率的分母是什么？

### 接口现场题

合成接口：

```http
POST /api/orders
Idempotency-Key: demo-001
Content-Type: application/json

{"sku":"BOOK-01","quantity":2}
```

任务：

1. 写一个正常用例；
2. 写一个相同键重复请求用例；
3. 写一个相同键不同请求体用例；
4. 解释数据库或后续 API 怎样核对；
5. 故意写错断言并展示失败证据。

评分点：

- 用例名称表达业务；
- 客户端、数据、断言分层；
- 不把密钥写进仓库；
- 幂等不只看两个响应相等；
- 失败输出可定位；
- 不使用公司接口和数据。

### Web UI 现场题

> React 搜索页有动态 DOM、异步建议和 A/B 开关，怎样用 Playwright 实现？

面试官观察候选人是否：

- 优先用角色、标签和 test id；
- 等待业务状态而不是固定睡眠；
- 能用网络 Mock 构造空、错、慢响应；
- 理解 Mock 测试与真实端到端的边界；
- 会用 Trace 定位失败。

### App UI 追问

> Android/iOS 的客服 App 哪些自动化代码可以复用？

继续追问权限、键盘、通知、后台恢复、WebView 和真机矩阵。回答“Appium 一套代码全部复用”不合格。

### CI 故障题

> 1600 条回归运行 120 分钟，失败里 8% 是 flaky，你先做什么？

正确顺序是先定义分母和建立首次失败基线，再分类和治理。不能把所有失败自动重跑后显示绿色。

### 自动化/测开通过线

- 六维评分至少 18/24；
- 能写出可运行的最小代码；
- 至少能独立定位一次故意失败；
- 能解释框架边界、数据隔离与 CI 分层；
- UI 与 API 的职责分配合理。

## 六、AI 测试全流程模拟（90 分钟）

### 阶段安排

| 阶段 | 时间 | 面试官目标 |
|---|---:|---|
| AI 项目与传统基础 | 15 分钟 | 防止只会模型名词 |
| 评测集与指标 | 20 分钟 | 验证数据、统计与人工校准 |
| RAG/Agent 场景 | 20 分钟 | 验证分层定位和副作用控制 |
| 安全、隐私、性能 | 15 分钟 | 验证上线边界 |
| 现场评测设计 | 15 分钟 | 验证可执行方案 |
| 反问 | 5 分钟 | 验证方向理解 |

### 第一段：系统边界

主问题：

> AI 系统与传统确定性接口的测试预言有什么不同？哪些断言仍然可以确定？

合格答案应同时说出：

- Schema、权限、工具参数、数据状态等仍可确定性断言；
- 开放文本需要任务量表、统计重复、裁判与人工抽检；
- 质量、安全、延迟和成本需要联合评估；
- 不能用“模型有随机性”解释所有失败。

### 第二段：黄金评测集

> 为合成客服系统设计 400 条评测集。

面试官追问：

1. 普通、长尾、安全、隐私和多轮怎样分层？
2. 样本从哪里来？
3. 开放答案怎样标注？
4. 两位标注者不同意怎么办？
5. 怎样防止 Prompt 调优污染最终集？
6. 线上坏例怎样进入回归？

高分回答必须明确样本来源、适用范围和数据治理方式。

### 第三段：RAG 错答

题目：

> 正确知识写“7 天”，系统回答“30 天”，如何定位？

要求候选人画出：

```text
语料版本 → query/改写 → 召回 → 重排 → 上下文 → 生成 → 引用
```

并设计两个反事实实验，分别隔离检索和生成问题。

### 第四段：Agent 副作用

题目：

> 退款工具调用超时，Agent 是否应该重试？

候选人必须识别“执行结果未知”，先查询原调用或业务状态；使用稳定幂等键；超限进入人工对账；检查权限、金额、调用轨迹和审计。只回答“指数退避重试三次”不合格。

### 第五段：AI 安全

题目：

> RAG 文档要求 Agent 忽略规则并导出全部客户数据，怎样测试和防护？

高分回答：

- 外部内容是不可信数据；
- Prompt 不是最终权限边界；
- 工具网关做身份、最小权限、参数和输出校验；
- 测直接、间接、混淆、跨语言、多轮与工具结果注入；
- 验证完整轨迹，不只看最终拒绝文本；
- 全部在合成账号和隔离工具中完成。

### 第六段：统计门禁

> v2 得分 82.1，v1 得分 81.4，能宣布提升吗？

合格答案应要求固定变量、配对重复、方差/置信区间、实际影响、切片和人工复核。若安全切片下降，总体平均提高也不能抵消。

### AI 测试通过线

- 六维评分至少 18/24；
- 传统接口、数据、性能和安全基础不能明显缺失；
- 能区分模型、检索、编排和工具层；
- 能设计评测集、重复实验和人工校准；
- 不把敏感数据发送给公共模型。

## 七、面试官通用追问树

对每个回答最多选择三层，避免把模拟变成背题：

1. **定义层**：你说的概念是什么？
2. **条件层**：成立条件和例外是什么？
3. **行动层**：第一步具体做什么？
4. **数据层**：数据如何构造和隔离？
5. **证据层**：怎样证明成功或失败？
6. **故障层**：超时、并发、重试或部分失败怎么办？
7. **取舍层**：为什么不用另一种方案？
8. **真实性层**：这部分是你实际做过，还是方案设计？

如果回答者连续两轮只能重复工具名，应标为“知道名词，尚未形成可执行能力”。

## 八、反问面试官

优先选择能判断岗位真实工作的反问：

- 这个岗位当前最重要的质量风险是什么？
- 团队如何划分功能测试、自动化、测试开发和研发自测责任？
- 当前从提交到获得可靠测试反馈需要多久？
- 自动化最主要的问题是覆盖不足、稳定性还是诊断成本？
- AI 测试岗位更偏数据评测、系统测试、平台开发还是安全？
- 新人前三个月的成功标准是什么？

不要在信息已公开时重复询问，也不要用反问套取公司内部资料。

## 九、面后复盘

每场结束立即记录：

```markdown
- 哪三题有结论、行动和证据？
- 哪三题只有名词？
- 哪个项目数字没有分母？
- 哪个回答把练习说得像真实经历？
- 哪个故障缺少复现或 Trace？
- 下一次只改哪两个高价值问题？
```

网站会保存模拟题单、自答、自评和复盘；Markdown 版也可使用[模拟面试与评分表](./11-模拟面试与评分表.md)中的六维量表。
