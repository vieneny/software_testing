# 题库逐题质量审校

> 审校批次：2026-07-29 至 2026-07-30
>
> 审校范围：10 个模块、310 道正式题，以及面试题库网站的答案展示、来源图片、筛选、笔记和键盘交互。
>
这次审校不是只做字数和格式检查。每道题都按“题目在问什么—答案是否正面回应—解释为什么成立—怎样在合成场景落地—证据是什么—边界在哪里”逐项复核，再用自动化门禁防止后续修改重新引入结构问题。

自动化可以检查字段、长度、来源、图片和代码围栏，但不能证明技术结论永远正确。因此，版本敏感内容仍需人工依据官方标准、工具文档和可复现实验复核。

## 三、答案表达标准

每道题优先使用下面的结构，不再堆成长段原文：

| 层级 | 要回答的问题 | 推荐表现形式 |
| --- | --- | --- |
| 结论 | 正面答案是什么 | 1～3 句结论 |
| 判断依据 | 为什么这样判断 | 短段落或对照表 |
| 落地步骤 | 实际怎样做 | 有顺序的编号列表 |
| 证据 | 怎样证明结果可信 | 指标、日志、Trace、数据库或报告清单 |
| 边界 | 哪些情况不能推出同样结论 | 条件、风险、成本和待确认项 |

复杂状态和跨系统链路优先使用“当前状态—事件—下一状态—副作用”表或编号流程。正式题库答案禁止嵌入 Markdown 图片；确需保留的来源图片只存在于 Git 忽略的本地快照中，并在网站内默认折叠，展开后也限制最大高度。

## 四、逐题自动化门禁

[逐题审计报告](../../../../apps/interview-bank/data/题库逐题质量审计.json)为每道题保存内容哈希、答案与解释有效字符数、检查项和状态。当前结果：

| 门禁项 | 结果 |
| --- | ---: |
| 题目总数 | 310 |
| 全部硬性检查通过 | 310 |
| 失败 | 0 |
| 需结合上下文人工确认的措辞 | 2 |

两条人工提示均已复核：

1. `core-01-01` 的“绝对没有缺陷”用于说明测试**不能证明**这一结论，不是质量承诺；
2. `supplemental-websocket-reconnect-order` 的“认为 WebSocket 永远不会重复或乱序”位于常见误区中，不是协议保证。

硬性检查包括：

- 必需字段、角色、标签、来源和日期完整；
- 答案有效字符不少于 120，解释有效字符不少于 60；
- 答案与解释不是同一段文字；
- 追问和误区均存在；
- 实操题、场景题、项目题和行为题具有合成练习场景；
- 代码围栏成对闭合；
- 正式答案没有 Markdown 图片；
- 来源 ID 能解析到登记记录；
- 同模块标题不重复。

模块末尾的版本说明、检查表和公开参考曾被误并入最后一题的“常见误区”。构建器现已增加附录边界，并有回归测试保证这些维护内容不再进入题目字段。

## 五、网站显示与交互验收

| 用户动作 | 优化后的行为 | 自动化证据 |
| --- | --- | --- |
| 查看答案 | 表格、列表、引用、行内代码和代码块正确渲染 | Markdown 渲染与 XSS 测试 |
| 阅读长答案 | 主答案直接显示；解释默认展开；深化、追问、误区按层折叠 | 组件状态测试 |
| 查看来源图片 | 图片默认折叠，只加载清单登记的本地安全类型 | 本地资产白名单与失败占位测试 |
| 揭示答案 | 展开后焦点进入答案区，键盘用户能立即继续阅读 | `aria-controls` 与焦点逻辑 |
| 收藏或加入错题 | 使用明确文字按钮，不用含义不明的字符图标 | 按钮状态测试 |
| 跨页筛选收藏/错题 | 将本地标记 ID 交给 FastAPI 过滤，再由服务端正确分页 | 跨页、取消补位和尾页回退测试 |
| 连续修改学习状态 | 本地乐观更新；按题目修订序号丢弃迟到的旧同步响应 | 进度竞态回归测试 |
| 保存笔记 | 去除首尾空白并显示“已保存/已清除”反馈 | 事件与 `aria-live` 测试 |
| 打开来源弹窗 | Esc 关闭、Tab 焦点循环、关闭后返回触发按钮、背景锁定，迟到请求不覆盖新状态 | 弹窗组件与请求竞态测试 |

来源正文和题库答案都经过 `markdown-it` 禁用原始 HTML/自动链接，再经过 DOMPurify 白名单净化。原始网址只作为可复制文本，正文中的外链不会变成可点击跳转。

本轮已有组件、DOM、键盘和构建证据，但当前工具环境没有完成真实浏览器下的多视口截图对比，因此不把结果描述为完整视觉验收或 WCAG 合规认证。后续人工视觉验收至少应覆盖 320、375、768 和 1440 像素宽度，以及长表格、长代码、来源大图和 200% 缩放。

## 六、复核流水线

| 顺序 | 输入 | 处理 | 输出 |
| ---: | --- | --- | --- |
| 1 | 中文核心模块、评审 JSON、历史覆盖清单 | 检查结构与来源 | 可进入审校的真源 |
| 2 | 题目、答案、解释、追问、误区、场景 | 人工逐题技术与表达审校 | 修订后的内容真源 |

从仓库根目录执行完整检查：

```bash
bash apps/interview-bank/scripts/check.sh
```

只更新逐题报告：

```bash
apps/interview-bank/backend/.venv/bin/python \
  apps/interview-bank/scripts/audit_question_quality.py --write-report
```

## 七、维护要求

1. 先修改 10 个中文模块或对应评审 JSON，不直接编辑 `questions.json`；
2. 新增或修改事实前，先核对标准、官方文档或一手研究；
3. 社区面经只用于发现题型，不作为事实唯一依据；
4. 图片只作本地来源证据，正式答案优先表格、编号流程和代码；
5. 合成场景必须明确是练习，不能包装成真实商业经历；
6. 每次修改后重新构建题库、生成逐题报告并运行完整检查；
7. 版本、弃用、安全清单和 AI 工具至少每季度复核一次。
