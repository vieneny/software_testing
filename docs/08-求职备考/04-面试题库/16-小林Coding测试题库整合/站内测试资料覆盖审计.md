# 站内测试资料覆盖审计

## 一、审计口径

本次统计的是 2026-07-29 当前公开页面：

- `source_chars`：浏览器读取到的页面正文字符数，用于证明页面已实际检查，不代表有效知识数量；
- `declared_question_count`：站内导航或专题页标注的题数；
- `observed_question_count`：当前页面可见问题标题的实际识别数；
- `question_ids`：本页面主题最终映射到的现行题目，不等于复制的原题；
- `coverage_mode`：区分直接题库逐题盘点、学习导航核对和测开支撑主题映射。

标称数与可见数不一致时，两种数据都保留，不用较大的数字宣传覆盖率。

### 为什么 Git 页面是 24 对 23

页面结构中有一个“推荐学习”二级标题，它是导航提示而不是面试问题。自动把所有二级标题计为题目会虚增一题，因此实际题数记为 23。

## 五、支撑专题不是全部导入

测试开发需要理解被测系统，但不等于把后端开发题库完整复制一份。采用以下边界：

- Java、集合、并发、JVM：保留会直接影响测试代码、并行执行、稳定性和排障的主题；
- Spring、MySQL、Redis、消息队列：保留接口、事务、数据一致性、故障注入和性能分析主题；
- 操作系统、网络、Linux：保留可形成证据链的排障能力；
- 系统设计与分布式：从测试策略、容量、恢复、幂等和可观测性角度学习；
- 算法：作为测开编码练习，不用算法题数量扩充软件测试题库；
- Git 与 Docker：服务于自动化代码协作和可重复环境。

## 六、机器可读快照

完整映射保存在：

```text
apps/interview-bank/data/xiaolincoding-coverage.json
```

快照具有以下可验证约束：

- 21 个 `document_id` 唯一；
- 21 个 URL 唯一；
- 所有页面至少映射一道现行题；
- 所有题目 ID 必须存在于生成后的 `questions.json`；
- 页面正文字符合计必须为 672,610；
- 标称题量合计必须为 1,143；
- 实际题量合计必须为 1,111；
- 构建检查和离线测试会阻止未知题目 ID 或重复 URL 进入聚合题库。

## 七、统计限制

- 网页更新后字符数和问题标题数量可能变化；
- “问题标题”按当前 HTML 标题结构识别，不能代表每题内容深度；
- 站内标称题量可能包含导航项、隐藏项或历史版本，本仓库不推测差异原因；
- 本次统计不能用于宣称市场占有率、招聘频率或题目命中率；
- 题目是否进入正式题库由能力缺口和答案质量决定，而不是出现次数。
