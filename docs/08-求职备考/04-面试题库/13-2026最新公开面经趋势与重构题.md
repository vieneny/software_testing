# 2026 最新公开面经趋势与重构题

> 调研日期：2026-07-29
>
> 适用方向：软件测试、接口/自动化测试、测试开发、性能测试、AI 测试
>
## 一、先理解这次更新做了什么

本轮没有把“小红书面试题”“牛客面经”整页搬进仓库，而是采用四步流程：

1. 从 2026 年 6—7 月公开面经中找反复出现的能力；
2. 把公司名、候选人经历和偶然措辞去掉，改写为通用问题；
3. 用 RFC、工具官方文档、ISTQB、OWASP 等资料核对技术结论；
4. 为每题补上合成场景、数据、详细答案、证据、追问、误区和可运行练习。

证据等级如下：

| 等级 | 用途 | 例子 |
|---|---|---|
| A：标准/官方指南 | 核对技术原理、安全边界与版本 | RFC 9110、ISTQB CT-AI v2.0、OWASP |
| B：工具官方文档 | 核对具体工具行为 | Playwright、Appium |
| C：公开学习导航 | 检查知识结构是否缺项 | 小林 Coding |
| D：社区面经趋势 | 发现“最近怎样问”，不作为答案依据 | 牛客、小红书 |

小红书本轮通过用户已登录的浏览器正常查看，未遇到验证码。仓库只记录搜索词、观察日期和归纳后的题型，不保存作者、用户主页、评论、图片或带 `xsec_token` 的临时链接。

## 二、2026 年最明显的面试变化

### 1. AI 测试已从“会不会用 AI”升级为独立能力域

近期问题已经深入到：

- AI 生成用例的可用率、风险召回和返工成本；
- 黄金评测集、标签一致性、数据泄漏和切片；
- RAG 的检索、上下文、生成和引用分层定位；
- 非确定性回归、重复试验、置信区间和人工校准；
- Agent 的工具权限、幂等、超时恢复、死循环和审计；
- Prompt Injection、隐私、模型升级、延迟和成本。

因此，只回答“我会调用模型 API”或“用 AI 写脚本”已经不够。

### 2. 自动化从“会工具”升级为工程闭环

面试官更关注：

- 新接口怎样从需求评审进入 CI；
- Token 刷新、接口关联、数据隔离和副作用断言；
- Playwright 动态等待、Trace 与定位失败诊断；
- Android/iOS 复用边界、WebView、真机矩阵；
- flaky 的统计口径、责任、隔离与退出标准；
- AI 生成代码怎样审查、隔离执行和证明提效。

### 3. 场景题必须讲不变量、数据和证据

“列几个正常、异常、边界用例”只能算开头。高质量回答还应包括：

```text
澄清规则
  → 找到不可接受的损失和业务不变量
  → 建模状态、角色、并发和依赖
  → 构造合成数据与故障
  → 定义接口/数据库/日志/指标证据
  → 选择自动化层级
  → 给出准出、监控、回滚和残余风险
```

### 4. 项目数字会被反向验证

当你说“覆盖率 98%”“节省 80% 时间”“支持 5 万并发”时，面试官通常会继续问：

- 分母是什么？
- 数据从哪里来？
- 时间窗口多长？
- 首次失败和重跑如何统计？
- 剩余部分为什么没覆盖？
- 这个数字带来了什么真实决策？

没有证据时，正确做法是给出测量计划，而不是补一个好看的数字。

## 四、四道代表题应该怎样答

以下不是完整题库的重复拷贝，而是展示统一答题结构。完整追问和评分点可在离线题库中按关键词或稳定 ID 检索。

### 1. HTTP 200 但业务失败

先分四层断言：

1. 协议层：HTTP 状态、Content-Type、超时；
2. 契约层：字段是否存在、类型是否正确；
3. 业务层：业务码、权限、状态和返回内容；
4. 副作用层：数据库、消息或后续查询是否符合预期。

失败报告必须提供 `trace_id`、脱敏请求上下文和各层实际值。`200` 只表示服务器成功返回响应，不能推出业务成功。

### 2. Android/iOS 自动化复用

业务流程、数据工厂、API 准备和领域断言可以复用；权限弹窗、通知、手势、键盘、控件树与 WebView 驱动属于平台适配。页面对象表达“打开会话、发送回复”的意图，Android/iOS 分别实现定位与系统动作。不要为了复用率在用例里堆满 `if platform`。

### 3. RAG 回答错误

依次确认：

1. 正确知识是否存在且版本正确；
2. 是否被召回到 top-k；
3. 是否经过重排并进入最终上下文；
4. 模型是否依据上下文回答；
5. 引用是否真正支持结论。

把正确证据直接交给模型可以隔离生成问题；把检索结果交给固定生成器可以隔离检索问题。最终要分别报告检索、上下文、事实性、引用和端到端成功。

### 4. Agent 工具超时

“超时”不等于“没有执行”。对退款等副作用操作，Agent 必须使用稳定幂等键；响应丢失后先查询原调用或业务状态，不能换键再次执行。需要验证调用轨迹、参数、权限、业务流水、审计和最终回复，并把“结果未知”作为真实状态处理。

## 五、练习顺序

### 计算机专业小白

1. 先答状态机、文件上传和 HTTP 200；
2. 在 Demo Shop 实际发送接口并观察业务码；
3. 学会用 SQL 或后续查询验证副作用；
4. 再进入 Playwright、Appium 和 pytest。

### 有测试经验、准备拔高

1. 从覆盖率真实性、半天发布和不可复现缺陷开始；
2. 把每个回答补上 Trace、指标、数据库或流水线证据；
3. 完成幂等并发、P99 和 flaky 治理；
4. 最后学习 AI 评测与 Agent 安全。

### AI 测试方向

1. 先掌握传统接口、数据、性能和安全；
2. 构建合成黄金集；
3. 分层评测 RAG；
4. 给 Agent 工具增加权限、幂等、恢复和审计；
5. 用统计门禁与人工复核完成版本回归。
