# 岗位能力地图：从招聘要求到可证明能力

本章把公开招聘描述翻译成学习任务和作品证据。当前中国招聘底座来自 2026-07-27 的 BOSS 直聘公开岗位快照，样本、关键词、去重和限制详见[软件测试与人工智能测试招聘需求调研](../00-学习指南/04-软件测试与人工智能测试招聘需求调研.md)；技术选型方法见[市场需求与技术选型](../00-学习指南/02-市场需求与技术选型.md)。

岗位名称在不同公司差异很大。“测试工程师”可能偏业务，也可能要求平台开发；不要只按标题判断，要看实际职责、系统类型、技术栈和成功标准。

## 招聘方真正需要什么

一条常见招聘要求可以拆成四层：

```text
关键词：pytest / Playwright / JMeter / Docker
    ↓
任务：构建回归、验证关键旅程、评估容量、复现环境
    ↓
风险：回归遗漏、脚本脆弱、性能未知、环境不一致
    ↓
证据：可运行项目、失败诊断、报告、取舍和改进结果
```

只在简历列工具属于第一层。面试中有区分度的是：你解决了什么风险、为什么选这种方法、如何验证、失败怎么定位、结果怎样影响决策。

## 五类求职方向

### 软件测试 / 功能测试

核心任务：需求评审、风险识别、用例设计、探索式测试、缺陷闭环、回归和发布判断。

入门证据：

- 对虚构需求写出范围、风险、判定表、状态图和探索 charter；
- 缺陷报告可复现，包含环境、期望、实际、证据和影响；
- 会用浏览器开发者工具、Postman/curl、SQL、Linux 日志定位；
- 能解释未覆盖内容和残余风险。

不要把功能测试描述为“点点点”。优秀功能测试强调业务模型、系统交互、异常恢复和用户影响。

### 自动化测试

核心任务：把稳定、重复、高价值的检查变成可靠反馈，覆盖 API、UI、数据、报告和 CI。

入门证据：

- Python + pytest + Requests 的接口项目；
- Playwright 的少量关键旅程，无固定 sleep；
- fixture、参数化、配置、数据隔离、日志脱敏和失败 trace；
- smoke / regression 分层并在 CI 用退出码门禁。

招聘描述中的“搭建框架”不等于写很多 Base 类。优先证明项目清晰、可复现、稳定、可诊断和易扩展。

### 测试开发 / SDET / 质量工程

核心任务：开发测试基础设施、提升可测性、治理环境数据、缩短反馈、支持多个团队。

进阶证据：

- OpenAPI 契约、属性测试、WireMock/Pact/Testcontainers 实验；
- CI 分层、并行、缓存、制品、质量门禁和 flaky 治理；
- Docker、数据库、缓存、消息队列和微服务的测试策略；
- 可观测性数据将失败定位从小时降到分钟的实验；
- 对平台投入产出、使用者体验和维护成本有指标。

高级岗位还要求测试策略、架构取舍、跨团队推动和指导能力，不只是更复杂的代码。

### 性能 / 稳定性测试

核心任务：从业务量和 SLO 建立负载模型，结合服务端指标找出容量和可靠性风险。

进阶证据：

- 基线、阶梯负载、压力、峰值和耐久测试的适用条件；
- k6 主线脚本与 JMeter 存量能力，必要时 Locust；
- p95/p99、错误率、吞吐、饱和度和依赖指标的时间线；
- 开放/封闭模型、预热、think time、数据、关联和压测机瓶颈；
- 结论包含环境限制、可证伪假设和下一轮实验。

只会设置线程数、看平均响应时间，不能证明性能工程能力。

### AI 测试 / AI 质量工程

“AI 质量工程”是岗位族，不是一份统一职责。BOSS 当前样本至少分成：

| 路线 | 核心任务 | 作品证据 |
|---|---|---|
| 普通测试 + AI 提效 | 生成候选用例/数据/脚本和失败假设，并通过人工与执行验收 | AI 草稿与人工修改差异、采纳/返工、可运行回归 |
| AI 应用测试 | 评测 LLM/RAG/多模态产品的功能、效果、安全、延迟和成本 | 模型 Mock、版本化评测集、分层报告和 CI 门禁 |
| 大模型/多模态评测 | 建设数据、指标、Benchmark、标注和模型比较实验 | 黄金集、评审一致性、裁判校准、配对比较和切片 |
| Agent 测试 | 验证规划、状态、工具、权限、终态、副作用和恢复 | 可重置 Mock、轨迹断言、越权与幂等回归 |
| 测试开发/评测平台 | 开发评测任务、执行、结果、版本、观测和质量平台 | 异步评测服务、结果库、Trace、门禁和审计 |

进阶证据：

- 版本化合成评测集和明确 rubric；
- 确定性 oracle、模型裁判与人工校准的组合；
- RAG 检索/生成/端到端分层指标；
- Agent 工具轨迹、数据库终态、权限、副作用和多次运行可靠性；
- OWASP 提示注入、泄露、过度代理和 Agent 风险回归；
- 生产 Trace 脱敏回流到离线集的设计。

“会写提示词”不是 AI 测试岗位的充分条件。测试基础、统计思维、API、自动化、安全和可观测性仍是底座。

具体学习路线见[人工智能测试岗位能力与实战路线](../06-AI测试/04-人工智能测试岗位能力与实战路线.md)。

## 能力分层

年限只作招聘筛选参考，能力应以能否独立交付判断。

| 能力域 | 入门：独立完成明确任务 | 中级：负责模块/系统 | 高级：影响组织质量 |
|---|---|---|---|
| 需求与风险 | 从规则设计正反用例 | 主导测试分析、范围和优先级 | 建立风险策略并推动可测性 |
| 功能与探索 | 执行并清晰报告 | 用模型和 charter 发现未知风险 | 指导复杂系统测试与退出决策 |
| API / 数据 | HTTP、Postman、SQL 基础 | 契约、鉴权、幂等、并发、一致性 | 跨服务契约、数据与环境治理 |
| 编程 | 修改 Python 脚本 | 设计可维护客户端/fixture/工具 | 平台、库、架构、代码评审与演进 |
| UI 自动化 | 稳定定位和等待 | 数据隔离、并行、trace、跨浏览器 | 分层策略、基础设施和 flaky 治理 |
| 性能 | 运行脚本并解释基本指标 | 建模、监控、瓶颈实验 | 容量规划、稳定性策略和跨团队改进 |
| CI/CD | 读懂并修改流水线 | 分层门禁、制品和失败分诊 | 质量平台、指标、成本与开发者体验 |
| 云原生 | 会用 Docker 和看日志 | 测试 K8s 中的服务和依赖 | 分布式可靠性、可观测性和故障策略 |
| AI 测试 | 构造数据集和确定性检查 | RAG/Agent 评测、安全和 CI | 评测平台、治理、在线闭环与风险决策 |
| 沟通 | 报告事实和复现 | 协调范围、风险与发布 | 跨团队影响、指标、复盘和人才培养 |

## 从 JD 到学习计划

任选 20 个当前 BOSS 目标岗位做公开样本，不把原始职位全文复制进仓库。AI 方向要同时搜索 AI 测试、AI 测试开发、大模型评测和 Agent 测试，去重并排除只因标题含 AI 的硬件/标注噪声。建立本地个人表格：

| 字段 | 示例 |
|---|---|
| 岗位方向 / 层级 / 地区 / 行业 | 自动化测试 / 中级 / 目标城市 / SaaS |
| 主要职责 | API 回归、Web 自动化、CI、质量分析 |
| 必需能力 | Python、pytest、HTTP、SQL、Linux、Git |
| 加分能力 | Playwright、Docker、性能、AI |
| 作品证据 | demo-shop API + UI + CI + 失败复盘 |
| 当前差距 | Docker 与服务虚拟化不足 |
| 4 周动作 | 两个 Testcontainers 实验 + 一次 mock interview |

统计只用于本次个人定向样本和自己决策：

1. 合并同义词，如 requests/HTTP client 归入接口自动化；
2. 区分“必需”和“加分”；
3. 区分稳定能力与某公司特定工具；
4. 记录采集时间、关键词、城市、原始条数、去重后条数和排除原因；
5. 月薪、日薪和不同“几薪”不混算；
6. 选择覆盖多个目标岗位的主线；
7. AI 岗每月、普通测试岗每季度重新抽样，职位变化时调整选修，不频繁推翻底层主线。

个人求职表可能包含公司名、联系人和应聘记录，不应提交到公开仓库。

## 招聘关键词的正确学习深度

| 关键词 | 只会名词 | 可入职的证据 | 拔高证据 |
|---|---|---|---|
| pytest | 会运行 | fixture、参数化、marker、报告、清理 | 插件边界、并行、flaky 与 CI 设计 |
| Postman | 会点 Send | 环境、脚本、链式请求、数据驱动 | Collection 版本、Postman CLI 门禁与密钥治理 |
| Playwright | 会录制 | 稳定定位、自动等待、隔离和 trace | 网络控制、并行、兼容矩阵与分层取舍 |
| Selenium | 会写 XPath | 显式等待、Manager、Page Object | Grid、BiDi、存量迁移与稳定性治理 |
| JMeter | 会设线程 | 关联、参数化、CLI、指标与报告 | 模型、分布式、监控与瓶颈假设 |
| Docker | 会启动容器 | 可复现依赖、日志、网络和健康检查 | Testcontainers、CI 环境与安全边界 |
| Kubernetes | 会背对象 | 部署测试服务、查看事件/日志/资源 | 故障、弹性、可观测性和可靠性策略 |
| AI 测试 | 会调用模型 | 数据集、评分、切片、回归和安全 | RAG/Agent、裁判校准、在线评估与治理 |

## 每个层级的最小作品集

### 小白 / 校招 / 转行

1. `demo-shop` 功能测试分析；
2. pytest API 自动化；
3. 两条 Playwright 关键旅程；
4. CI 运行截图以外，还要有公开配置和失败修复记录；
5. 一页项目复盘。

### 1～3 年能力目标

在上述基础上增加：

- OpenAPI/契约或 Mock 实验；
- 性能负载模型和报告；
- Docker 可复现环境；
- 一次 flaky 治理或失败分诊案例；
- 目标岗位所需的移动端或行业专项。

### 高级 / 测试开发 / AI 方向

增加：

- 分层 CI 设计和质量指标；
- 分布式依赖与可观测性诊断；
- RAG/Agent 评测及安全红队；
- 平台/框架的使用者视角、成本与迁移方案；
- 一次公开开源贡献或高质量技术文章。
