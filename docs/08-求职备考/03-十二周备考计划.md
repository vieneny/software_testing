# 十二周求职备考计划

适合已经具备测试基础、希望集中准备软件测试/自动化测试岗位的人。完全小白先走 [20 周路线](../00-学习指南/01-学习路线.md)，不要为了赶时间跳过 HTTP、SQL、Git、Linux 和功能测试设计。

每周建议 12～15 小时，产出优先于刷题数量。

## 第 0 周：确定目标

- 选择一个主方向：软件测试、自动化、测试开发、性能或 AI 测试；
- 按[最新招聘调研](../00-学习指南/04-软件测试与人工智能测试招聘需求调研.md)从 BOSS 当前公开职位抽取 20 个去重样本，记录采集时间、关键词、城市、经验、学历、职责和排除原因；
- AI 方向不能只搜“AI 测试”，至少覆盖 AI 测试开发、大模型评测和 Agent 测试，并区分产品测试、模型评测与平台开发；
- 对照 [岗位能力地图](01-岗位能力地图.md) 自评；
- 选 3 个主要差距，不同时补 10 个工具；
- 创建个人求职表，但不要提交含公司/联系人信息的文件。

交付：目标岗位画像、差距清单、12 周可验收目标。

## 第 1 周：功能与风险

- 重做 `demo-shop` 下单风险分析；
- 用等价类、边界值、判定表和状态迁移设计用例；
- 完成两个探索式测试 session；
- 写一份高质量缺陷报告和测试总结。

面试练习：测试流程、用例设计、缺陷等级、回归范围、如何判断测试结束。

## 第 2 周：HTTP、SQL、Linux 与定位

- 用 curl 复现 GET/POST/header/body/鉴权的公开例子；
- 解释 DNS、TCP、TLS、HTTP 的定位层次；
- 完成查询、JOIN、聚合、重复检查和事务练习；
- 练习端口、进程、日志、磁盘、网络命令；
- 从一段合成日志写“证据—假设—验证”。

交付：一份排错手册，不包含真实工作日志。

## 第 3～4 周：API 与 pytest 主项目

- 完成 `demo-shop` API 正常、边界、异常、契约和幂等用例；
- 使用 Session、显式 timeout、fixture、参数化和 marker；
- 增加配置、数据工厂、清理和日志脱敏；
- 主动修改一个字段让测试失败，修复并记录；
- 把 smoke 接入 CI。

交付：可从零运行的接口自动化项目和两页设计说明。

## 第 5 周：Playwright

- 完成加载、下单、失败反馈两到三条关键旅程；
- 使用 role/label/test id 与 web-first assertion；
- 配置失败 trace；
- 解释为何其余组合留在 API 层；
- 读懂一个 Selenium 显式等待示例，准备存量项目问题。

交付：稳定运行三次的 UI smoke 和失败诊断。

## 第 6 周：性能与可观测性

- 从假设业务量推导场景比例；
- 用 k6 完成基线和阶梯负载；
- 用 JMeter CLI 重现一个等价小场景；
- 记录 p95、错误率、吞吐和服务资源；
- 写瓶颈假设、限制和下一轮实验。

交付：不是工具截图，而是带时间线和结论的 Markdown 报告。

## 第 7 周：CI、Docker 与工程化

- 分层本地、PR、nightly 和人工任务；
- 学会 Docker image/container/network/volume/healthcheck；
- 失败时仍上传诊断制品；
- 模拟 flaky，建立分类和处理流程；
- 检查最小权限、Secret 和日志脱敏。

交付：流水线图、可运行 YAML/命令和失败分诊手册。

## 第 8 周：专项选择

只选与目标岗位最相关的一条：

- 移动端：Appium 3 + UiAutomator2；
- 微服务：WireMock + Pact/Testcontainers；
- 性能：JMeter/k6 深入 + Prometheus/Grafana；
- Java 企业栈：Java + RestAssured/TestNG；
- 云原生：Docker/K8s 中的部署、日志、事件和资源测试。

交付：一个能主动失败的专题实验。

## 第 9 周：AI 测试与 AI 提效

- 先按[AI 测试岗位能力与实战路线](../06-AI测试/04-人工智能测试岗位能力与实战路线.md)选择一条职责线；
- 扩展本地合成评测集到 30 条；
- 设计确定性门禁和人工 rubric；
- 研究 RAG/Agent 分层与 OWASP 风险；
- 用 AI 对公开虚构需求生成用例草稿，测采纳率和误报；
- 全程不输入公司、本机工作或真实求职数据。

交付：AI 评测报告，以及“AI 帮了什么、错了什么、如何验证”的提效复盘。

## 第 10 周：作品与简历

- 按 [综合实战](../07-综合实战/README.md) 整理作品；
- README 先讲目标、风险、策略、证据和限制；
- 简历每条使用“对象+目标+行动+取舍+结果”；
- 删除无证据的“精通”和工具堆砌；
- 做一次敏感信息与许可证检查。

交付：一页简历、一个主项目、一个专题项目。

## 第 11 周：模拟面试

先阅读[面试题库](./04-面试题库/README.md)，再使用统一的[模拟面试与评分表](./04-面试题库/11-模拟面试与评分表.md)完成三次不同形式：

1. 45 分钟测试基础与项目追问；
2. 60 分钟 API/代码/SQL 实操；
3. 60 分钟系统质量或专项设计。

每次按六个维度 0～4 分：概念正确性、分析结构、实践落地、证据意识、风险与边界、沟通真实性。评分必须附回答证据和下一轮验收项，不能只记总分。

只修复重复出现的高影响弱项，不在最后一周新增整套技术栈。

## 第 12 周：投递与迭代

- 按目标岗位调整项目顺序和关键词，不编造经历；
- 每次面试后只记录可公开、通用的知识差距；
- 将问题分类为知识、项目证据、表达、算法/编码或岗位不匹配；
- 每周选择一个最高收益改进；
- AI 岗每月、普通测试岗每季度更新 BOSS 公开样本与项目链接。

求职公司、联系人、薪资和面试原题属于个人信息，只保存在私有工具中，不进入公开仓库。

## 每日最小节奏

```text
30 分钟：回忆和口述一个概念
60 分钟：编码或实验
30 分钟：主动失败与定位
20 分钟：把结果写成证据
10 分钟：决定明天最小任务
```

## 什么时候可以开始投递

不需要等“全部学完”。满足以下条件即可边投递边迭代：

- 能独立完成目标岗位的基础任务；
- 有一个可运行主项目和一次失败诊断；
- 能讲清风险、策略、结果和限制；
- 基础题不是只背定义；
- 简历真实，公开材料无公司数据；
- 对未掌握内容能诚实说明学习路径。

准备工作的终点不是题库清零，而是让能力证据与目标岗位形成可信匹配。
