# AI 测试：从确定性基线到持续评测

> 时效核对：2026-07-27。AI 工具、模型和安全分类变化很快；引用带日期的信息时，先打开本章末尾的官方链接复核。

AI 测试不是“问模型几个问题，看起来不错就上线”。它要把概率性输出转成可重复的证据：版本化数据集、明确评分规则、分层指标、失败样本、成本与延迟，以及安全门禁。

本模块同时处理两类问题：

1. **测试 AI 系统**：LLM、RAG、工具调用 Agent 的质量、安全、可靠性、性能与成本；
2. **用 AI 提升测试效率**：辅助分析需求、生成候选用例和脚本、归纳失败，但由人和可执行证据负责最终结论。

## 当前招聘市场如何划分 AI 测试

2026-07-27 的 BOSS 直聘定向样本表明，“AI 测试”不是单一岗位。26 个去重样本中，本科及以上为 24/26，明确要求 3 年及以上经验为 20/26；这只描述主动覆盖中高级岗位的本次样本，不能外推全国。

学习时应按实际职责选择路线：

| 路线 | 重点 |
|---|---|
| 普通测试 + AI 提效 | AI 生成候选用例、数据、脚本和分诊结论，人和运行证据负责验收 |
| AI 应用测试 | LLM/RAG/多模态产品的功能、接口、流式、性能、稳定性、效果和安全 |
| 大模型/多模态评测 | 数据集、Benchmark、标注、事实性、鲁棒性、公平性、无害性和统计比较 |
| Agent 测试 | 规划、状态、记忆、工具调用、权限、终态、副作用、恢复和多 Agent |
| 测试开发/评测平台 | 自动化框架、评测任务、结果平台、CI/CD、可观测性、脱敏和审计 |

完整样本与方法见[软件测试与人工智能测试招聘需求调研](../00-学习指南/04-软件测试与人工智能测试招聘需求调研.md)，分路线的学习任务、作品和验收见[人工智能测试岗位能力与实战路线](04-人工智能测试岗位能力与实战路线.md)。

## 学习目标

完成本模块后，你应能：

- 把模糊的“回答得好”拆成可测的事实性、规则遵循、拒答、安全、检索、轨迹、延迟和成本指标；
- 先写确定性检查，再按需要增加人工评分或经过校准的模型评分器；
- 为 LLM、RAG 和 Agent 分层设计离线回归集与在线监控；
- 在授权、隔离的合成环境中执行提示注入和 Agent 红队测试；
- 让 AI 参与测试分析和自动化，同时保留来源引用、人工复核、最小权限和可回滚变更；
- 明确“工具在本机运行”和“数据没有外发”不是一回事。

## 1. 先建立正确的测试模型

传统程序通常是相同输入得到相同输出；生成式系统还受到模型快照、提示词、采样参数、检索结果、工具状态和上下文的影响。因此不能只比较唯一标准答案。

建议用下面五层组织证据：

| 层次 | 主要对象 | 优先检查 |
|---|---|---|
| 1. 确定性契约 | JSON、工具参数、权限、金额、引用格式 | Schema、精确值、范围、禁止词、状态不变量 |
| 2. 语义质量 | 开放式回答、总结、改写 | rubric、成对比较、人工标注、校准后的模型评分 |
| 3. RAG 链路 | 查询、召回、重排、回答、引用 | Recall@k、MRR、nDCG、忠实性、引用正确性 |
| 4. Agent 行为 | 计划、工具、状态变化、恢复 | 最终环境状态、允许/禁止动作、轨迹、预算、重试 |
| 5. 运行风险 | 线上分布、安全、性能、成本 | 切片通过率、严重失败数、p95 延迟、每任务成本、漂移 |

核心循环是：

```text
定义风险与成功标准
  → 建立小而可信的合成/公开评测集
  → 运行并保存逐例证据
  → 分析切片与失败模式
  → 修改提示词、检索、工具或代码
  → 回归并监控新的真实分布
```

单一平均分不能证明系统安全。安全关键用例、越权操作、敏感信息泄漏和金额错误应设为独立的“零容忍门禁”或按风险审批，不能被大量简单样本稀释。

## 2. 工具路线：一条主线，按问题选修

不要为了“工具栈丰富”同时维护五套重叠框架。先掌握评测设计，再选择能回答当前问题的最小工具集。

### 主线

| 阶段 | 工具 | 本教程中的职责 |
|---|---|---|
| 入门与 CI 门禁 | 本仓库 Python 评分器 + pytest | 无模型、无网络、可解释地验证数据集和确定性规则 |
| 通用 LLM/Agent 评测与红队 | [Promptfoo](https://github.com/promptfoo/promptfoo) | 将 prompts、providers、tests、assertions 作为代码版本化，本地或 CI 执行 |
| 追踪与线上反馈 | [OpenTelemetry GenAI 语义约定](https://github.com/open-telemetry/semantic-conventions-genai) + [Phoenix](https://arize.com/docs/phoenix) | 采集经过脱敏的 trace，把线上失败转回离线评测样本 |

### 按需选修

| 需求 | 可选工具 | 何时引入 |
|---|---|---|
| Python 单元测试风格的 LLM 指标 | [DeepEval](https://github.com/confident-ai/deepeval) | 团队以 pytest/Python 为主，确实需要其指标或数据模型时 |
| RAG 专项指标 | [Ragas](https://docs.ragas.io/) | 已能拆分检索与生成，需要成套 RAG 实验时 |
| 高可控的安全评测任务 | [Inspect AI](https://inspect.aisi.org.uk/) | 需要 sandbox、task/model/scorer 组合的高级评测时 |
| 模型漏洞扫描 | [garak](https://github.com/NVIDIA/garak) | 已明确授权范围，需要补充探针覆盖时 |
| 托管数据集、实验与人工标注 | [LangSmith](https://docs.langchain.com/langsmith/evaluation-concepts) | 组织允许数据进入该平台，且托管协作价值高于合规与成本负担时 |

选修不代表“更高级”。如果确定性检查已经能准确判断金额或工具参数，就不应换成更昂贵、更不稳定的模型裁判。

## 3. 2026 年必须记录的工具变更

### OpenAI hosted Evals 退出

这里要区分两个对象：

- **OpenAI Platform 中托管的 Evals 产品**：OpenAI 于 **2026-06-03** 宣布弃用；官方时间表是 **2026-10-31** 现有 eval 变为只读，**2026-11-30** Evals dashboard 与 API 计划关闭；
- **`openai/evals` 开源仓库**：仍可查看，但本教程只把它作为历史/参考项目，不作为新学习路线的主线。

OpenAI 官方给出的迁移路线是 Promptfoo。迁移不是“换个按钮”：

1. 导出可运行的 Promptfoo 配置；
2. 另行导出历史结果；
3. 检查未迁移的自定义 grader、工具和 Agent provider；
4. 重新校准相似度或 LLM judge，不能假设两个系统分数完全一致；
5. 在本地和 CI 验证新门禁真的会失败。

来源：[OpenAI 弃用时间表](https://developers.openai.com/api/docs/deprecations#2026-06-03-evals-platform)、[官方迁移教程](https://developers.openai.com/cookbook/examples/evaluation/moving-from-openai-evals-to-promptfoo)、[`openai/evals`](https://github.com/openai/evals)。

### Promptfoo 与 Node.js

截至核对日，Promptfoo README 说明：

- Promptfoo 已成为 OpenAI 的一部分，仍保持 MIT 开源；
- npm/npx 当前要求 Node.js `^20.20.0` 或 `>=22.22.0`；
- **Node.js 20 支持将于 2026-07-30 00:00 UTC 结束**，因此新环境直接使用 **Node.js 24 LTS**，并在安装/升级 Promptfoo 前复核其 README。

不要把 `npx promptfoo` 在本机启动理解为数据必然留在本机。配置了云模型 provider 后，提示词、测试输入、上下文和候选输出仍可能发往云端；是否存储、训练、保留多久取决于具体服务、账号设置和合同。

## 4. 零密钥快速实验

本仓库已有一个完全确定性的 AI 评测实验：

- 数据集：[`人工智能评测数据集.jsonl`](../../labs/demo-shop/tests/ai/人工智能评测数据集.jsonl)
- 评分器：[`人工智能回答评测器.py`](../../labs/demo-shop/tests/ai/人工智能回答评测器.py)
- 回归测试：[`测试_人工智能回答评测器.py`](../../labs/demo-shop/tests/ai/测试_人工智能回答评测器.py)

它包含事实性、退款边界、提示注入、未知订单拒答和价格计算五个合成样本。评分器只检查：

- 每个 `required_terms` 是否都出现；
- 每个 `forbidden_terms` 是否都没有出现；
- 单例是否所有检查通过；
- 数据集通过率是否达到阈值。

它不调用模型、不读取外部服务，也不需要密钥。进入实验目录运行：

```bash
cd labs/demo-shop
python tests/ai/人工智能回答评测器.py
pytest tests/ai -q
```

预期行为：

- 正常数据集输出逐例 JSON 结果，进程退出码为 `0`；
- 单元测试构造含 `DEMO_SECRET` 的合成失败，确认评分器能报告禁止词；
- 将副本数据中的必需词删除或加入禁止词后，评测命令应返回非零退出码。

这只是第一道门禁，不是生产级语义评测。关键词评分会误判同义表达、否定句、引用攻击文本和复杂上下文；这些局限将在下一章通过对抗样本、人工 rubric 和校准实验暴露出来。

## 6. 数据外发前的硬门禁

任何模型调用、托管观测、插件、浏览器扩展或在线评测前，都先填写：

| 问题 | 不清楚时的默认动作 |
|---|---|
| 输入是否已确认授权范围和数据分类？ | 不发送 |
| 是否含真实姓名、账号、订单、日志、截图、代码、内部 URL、Cookie、Token？ | 不发送；不要只依赖“打码应该够了” |
| provider 会把数据发到哪里、保存多久、是否用于训练？ | 不发送，先查官方条款和组织审批 |
| trace/报告是否包含完整 prompt、检索块或工具返回？ | 默认不采集正文，只保留必要元数据 |
| 是否能用合成数据、mock 工具和假 canary 达到同样学习目的？ | 优先替代 |
| 输出是否会被自动执行、提交或发消息？ | 关闭自动执行，保留人工确认与沙箱 |

## 7. 常见误区

| 误区 | 为什么有问题 | 改进 |
|---|---|---|
| 跑十个问题都“看起来不错” | 没有分布、标准和回归能力 | 版本化数据集，按风险切片并保存逐例结果 |
| 用一个模型裁判评价所有内容 | 裁判也有偏差、随机性和注入风险 | 确定性优先；judge 与人工标签校准 |
| 只看总通过率 | 严重安全失败会被平均值掩盖 | 安全、越权、金额等单独设门禁 |
| RAG 回答错就只改提示词 | 可能是召回、重排、权限或资料版本问题 | 分层测检索、上下文和生成 |
| Agent 最终回答对就算通过 | 中途可能调用错工具、产生副作用或浪费预算 | 同时验证环境终态、轨迹与策略 |
| CLI 在本地，所以数据没外发 | 云 provider、遥测和结果平台仍可能接收数据 | 画数据流，逐个审查出口 |
| 红队就是收集“越狱咒语” | 缺少资产、权限、影响与修复验证 | 从威胁模型到安全回归闭环 |
| AI 生成脚本后直接提交 | 可能有幻觉 API、不安全依赖和脆弱断言 | 小步生成、审查、运行、失败诊断 |

## 8. 练习

### 练习 A：证明门禁有效

1. 运行原始确定性评测并保存摘要；
2. 复制数据集到临时目录，不修改基线文件；
3. 制造一条缺少必需词和一条包含禁止词的失败；
4. 用 `--dataset` 指向临时副本；
5. 记录非零退出码、失败 case ID 和诊断字段。

### 练习 B：暴露关键词评分缺陷

为同一规则写四种候选回答：同义表达、否定句、引用攻击文本、看似拒答但暗含敏感片段。人工先标正确与否，再运行关键词评分，列出假阳性和假阴性。

### 练习 C：设计分层门禁

为一个虚构客服 Agent 写出：

- 5 条确定性契约；
- 1 份 4 级语义 rubric；
- 3 个安全关键零容忍用例；
- 2 个工具调用终态断言；
- 1 个延迟和成本观察指标。

## 9. 模块验收

- [ ] 能解释为什么确定性评分应先于模型评分；
- [ ] 能运行 `demo-shop` 的 AI 评测并主动制造可诊断失败；

- [ ] LLM judge 有人工金标准、偏差检查和版本记录；
- [ ] RAG 能区分检索失败、上下文污染和生成失败；
- [ ] Agent 同时验证最终状态、工具轨迹、权限、副作用和预算；
- [ ] 安全测试只在明确授权的本地/mocked 目标执行；
- [ ] 能准确说明 OpenAI hosted Evals 的 2026 退出时间表和 Promptfoo 迁移；

- [ ] 所有模型输入均已完成授权、数据分类和必要性检查；
- [ ] 能画出模型、观测、插件和报告的数据外发路径；
- [ ] 结论包含失败样本、限制、版本和证据，不把单次分数包装成普遍能力。
