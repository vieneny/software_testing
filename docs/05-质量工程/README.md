# 阶段 5：质量工程、CI 与可观测性

目标：把功能、接口、UI、性能和 AI 测试组织成不同速度、不同风险的反馈通道，让失败可分诊、发布可决策。

## 学习顺序

1. [持续集成、持续交付与质量门禁](./01-持续集成持续交付与质量门禁.md)
2. [测试数据、环境与可观测性](./02-数据环境与可观测性.md)
3. [自动化框架设计与进阶项目](./03-自动化框架设计与进阶项目.md)
4. [自动化故障排查](./04-自动化故障排查.md)

## 阶段项目

为现有工程设计并实现：

```text
本地静态/单元
  → PR 离线与 API smoke
  → 合并后集成/Web
  → 夜间 App/性能/安全
  → 发布前矩阵
  → 发布后观测与回归样本
```

## 完成证据

- [ ] 每条通道有触发、输入、超时、退出码和产物；
- [ ] Secret、环境配置和测试数据职责分开；
- [ ] 首次失败不会被重试或清理覆盖；
- [ ] Trace、日志、指标通过关联 ID 串联；
- [ ] flaky 测试有分类、责任和退出隔离策略；
- [ ] 门禁依据风险和反馈成本，而不是追求全部检查每次运行。

完成后可进入 [AI 测试](../06-AI测试/README.md)或[综合实战](../07-综合实战/README.md)。
