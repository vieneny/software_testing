> 适用对象：希望从 iOS Simulator 入门，再安全过渡到真机和可维护框架的测试同学。
>
> 内容核对日期：2026-07-27。Apple/Xcode/iOS 与 XCUITest Driver 兼容矩阵变化很快，执行前重新核对官方文档。

## 2. iOS 调用链

```text
pytest / Appium Python Client
          │ W3C WebDriver
          ▼
Appium 3 Server
          │ automationName=XCUITest
          ▼
XCUITest Driver
          │ 构建/启动/复用 WebDriverAgent
          ▼
XCTest / iOS Simulator 或签名真机
          │
          ▼
公开练习 AUT
```

WDA 是 Appium 与 Apple XCTest 之间的桥。真机报签名错误时，修改 Python 定位器毫无帮助；反过来，
能启动 WDA 也不等于 AUT 的 locator 正确。按层排查是 iOS 自动化的核心能力。

## 4. 主机与工具链

### 4.1 为什么需要 macOS

XCUITest Driver 的标准主机是 macOS，因为 Apple 的 Xcode、XCTest、Simulator 和签名工具链只在
macOS 上提供。Windows/Linux 可以作为调度端，但不能替代执行节点上的完整 Xcode 环境。

安装并首次打开 Xcode，接受许可证和组件安装，再选择正确的 Command Line Tools：

```bash
xcode-select -p
xcodebuild -version
xcrun xctrace list devices
```

如果电脑有多个 Xcode，不要凭应用名称猜。用 `xcode-select` 明确当前 CLI 选择，并将 Xcode 版本纳入
运行 manifest。

### 4.2 安装 Appium 与 Driver

先按目标 Appium 3 版本要求准备 Node/npm：

```bash
node --version
npm --version
npm install --global appium
appium --version
appium driver install xcuitest
appium driver list --installed
appium driver doctor xcuitest
```

需要复现本机快照时可明确版本：

```bash
appium driver install xcuitest@11.11.2
```

但不能只因“本机有 11.11.2”就认定它适配任何 Xcode/iOS。安装前阅读
[System Requirements](https://appium.github.io/appium-xcuitest-driver/latest/installation/system-requirements/)、
[安装说明](https://appium.github.io/appium-xcuitest-driver/latest/installation/)与对应 Release Notes。

Appium 提供：

```bash
appium setup mobile
```

在 macOS 上可批量配置常用移动 Driver/组件；学习和受控升级更推荐逐个安装并记录版本，便于知道到底
变更了什么。

### 4.3 Python 环境

```bash
cd labs/automation-practice
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[mobile,dev]'
```

代码使用 `XCUITestOptions`：

```python
from appium.options.ios import XCUITestOptions

options = XCUITestOptions()
options.load_capabilities(
    {
        "platformName": "iOS",
        "automationName": "XCUITest",
        "deviceName": "iPhone 17 Pro",
        "app": "/绝对路径/UIKitCatalog-iphonesimulator.zip",
    }
)
```

新版 Python Client 不再接受旧式 `desired_capabilities=`。

## 5. Simulator 与真机：不能混为一谈

| 维度 | Simulator | 真机 |
|---|---|---|
| CPU/SDK build | `iphonesimulator` | `iphoneos` |
| 常见 AUT | `.app` 或包含 simulator `.app` 的 `.zip` | 签名 `.app`/`.ipa` 或已安装 bundle |
| WDA 签名 | 通常无需开发者签名 | 必须完成开发团队/Provisioning 配置 |
| 设备选择 | Simulator UDID 最可靠；也可 name + version | 必须使用真实 UDID |
| 传感器/硬件 | 模拟或缺失 | 真实行为 |
| 性能结论 | 不能代表真机 | 仍需考虑机型、温度、电量 |
| 清理 | 可创建/删除独立 simulator | 谨慎，只清理测试 AUT |
| 推荐用途 | 快速反馈、UI 主流程、定位开发 | 安装/签名、权限、硬件、真实兼容性 |

Simulator `.app` 不能安装到真机；真机 `.ipa` 也不能当 Simulator build。错误资产通常会出现架构、
签名或安装错误，增加 timeout 无法解决。

## 8. iOS 真机端到端

真机配置复杂的根本原因不是 Appium，而是 Apple 要求所有运行代码都经过可信签名，WDA 也不例外。

### 8.1 使用专用测试设备

- 设备不登录私人 Apple ID，或使用组织批准的测试 Apple ID。
- 不放私人照片、联系人、短信、健康数据、支付卡、密码或公司 App。
- 关闭锁屏通知预览。
- 不连接公司 VPN。
- 用完卸载公开样例/WDA，关闭 Developer Mode（按团队策略）。
- 所有截图、录屏和日志上传前人工复核。

### 8.2 信任、Developer Mode 与 UI Automation

1. 用可信数据线连接 Mac。
2. 解锁设备并选择“信任此电脑”。
3. iOS 16+ 打开 Developer Mode，按系统提示重启和确认。
4. 在需要的系统版本中启用 UI Automation/开发者相关选项。
5. 用 Xcode 的 Devices and Simulators 确认设备可用。

核对：

```bash
xcrun xctrace list devices
```

真机必须写准确 UDID。不要用 `deviceName` 猜测，也不要在连接私人手机和测试手机时使用 `udid=auto`。

### 8.3 AUT 签名

真机 AUT 必须：

- 使用 `iphoneos` SDK 构建。
- 由你有权使用的开发团队签名。
- Provisioning Profile 包含目标设备（开发/Ad Hoc 场景）。
- entitlement 与签名匹配。
- bundle id 不与无权覆盖的应用冲突。

签名凭据应通过受控的密钥管理流程注入，不要把证书、`.p12`、私钥或 Provisioning Profile 写入版本库。

### 8.4 WDA 签名

阅读
[XCUITest Driver Real Device Configuration](https://appium.github.io/appium-xcuitest-driver/latest/preparation/real-device-config/)。
常见受控配置包括：

```text
appium:xcodeOrgId
appium:xcodeSigningId
appium:updatedWDABundleId
appium:xcodeConfigFile
```

推荐将签名值保存在本机私有环境/密钥系统，不硬编码到测试代码。`updatedWDABundleId` 应是你控制且可签名
的唯一 bundle id。`xcodeConfigFile` 本身也可能泄露 Team 或签名信息，加入忽略规则。

先单独完成 WDA 构建/安装问题，再运行业务 smoke。常见验证方式是在 Xcode 中打开 Driver 附带的
WebDriverAgent 项目，选择目标设备和 Team，构建 `WebDriverAgentRunner`。具体路径随 Driver 安装方式
变化，以 `appium driver run xcuitest ...`/官方文档查询结果为准，不在代码中写死全局 npm 路径。

### 8.5 真机 `.env`

```dotenv
APPIUM_SERVER_URL=http://127.0.0.1:4723
MOBILE_PLATFORM=ios
MOBILE_APP_PROFILE=my_demo_app
MOBILE_DEVICE_NAME=Dedicated iPhone

MOBILE_PLATFORM_VERSION=
MOBILE_APP=/绝对路径/自己有权使用且已签名的公开练习.ipa
```

## 10. Capabilities 逐项解释

| Capability | Simulator | 真机 | 说明 |
|---|---|---|---|
| `platformName` | `iOS` | `iOS` | W3C 标准 |
| `appium:automationName` | `XCUITest` | `XCUITest` | 显式选择 Driver |
| `appium:deviceName` | 实际 simulator 名 | 描述性设备名 | 不用它选择真机 |
| `appium:udid` | 推荐精确 simulator UDID | 必填真实 UDID | 防止控制错误目标 |
| `appium:platformVersion` | 可选 | 可选 | 不要与真实设备版本矛盾 |
| `appium:app` | simulator `.app/.zip` | 签名 `.app/.ipa` | 必须绝对路径 |
| `appium:bundleId` | 对应公开样例 | 签名包真实 bundle | 可启动已安装 App |
| `appium:noReset` | 默认 `false` | 默认 `false` | 保持用例隔离 |
| `appium:autoAcceptAlerts` | 默认 `false` | 默认 `false` | 权限流程必须显式验证 |
| `appium:shouldTerminateApp` | `true` | `true` | 结束 Session 清理前台状态 |

真机常见 WDA 能力：

| Capability | 用途 | 风险/建议 |
|---|---|---|
| `xcodeOrgId` | Apple Team ID | 机密配置，不提交 |
| `xcodeSigningId` | 签名身份 | 通常为 Apple Development |
| `updatedWDABundleId` | 唯一 WDA bundle | 必须能由该 Team 签名 |
| `xcodeConfigFile` | 私有 `.xcconfig` | 文件加入忽略和权限控制 |
| `useNewWDA` | 是否每次重建 WDA | 不要为“修偶发失败”长期设 true |
| `wdaLocalPort` | 本机 WDA 代理端口 | 并行 Session 必须唯一 |
| `derivedDataPath` | Xcode 构建目录 | 并行建议隔离 |

不要一次复制二十个 capability。每新增一个都回答：解决什么已复现问题、默认值是什么、对安全/时间/
状态有什么副作用。

## 11. 定位器工程

### 11.1 优先级

1. 唯一、稳定、技术语义的 `accessibilityIdentifier`。
2. 精确 iOS Predicate。
3. 简短 iOS Class Chain。
4. 可控且稳定的可见 label/name。
5. XPath 仅作为最后方案。
6. 坐标仅用于探索，不进入回归。

[Apple accessibilityIdentifier 文档](https://developer.apple.com/documentation/uikit/uiaccessibilityidentification/accessibilityidentifier)
明确说明它可用于自动化脚本，并能避免滥用面向用户的 accessibility label。

好标识：

```text
catalog.product.backpack
product.add-to-cart
cart.item-count
```

脆弱标识：

```text
//XCUIElementTypeApplication/XCUIElementTypeWindow[1]/...
第 4 个 Button
坐标 (327, 52)
```

### 11.2 Predicate

UIKitCatalog 示例：

```python
(
    AppiumBy.IOS_PREDICATE,
    "type == 'XCUIElementTypeNavigationBar' AND name == 'Buttons'",
)
```

Predicate 必须尽量精确。`CONTAINS` 容易匹配多个元素；若为了兼容多个公开样例版本设置 fallback，要在
Page Object 内集中维护并对每个候选设置短 timeout，不能散落在测试中。

### 11.3 Class Chain

Class Chain 比完整 XPath 更贴近 XCUITest 查询，但仍依赖层级。示意：

```text
**/XCUIElementTypeCell[`name == "catalog.product.backpack"`]
```

优先推动应用提供 identifier。自动化可测性是产品代码的接口，不应长期由测试用复杂层级补洞。

### 11.4 页面切换等待

点击 `Buttons` 后等待名为 `Buttons` 的 Navigation Bar，而不是等待固定两秒。点击产品后等待详情页
独有的 Add to Cart。这样失败日志能回答“目标页面没有出现”，而不仅是“下一步找不到元素”。

## 12. 等待、滚动与手势

`BaseScreen` 提供：

- `wait_visible`
- `wait_clickable`
- `wait_until_gone`
- `scroll_until_visible`
- `save_screenshot`

iOS 有界滚动使用：

```python
driver.execute_script("mobile: swipe", {"direction": "down"})
```

复杂手势可参考
[XCUITest Driver Execute Methods](https://appium.github.io/appium-xcuitest-driver/latest/reference/execute-methods/)：

- `mobile: swipe`
- `mobile: scroll`
- `mobile: dragFromToForDuration`
- `mobile: tap`
- `mobile: touchAndHold`

注意：

- iOS 的滚动/滑动语义和 Android 不完全相同。
- 每次滚动后重新定位元素，避免持有 stale reference。
- 限制尝试次数并输出 locator/方向。
- 业务回归避免坐标；画布、地图等特殊控件才在明确屏幕区域内用坐标。

## 13. 权限与系统弹窗

本项目默认 `autoAcceptAlerts=false`，原因是自动“全部允许”会漏掉权限产品逻辑。

设计权限用例：

```text
Given 专用测试设备，样例 App 权限处于未决定状态
When 触发相机权限并选择“不允许”
Then App 显示可恢复说明且不崩溃
When 进入设置授予权限后返回
Then 功能可继续
```

边界：

- 相机使用公开测试二维码。
- 照片权限只使用专用设备上生成的公开测试图。
- 不读取通讯录、短信、健康、位置历史和私人相册。
- 不用个人 Apple ID/iCloud 数据做测试夹具。
- 系统弹窗定位要区分 AUT 与 SpringBoard。
- Locale 文本会变化，优先系统可访问性语义或在单一语言环境下明确测试。

Simulator 权限可通过 `simctl privacy` 管理，但命令必须指定测试 simulator UDID 和公开样例 bundle，
禁止使用 `all` 清理未知设备。

## 14. WebView / Hybrid

流程：

```python
contexts = driver.contexts
driver.switch_to.context("WEBVIEW_<bundle-or-process>")
# DOM/CSS 操作
driver.switch_to.context("NATIVE_APP")
```

前提：

- App 内 `WKWebView` 允许检查。iOS 16.4+ 应用通常需要设置 `isInspectable=true`。
- WebView 已加载到可用状态。
- 使用的 Safari/WebKit 调试链与设备/Xcode 兼容。
- 真机端口转发/WDA 配置正常。

UIKitCatalog 4.x 为样例 WebView 提供了适配，但每次仍应以对应 tag 源码和 Driver 文档为准。

不要在 Hybrid 练习中打开公司网站、邮箱、网盘或私人账号。只使用公开静态页或自己本地的无敏感服务。

## 15. 并行设计

iOS 并行以独占设备/Simulator 为单位：

```text
worker-1
  simulator-UDID-A
  wdaLocalPort=8101
  derivedDataPath=/绝对路径/derived/A
  独立 AUT 数据

worker-2
  simulator-UDID-B
  wdaLocalPort=8102
  derivedDataPath=/绝对路径/derived/B
  独立 AUT 数据
```

还要考虑：

- 每个 Simulator 用唯一 UDID，不靠同名 `deviceName`。
- 真机每个 worker 独占一台设备。
- 不共享购物车、登录账号、推送 token。
- DerivedData 与 WDA 端口隔离。
- Simulator clone/erase 只操作已验证的测试设备 UDID。
- 设备池要有租约、超时和异常释放。

先稳定单设备，再并行。并行不能修复 flaky，只会更快暴露它。

## 16. 失败产物与隐私

最低必要产物：

- pytest 用例名、断言和阶段时长。
- Appium Server/XCUITest Driver 日志（脱敏）。
- 公开样例当前页面截图。
- Appium、Driver、Python Client、macOS、Xcode 版本。
- 设备类型、iOS 大版本、AUT 版本与 SHA-256。
- WDA 构建错误的必要片段。

默认不采集：

- 全量设备 syslog。
- 全量 page source。
- 长时间录屏。
- 设备文件、相册、剪贴板。
- Keychain、证书和 Provisioning Profile。
- Apple ID 或签名命令完整输出。

`BaseScreen.save_screenshot()` 要求调用方给出明确产物路径。打开失败自动截图前确认测试机关闭通知预览，
且 AUT 位于前台。所有产物设置保留期和访问权限。

## 17. 分层排障

### 17.1 `xcodebuild` 不可用或选错 Xcode

```bash
xcode-select -p
xcodebuild -version
xcrun --find simctl
```

不要直接重装 Appium。先让 Xcode CLI 工具链自洽。

### 17.2 找不到 XCUITest Driver

```bash
appium driver list --installed
appium driver doctor xcuitest
```

确认启动 Appium 的 Node 环境与安装 Driver 的环境一致。

### 17.3 Simulator 不存在

```bash
xcrun simctl list runtimes
xcrun simctl list devices available
```

修改为本机真实设备名称/UDID。`Unable to find a device` 通常不是等待问题。

### 17.4 应用架构不匹配

现象包括无法安装、缺少兼容架构、`ApplicationVerificationFailed`。确认：

- Simulator 用 `iphonesimulator` `.app/.zip`。
- 真机用签名 `iphoneos` `.app/.ipa`。
- 下载哈希正确。
- 目标最低 iOS 不高于设备版本。

### 17.5 真机 WDA 签名失败

看 xcodebuild 根因，不要只看最后一行 `exit code 65`：

- Team 是否正确。
- WDA bundle id 是否唯一且可签名。
- Provisioning Profile 是否包含真机 UDID。
- 证书是否有效且私钥在 Keychain。
- Developer Mode/信任是否打开。
- Xcode 是否支持目标 iOS。

禁止通过借用、上传或提交他人的企业证书解决。

### 17.6 WDA 已装但连接失败

检查：

- 真机是否解锁、仍信任 Mac。
- `wdaLocalPort` 是否冲突。
- USB 是否稳定。
- WDA runner 是否被系统终止。
- 设备与 Mac 时间/网络策略是否异常。
- Server 日志中是 WDA 启动、端口代理还是 `/status` 超时。

### 17.7 AUT 启动失败

- `bundleId` 是否与构建产物一致。
- `.app/.ipa` 是否有效签名。
- App 最低 iOS 是否满足。
- 是否试图覆盖不同 Team 签名的同 bundle 应用。
- 公开样例路径是否为绝对路径且 hash 正确。

只卸载目标公开样例；不要批量删除设备 App。

### 17.8 元素找不到

1. 截图确认页面和弹窗。
2. Appium Inspector 查看 identifier/name/label/type。
3. 确认 locator 是否唯一。
4. 等待目标页独有元素。
5. 检查元素是否在可滚动区域。
6. 检查 context 是 `NATIVE_APP` 还是 `WEBVIEW`。
7. 检查语言、动态字体和系统版本差异。
8. 最后才考虑 Predicate/Class Chain/XPath fallback。

### 17.9 stale element / 间歇失败

列表刷新、动画或滚动后重新定位，不长期缓存 element。将页面动作设计成“等待 → 查找 → 操作”，不要在
Page Object 构造函数里保存所有 WebElement。

### 17.10 测试结束后残留 Session

fixture 必须 `finally/teardown` 执行 `driver.quit()`。本仓库的 on-demand factory 会记录已创建 Driver，
逆序关闭。若 Python 进程被强杀，检查 Appium Session/WDA 状态并只清理已确认的测试目标。

## 18. Page Object 设计复盘

UIKitCatalog smoke：

```text
首页等待 Buttons
  → 点击 Buttons
  → 等待 name=Buttons 的 NavigationBar
```

My Demo App iOS smoke：

```text
等待 Catalog-screen 与 Product Name
  → 进入详情
  → 等待 ProductDetails-screen
  → 点击 Add To Cart
  → 点击 Cart-tab-item 并等待 Cart-screen
  → 断言购物车有 Sauce Labs Backpack - Black
```

这些 identifier 来自 2.2.2 tag 自带的 `MyDemoAppUITests/PageObjects/PageObject.swift`，因此代码固定
样例版本并拒绝 XPath/坐标。升级 Release 时先用上游测试和 Inspector 重新核对，不能无依据地堆叠文案
fallback。真实团队应与开发约定稳定 `accessibilityIdentifier`。

测试文件只保留业务意图，Driver 生命周期在 fixture，能力选择在 factory，等待/手势在 BaseScreen。
这个分层能让失败定位到具体责任边界。

## 20. 分级练习

### L1：Simulator 入门

- 固定 UIKitCatalog Release 和 SHA-256。
- 用明确 Simulator UDID 跑通 Buttons smoke。
- 故意将 profile 改成 `api_demos`，观察创建 Session 前的配置错误。
- 默认不加 `--run-mobile`，证明不会启动 Session。

### L2：定位和等待

- 为 UIKitCatalog 增加 Alerts 或 Text Fields Page Object。
- 只用 identifier/Predicate/Class Chain。
- 替换所有 sleep。
- 用页面独有元素证明切换完成。
- 连续运行 20 次，输出成功率和 P95。

### L3：状态与权限

- 用专用 Simulator 设计一次允许/拒绝权限用例。
- 每条用例恢复自己的权限状态。
- 测试 Locale、动态字体和横竖屏。
- 验证失败产物不包含通知、Apple ID 或私人数据。

### L4：真机

- 使用自己的开发 Team 构建 UIKitCatalog real-device target。
- 配置唯一 WDA bundle id。
- 用准确 UDID 建立 Session。
- 记录从 Session 请求到 WDA ready、AUT ready 的分段耗时。
- 故意制造签名错误并写出分层根因，不泄露 Team/证书信息。

### L5：Hybrid 和并行

- 在公开/自建最小 Hybrid App 中等待并切换 WEBVIEW。
- 两个 Simulator 分配唯一 UDID、WDA 端口、DerivedData。
- 设计设备租约和异常释放。
- 生成版本/设备/AUT hash manifest。
- 为 flaky 用例设计隔离、所有者、根因和关闭条件。
