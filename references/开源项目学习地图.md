# 开源项目学习地图

本页保留“少而精”的主线选择。需要按功能、接口、Web/移动自动化、性能、AI 测试、Agent 安全和 AI 开发横向查阅项目时，使用[分类开源项目参考库](开源项目参考库/README.md)。

核对日期：**2026-07-27**。本集合用于建立教程的技术根基，不按 GitHub star 排名；引用项目时应遵守其许可证与署名要求。

使用任何项目之前都要检查当前 README、release、维护状态、`LICENSE` / `NOTICE` 和安全说明。许可证允许阅读不一定允许任意再分发；本仓库优先链接原项目并编写原创实验。

## 选择标记

- **主线**：个人项目实际使用，学到能设计、调试并接入 CI；
- **市场兼容**：能阅读和维护已有项目，理解迁移与取舍；
- **专题**：岗位或系统需要时深入；
- **参考实现**：阅读思想与工程结构，不作为当前依赖。

难度只是建议：

- L0：无需测试经验；
- L1：会基本命令、HTTP 或 Python；
- L2：能维护自动化项目；
- L3：需要分布式系统、性能、安全或 AI 基础。

## Python 与接口测试生态

### [pytest](https://github.com/pytest-dev/pytest) — 主线，L1→L3

学习重点：

- 从官方文档和自身测试理解收集、fixture、参数化、marker、hook；
- 阅读项目自己的测试和 CI，观察成熟项目怎样验证插件与兼容性；
- 写一个最小插件或 hook 体验扩展点，但不先造“万能框架”。

作品证据：可乱序、可重复、失败可诊断的接口测试项目和 JUnit 报告。

### [Requests](https://github.com/psf/requests) — 主线，L1→L2

学习重点：Session、显式超时、认证、Cookie、文件、重定向、TLS 与异常。检查项目测试如何处理 HTTP 行为。

作品证据：封装小而清晰的 API client，日志默认脱敏，网络失败有明确策略。

### [HTTPX](https://github.com/encode/httpx) — 专题，L2

当目标需要异步客户端、HTTP/2 或 ASGI/WSGI 原进程测试时再学。对比 Requests 的 timeout、client 生命周期和异常，不维护两套重复主线。

### [Schemathesis](https://github.com/schemathesis/schemathesis) — 专题，L2

从 OpenAPI 生成属性与边界测试。练习内容：运行 CLI、缩小失败、保存可复现案例、判断契约缺陷还是实现缺陷。它补充业务用例，不能替代业务规则测试。

## API 工具、Mock 与契约

| 项目 | 定位 | 难度 | 学习产出 |
|---|---|---:|---|
| [Newman](https://github.com/postmanlabs/newman) | 市场兼容；Collection v2.1 存量 CLI | L1 | 能维护旧流水线；新 Postman v12 项目同时理解 Postman CLI 迁移 |
| [WireMock](https://github.com/wiremock/wiremock) | HTTP 服务虚拟化专题 | L2 | 模拟错误、延迟、状态和第三方依赖，写出 stub 生命周期 |
| [Pact Python](https://github.com/pact-foundation/pact-python) | 消费者驱动契约专题 | L2→L3 | 消费者契约、Provider 验证、版本发布与 broker 流程 |
| [Testcontainers Python](https://github.com/testcontainers/testcontainers-python) | 真实依赖集成测试专题 | L2 | 临时数据库/队列、就绪检查、隔离和清理 |
| [Responses](https://github.com/getsentry/responses) | Requests 客户端单元测试选修 | L2 | 超时、错误响应、重试等客户端分支 |

选择原则：

- 函数/客户端的局部失败，用轻量 Mock；
- 独立服务边界和复杂状态，用 WireMock；
- 多团队独立发布且消费者契约重要时，用 Pact；
- 需要验证真实数据库/队列行为时，用 Testcontainers；
- 始终保留真实服务集成测试，不能让全部测试只面对 Mock。

## Web UI 自动化

公开练习目标按以下方式分工：

- [Playwright TodoMVC](https://demo.playwright.dev/todomvc/)：CRUD、过滤、键盘和 BrowserContext 隔离；
- [SauceDemo](https://www.saucedemo.com/)：登录、排序、购物车和完整结算；
- [The Internet](https://github.com/saucelabs/the-internet)：弹窗、iframe、窗口、上传下载和动态等待；
- [ParaBank](https://github.com/parasoft/parabank)：本地 Docker 中练习银行 Web + REST 全链路。

公共站点只做低频功能 smoke；完整回归优先使用本地可控实例。

### [Playwright](https://github.com/microsoft/playwright) / [playwright-python](https://github.com/microsoft/playwright-python) — 主线，L1→L3

学习重点：

- role / label / test id 定位；
- 自动等待和 web-first assertion；
- browser context 隔离、认证状态、网络控制；
- trace、截图、视频与 CI 失败诊断；
- Chromium / Firefox / WebKit 的必要兼容矩阵。

作品证据：2～4 条关键旅程，零固定休眠，失败 trace 可解释问题。

### [Selenium](https://github.com/SeleniumHQ/selenium) — 市场兼容，L1→L3

学习重点：W3C WebDriver、显式等待、Selenium Manager、Page Object、Grid 和基础 BiDi。目标是接手企业存量与理解浏览器远程协议，不复制第二套完整个人主线。

### [Appium](https://github.com/appium/appium) — 移动端专题，L2→L3

学习重点：Appium 3 的 driver/plugin 架构、UiAutomator2、XCUITest、原生与 WebView context、权限、手势、真机/模拟器和稳定性。平台驱动需单独安装，旧 Appium 1 教程不再作为参考。

## 性能测试

### [Grafana k6](https://github.com/grafana/k6) — 代码化主线，L2→L3

学习重点：scenario、开放/封闭模型、arrival rate、custom metrics、threshold、数据关联和 CI 退出码。先用本地服务推导负载模型，再写脚本。

作品证据：业务量假设、场景比例、p95/错误率阈值、资源指标、瓶颈假设与环境限制。

### [Apache JMeter](https://github.com/apache/jmeter) — 市场兼容，L1→L3

学习重点：Thread Group、Sampler、CSV、提取/关联、断言、Timer、CLI 与 HTML 报告。GUI 只用于设计和调试，正式负载使用 Non-GUI。

作品证据：一份可参数化 JMX 和 CLI 报告；能解释与 k6 场景模型的对应关系。

### [Locust](https://github.com/locustio/locust) — Python 专题，L2→L3

适合复杂 Python 用户行为、事件扩展和分布式 worker。学习 `HttpUser`、task 权重、wait time、headless、事件与 `FastHttpUser`。

工具不是容量结论。无论选择哪个项目，都必须同时采集被测端资源与依赖指标，并记录压测机是否先饱和。

## AI 评测与安全

### [Promptfoo](https://github.com/promptfoo/promptfoo) — AI 评测主线，L2→L3

定位：跨 provider 的数据集、提示词比较、断言、CI 和红队。2026-07-27 的新学习环境建议直接使用 Node.js 24 LTS；OpenAI hosted Evals 正在退出，官方也给出迁移到 Promptfoo 的路径。

作品证据：全部为合成数据的版本化评测集、确定性与语义评分、切片报告、安全门禁和基线比较。

### [DeepEval](https://github.com/confident-ai/deepeval) — Python 分支，L2→L3

定位：pytest 风格的 LLM/RAG/对话/Agent 评测。公开教程优先使用本地 OSS 能力；启用托管功能前检查数据是否上传、保留策略和权限。

### [Ragas](https://github.com/vibrantlabsai/ragas) — RAG 专题，L3

定位：RAG 指标、数据生成与实验。将检索 IR 指标、Ragas/模型指标和人工标签组合，不用单一总分替代质量判断。

### [Inspect AI](https://github.com/UKGovernmentBEIS/inspect_ai) — 高阶评测/安全，L3

定位：英国 AI Security Institute 维护的通用、Agent 与安全评测框架，支持任务、solver、scorer 和 sandbox。适合在掌握基础评测后研究复杂 Agent 与受控执行。

### [NVIDIA garak](https://github.com/NVIDIA/garak) — 红队入口，L3

定位：探测提示注入、泄露、越狱和有害输出等弱点。自动扫描结果必须人工复核；只对自有或明确授权目标运行，并设置预算与停止条件。

### [Arize Phoenix](https://github.com/Arize-ai/phoenix) — 可观测性/评测专题，L3

定位：tracing、数据集、实验和评测。自托管界面不代表模型请求不外发；provider 是云服务时，输入仍会离开电脑。

### [τ³-bench（仓库名保留 tau2-bench）](https://github.com/sierra-research/tau2-bench) — Agent 评测参考实现，L3

阅读重点：以环境/数据库终态、多次运行和工具交互评测 Agent，而不是只看最终文案。将其思想迁移到虚构的本地 mock 工具，不复制真实任务数据。

### [openai/evals](https://github.com/openai/evals) — 历史参考，L3

开源仓库仍可帮助理解 benchmark registry 与旧式 harness，但 OpenAI hosted Evals dashboard/API 已宣布于 2026-11-30 关闭。教程不得把开源仓库和即将关闭的托管产品混为一谈。

## 可观测性与 CI

| 项目 | 定位 | 难度 | 学习任务 |
|---|---|---:|---|
| [OpenTelemetry](https://github.com/open-telemetry) | traces / metrics / logs 标准生态 | L2→L3 | 关联请求、测试和服务端 span；设计脱敏与采样 |
| [Allure Report](https://github.com/allure-framework/allure3) | 报告选修 | L2 | 只在需要可视化与历史趋势时引入，不作为测试运行前置 |
| [GitHub Actions examples](https://github.com/actions/starter-workflows) | CI 参考 | L1→L2 | 读权限、缓存、矩阵和最小 Secret；命令保持平台无关 |

仓库托管于 Gitee 时，GitHub Actions 文件只是公开求职学习示例。真实执行可适配 Gitee Go 或 Jenkins，但测试入口、退出码和报告格式不应绑定某个平台。

## 三条推荐学习路径

### 小白主线

```text
demo-shop → pytest + Requests → Playwright → k6
          → GitHub Actions 示例 → 综合作品
```

只在主线稳定后接触 Schemathesis、WireMock 或 Allure。

### 自动化/测试开发拔高

```text
pytest 工程化 → OpenAPI/Schemathesis → WireMock/Pact/Testcontainers
→ Playwright 诊断与并行 → CI 分层 → k6/JMeter + 可观测性
```

### AI 测试

```text
本地确定性评测 → Promptfoo 或 DeepEval → RAG/Ragas
→ Agent 环境终态评测 → OWASP + Inspect AI/garak
→ Phoenix/OTel 持续评估
```

## 阅读开源项目的六步法

1. 读 README、官方文档和最近 release，确认当前入口；
2. 读许可证、安全政策和贡献指南；
3. 运行最小示例并记录版本；
4. 找到一个官方测试，解释 setup、action、oracle 和 cleanup；
5. 查看 CI 怎样分层、缓存、上传失败证据；
6. 选择一个小 issue 或文档问题，完成最小贡献。

不要把“收藏仓库”当成学习。最终证据必须是你能解释、运行、制造失败、诊断并迁移到另一个公开场景。

## 安全使用

- 只克隆公开项目到个人学习环境；
- 不对项目官网、公共演示站或第三方实例做扫描、压测或破坏测试；
- 使用本地容器、模拟器、mock 和合成 canary secret；
- 发现开源安全问题时遵循项目 `SECURITY.md`，不要公开利用细节。
