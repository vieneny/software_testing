# 公开练习应用与安全靶场

工具要在可控目标上练习才会变成能力。本页优先选择可本地部署、业务和缺陷清晰、能覆盖多个测试层的公开项目。公共在线实例仅用于低频人工探索或少量 smoke；自动化回归、性能、安全和故障注入必须使用本地或明确授权实例。

## 一、本仓库自带练习目标

| 项目 | 里面有什么 | 可以练什么 | 推荐阶段 |
|---|---|---|---|
| [demo-shop](../../labs/demo-shop/README.md) | 完全虚构的 Web/API/AI 小型商城、内存数据和测试 | 功能分析、接口、pytest、Web UI、性能、AI 评测、故障注入和 CI | **第一目标，L0→L3** |
| [automation-practice](../../labs/automation-practice/README.md) | API、Web 自动化框架骨架、配置和脚本 | Client/Page/Flow、证据、标签和分层复用 | **API/Web 主线，L1→L3** |
| [app-automation-learning](../../labs/app-automation-learning/README.md) | App 自动化离线业务流、Android/iOS Screen 和真机入口 | Appium、Screen/Flow、设备配置、失败证据与清理 | **App 主线，L1→L3** |

优先使用自带目标，因为：

- 数据完全合成；
- 服务只监听本机；
- 状态可以重置；
- 可以主动制造错误；
- 可以安全做少量性能和 AI 安全实验；
- 不受公共 Demo 改版、限流或账号污染影响。

## 二、跨端综合项目

### [Practice Software Testing / Toolshop](https://github.com/testsmith-io/practice-software-testing)（受限许可，非开源）

里面有：

- Web 商城；
- REST API 与 Swagger；
- Android 和 iOS App；
- Docker 本地环境；
- 可用于练习的不同版本和缺陷；
- 多端共享的商品、购物车、账号和订单业务。

可以做：

- API 建数、Web/移动端验证；
- 同一业务在 Web、Android、iOS 的一致性测试；
- 接口、UI、数据库和缓存的缺陷定位；
- 跨端 Page/Screen Object；
- 作为毕业 Capstone 输出完整报告。

许可边界：该项目当前许可证说明仅供参考，禁止商业使用、公开托管、再分发和作为第三方服务。它是有价值的公开练习项目，但不是可自由复用的开源软件；只能在当前许可允许的个人学习范围内使用，并在每次使用前重读上游许可证。

### [Grafana QuickPizza](https://github.com/grafana/quickpizza)

里面有公开 Web/API 演示服务、Docker、OpenTelemetry 和 k6/Grafana 生态示例。适合：

- API 功能与契约；
- k6 负载模型；
- Trace/Metric/Log 关联；
- 慢服务与依赖问题定位；
- 性能、可观测性和可靠性综合作品。

| 项目 | 里面有什么 | 可以做什么、学什么 | 边界 |

| [RealWorld](https://github.com/gothinkster/realworld) | 同一 Medium 类业务规范的多前端/后端实现生态 | 用同一验收标准比较技术栈、契约和跨实现一致性 | 选择一个活跃实现并固定版本 |

### SauceDemo

[SauceDemo](https://www.saucedemo.com/) 是有价值的公开练习站，适合登录、排序、购物车和结算，但它不是本页意义上的可自由复制开源靶场。只能遵守站点规则做低频学习验证，不能做性能、安全扫描或大规模自动化。需要长期稳定练习时，优先使用本地 `demo-shop`；也可在当前许可证允许的范围内使用 Practice Software Testing。

## 六、安全靶场与安全测试指南

| 项目 | 里面有什么 | 可以做什么、学什么 | 难度与边界 |
|---|---|---|---|
| [OWASP Juice Shop](https://github.com/juice-shop/juice-shop) | 现代 Web/API 漏洞、业务挑战和训练材料 | Web/API 安全、认证、访问控制、注入、业务逻辑和修复回归 | L1→L3；仅本地/授权 |
| [OWASP WebGoat](https://github.com/WebGoat/WebGoat) | Java Web 安全课程、课程关卡和解释 | 按漏洞原理练输入、认证、访问控制和服务端风险 | L1→L3；隔离运行 |
| [OWASP crAPI](https://github.com/OWASP/crAPI) | 面向 API Top 10 的微服务靶场 | 对象级授权、资源消耗、业务流和 API 清单 | L2→L3；资源较重 |
| [DVWA](https://github.com/digininja/DVWA) | 经典 PHP/MySQL 漏洞靶场和多难度配置 | 学基础 Web 漏洞、Proxy 和输入处理 | L1→L2；只放隔离网络 |
| [OWASP MASTG](https://github.com/OWASP/mastg) | 移动安全测试指南、测试案例和实践资源 | Android/iOS 安全测试方法、平台存储、网络、认证和逆向边界 | L2→L3；指南不是自动扫描器 |
| [OWASP AI Testing Guide](https://github.com/OWASP/www-project-ai-testing-guide) | AI 系统测试方法、风险和逐步测试案例 | 把 Prompt Injection、数据、模型、应用和 Agent 风险转成测试 | L2→L3；内容持续演进 |

安全靶场也必须隔离：

- 使用本地回环或独立 Docker 网络；
- 不绑定公网端口；
- 不使用真实密码、Token 或个人数据；
- 实验结束关闭服务并清理数据；
- 不把 payload 对准公司系统、公共 Demo 或第三方 API；
- 如发现开源项目真实漏洞，按 `SECURITY.md` 私下报告。

## 七、如何把练习变成作品

不要只提交脚本。每个练习项目至少留下：

1. 业务和架构理解；
2. 风险清单与优先级；
3. 测试模型和用例；
4. 环境启动、版本和重置方式；
5. 自动化代码与分层；
6. 主动制造的失败；
7. 日志、截图、Trace 或报告；
8. 缺陷定位与剩余风险；
9. CI 入口和失败门禁；
10. 许可证、授权和数据边界。

## 八、推荐 Capstone

### 初级：Restful Booker

```text
接口探索 → 20 个风险用例 → pytest 自动化
→ WireMock 失败注入 → CI 与 Allure
```

### 中级：Practice Software Testing（仅在受限许可允许的个人学习范围内）

```text
业务风险 → API 建数
→ Playwright Web → Appium Android
→ iOS 框架/Simulator → 跨端一致性
→ k6 小规模性能 → 质量报告
```

### 高级：QuickPizza 或 Petclinic Microservices

```text
服务依赖图 → 契约/集成测试
→ 负载模型 → OpenTelemetry
→ Toxiproxy/Chaos 故障 → 恢复与容量结论
```

### AI 测试：本地 `demo-shop`

```text
合成黄金集 → LLM/RAG 评测
→ Agent Mock 工具 → 安全红队
→ AIPerf/普通负载 → Trace 与质量门禁
```
