# 网页与移动端自动化开源项目

本页覆盖 Web、Android、iOS、可访问性、视觉回归和 AI UI 自动化的基础项目。主线仍是“稳定、可解释的确定性自动化”：Web 先学 Playwright，移动端先学 Appium；AI 驱动工具放在主线稳定之后做对照实验。

## 一、Web UI 自动化

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [Playwright](https://github.com/microsoft/playwright) | Chromium/Firefox/WebKit 驱动、定位器、自动等待、断言、网络控制、Trace、并行和测试运行器 | 学现代浏览器自动化的稳定性、隔离、取证和 CI；TypeScript 版本最能体现完整原生能力 | **核心，L1→L3** |
| [Playwright Python](https://github.com/microsoft/playwright-python) | Playwright 的 Python API、同步/异步接口和示例 | 与本仓库 pytest 主线组合；完成 Page/Component Object、fixture、Trace 和跨浏览器 smoke | **本仓库主线，L1→L3** |
| [Selenium](https://github.com/SeleniumHQ/selenium) | W3C WebDriver、多语言绑定、Grid、Manager 和 BiDi 演进 | 接手企业存量框架、理解远程浏览器协议和 Grid；重点学显式等待而非复制旧教程 | **市场兼容，L1→L3** |
| [Cypress](https://github.com/cypress-io/cypress) | 浏览器内测试运行、自动重试、网络 Stub、组件测试和交互式调试 | 学前端团队的测试体验与组件测试；比较其浏览器架构和多标签/多域限制 | **前端团队选修，L1→L2** |
| [WebdriverIO](https://github.com/webdriverio/webdriverio) | Node.js WebDriver/WebDriver BiDi、运行器、服务、报告器和 Appium 集成 | 在 JavaScript/TypeScript 团队统一 Web 与移动自动化；学习插件化配置 | **JS 岗选修，L2** |
| [Puppeteer](https://github.com/puppeteer/puppeteer) | Chrome DevTools Protocol/WebDriver BiDi 控制、页面、网络和性能能力 | 阅读浏览器自动化底层；适合爬取/工具开发，不作为本仓库第二套完整测试主线 | **架构阅读，L2** |

### Web 主线完成标准

- 使用 role、label 或稳定 test id，不依赖脆弱 XPath；
- 不使用固定休眠解决同步问题；
- 每个用例有独立 BrowserContext 和可重置数据；
- 失败时能得到 Trace、截图、视频、网络和控制台证据；
- 只自动化 2～4 条高价值用户旅程，不把所有接口规则搬到 UI 层；
- 在 CI 中按 smoke、回归、跨浏览器分层，而非每次全量执行。

### Android 真机练习顺序

```text
adb 设备识别
→ 安装公开 ApiDemos/My Demo App
→ Appium Server + UiAutomator2
→ Inspector 验证定位器
→ pytest 完成关键路径
→ 权限/网络/旋转/重装失败注入
→ 截图、page source、日志和报告
```

只能使用自己的设备、模拟器和公开练习 App。不要安装、读取或自动化公司 App，也不要导出设备中的公司账号、日志、文件或通知。

Sauce Labs My Demo App 的公开仓库当前未声明许可证。只按官方条款下载 Release 做个人学习，不复制或再分发其源码、二进制和素材；需要完全可控、可改造的长期靶场时优先使用本仓库 `demo-shop`。

### iOS 练习边界

- Simulator 需要 macOS 和 Xcode；
- 真机需要自己的 Apple 开发签名；
- UIKitCatalog 或 My Demo App iOS 适合控件和业务练习；
- WDA 构建、签名和端口问题要单独记录；
- 不能把 Android 的定位、返回键、包管理和权限经验直接套到 iOS。

## 三、可访问性测试

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [axe-core](https://github.com/dequelabs/axe-core) | WCAG 自动规则引擎、DOM 分析和多种测试框架集成 | 在 Playwright/Selenium 中检查常见可访问性问题；理解自动规则无法覆盖全部人工体验 | **推荐选修，L1→L2** |
| [Pa11y](https://github.com/pa11y/pa11y) | 命令行可访问性检查、Dashboard 和 CI 工具 | 为公开/本地站点建立轻量扫描与趋势；补充键盘、读屏和人工检查 | **选修，L1→L2** |

建议作品不是“0 个 axe 问题”，而是：

- 选定 WCAG 等级和页面范围；
- 自动规则 + 键盘导航 + 读屏抽检；
- 对误报和需人工判断项分类；
- 修复后回归并说明自动化覆盖边界。

## 四、视觉回归

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [BackstopJS](https://github.com/garris/BackstopJS) | Puppeteer/Playwright 场景、参考图、差异图、报告和 Docker | 学基线审批、视口矩阵、动态区域遮罩和像素差异治理 | **选修，L2** |
| [reg-suit](https://github.com/reg-viz/reg-suit) | 图片差异、快照发布、PR 比较和插件化存储 | 建立团队化视觉基线审查流程；学习基线不是自动真相 | **前端选修，L2** |
| Playwright Screenshot | Playwright 内置截图断言、阈值、遮罩和多浏览器能力 | 小型项目优先使用现有主线，不必为少量页面额外引入平台 | **主线优先，L1→L2** |

视觉测试常见误区：

- 把字体、时间、广告、动画等动态内容当缺陷；
- 自动接受所有新基线；
- 只看像素差异，不检查业务状态和可访问性；
- 不固定浏览器、字体、时区、DPI 和操作系统。

## 五、AI 驱动 UI 自动化与自愈

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [Midscene.js](https://github.com/web-infra-dev/midscene) | 基于视觉模型的 Web、Android、iOS、HarmonyOS 和桌面 UI 操作，支持自然语言动作、查询、断言及 Playwright 集成 | 对比纯视觉与 DOM 定位；测成功率、成本、延迟、跨版本鲁棒性和错误动作 | **AI 测试前沿选修，L2→L3** |
| [Stagehand](https://github.com/browserbase/stagehand) | 代码与自然语言混合的浏览器操作、结构化抽取、Agent 和动作缓存 | 学已知步骤用代码、未知页面用 AI 的混合策略；验证缓存/自愈是否掩盖缺陷 | **AI 浏览器选修，L2→L3** |
| [Healenium](https://github.com/healenium/healenium-web) | Selenium 定位器自愈、后端服务和修复记录 | 研究自愈机制和错误匹配风险；必须保留原定位器失败证据和人工审批 | **架构阅读，L3** |

AI 工具不能替代确定性 UI 基线。正确实验：

1. 先用 Playwright/Appium 写 20 个可重复任务；
2. 用同一任务测试 AI 工具至少多次运行；
3. 记录成功率、错误动作率、p95、Token/成本、重试和人工接管；
4. 改变文字、布局、DOM 或截图噪声后再次比较；
5. 检查 AI 是否“绕过”预期步骤却错误地判为成功；
6. 只对本地或授权环境运行。

更多项目见[人工智能提效与测试智能体](08-人工智能提效与测试智能体.md)。

## 六、建议形成的作品

### 作品一：Web 关键旅程

- Playwright Python + pytest；
- 登录、搜索、购物车、结算 2～4 条路径；
- API 建数、UI 验证、运行后清理；
- Trace、截图、视频和网络证据；
- Chromium 为主，Firefox/WebKit 做少量兼容 smoke；
- axe-core 检查关键页面。

### 作品二：Android/iOS 共用业务模型

- 首选本仓库 `demo-shop`；也可在上游许可允许的范围内使用 Practice Software Testing 或 Sauce Labs My Demo App；
- 把业务任务、页面对象和平台差异分层；
- Android 真机实际运行；
- iOS 无环境时保留可运行框架、Mock 驱动和明确说明；
- 统计稳定性、失败分类和设备矩阵。

### 作品三：确定性自动化与 AI 自动化对照

- Playwright/Appium 为真值基线；
- Midscene 或 Stagehand 为实验组；
- 对正常版本、文字变化、布局变化和网络异常分别测试；
- 输出 success@1、success@3、错误动作率、p95、成本、可诊断性和剩余风险；
- 不用一次 Demo 成功证明“AI 已经不需要测试脚本”。
