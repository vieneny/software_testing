# 测试基础与接口自动化开源项目

本页服务于功能测试、接口测试、Python/Java 接口自动化、契约测试、Mock 和测试开发。建议先掌握测试设计与 HTTP，再选一套主语言，不要同时建设三套同功能框架。

## 一、测试设计、运行器与生成式测试

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [pytest](https://github.com/pytest-dev/pytest) | 测试发现、fixture、参数化、marker、hook、插件和丰富的自测试 | 建立 Python 自动化工程；学习依赖注入、隔离、插件扩展、失败信息和 CI 结果 | **核心，L1→L3** |
| [JUnit](https://github.com/junit-team/junit-framework) | Jupiter 测试模型、参数化、生命周期、扩展机制、Platform Launcher 和构建工具集成 | 建立 Java 测试主线；理解注解、断言、扩展点、动态测试、并行和可复用测试基础设施 | **Java 核心，L1→L3** |
| [Hypothesis](https://github.com/HypothesisWorks/hypothesis) | Python 属性测试、策略生成、失败样本缩小和状态机测试 | 从“列举几个示例”升级为验证不变量；练习金额、日期、分页、状态序列和 API Schema 边界 | **按岗选修，L2** |
| [Microsoft PICT](https://github.com/microsoft/pict) | Pairwise/组合测试模型与命令行生成器 | 把多条件组合压缩成可解释集合；学习约束、非法组合和覆盖强度，而不是机械生成表格 | **架构阅读/工具选修，L1→L2** |
| [GraphWalker](https://github.com/GraphWalker/graphwalker-project) | 基于图的模型测试、路径生成和 Java 执行生态 | 将登录、订单、退款等状态迁移画成图，自动生成路径，并检查不可达或遗漏状态 | **按岗选修，L2→L3** |
| [Robot Framework](https://github.com/robotframework/robotframework) | 关键字驱动测试运行器、库接口、变量、标签、报告和远程库 | 理解关键字框架、业务可读性与扩展边界；适合需要 Robot 生态的岗位，不替代编程基础 | **市场兼容，L1→L2** |
| [OWASP Web Security Testing Guide](https://github.com/OWASP/wstg) | Web/API 安全测试分类、检查清单和技术说明 | 学习如何把认证、会话、输入、业务逻辑和配置风险转成测试，不把漏洞扫描器当全部安全测试 | **方法参考，L1→L3** |

### 推荐练习

1. 用判定表手写一组优惠规则用例；
2. 分别用 pytest 参数化和 JUnit 参数化表达一小组等价案例，比较生命周期与扩展方式；
3. 用 PICT 生成组合，比较手写用例漏了什么；
4. 用 Hypothesis 验证总价、库存和分页不变量；
5. 用 GraphWalker 表达订单状态，并人为加入一个非法迁移；
6. 把最终高价值案例落入测试运行器，而不是让生成工具直接决定通过标准。

## 二、Python 接口自动化主线

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [Requests](https://github.com/psf/requests) | Session、认证、Cookie、文件、代理、TLS、重定向和异常模型 | 封装小而清晰的 API Client；学习显式超时、连接复用、错误处理、证书和日志脱敏 | **核心，L1→L2** |
| [HTTPX](https://github.com/encode/httpx) | 同步/异步客户端、HTTP/2、ASGI/WSGI 原进程调用和连接池 | 测试异步服务、流式接口和 FastAPI；理解 client 生命周期及与 Requests 的差异 | **按需选修，L2** |
| [Schemathesis](https://github.com/schemathesis/schemathesis) | 从 OpenAPI/GraphQL 生成属性测试、CLI、失败缩小和状态化测试 | 自动探索 Schema 边界、复现最小失败、补充契约覆盖；不能替代业务规则用例 | **测试开发拔高，L2→L3** |
| [Responses](https://github.com/getsentry/responses) | 针对 Requests 的 HTTP Mock、匹配器、回调和请求记录 | 单元测试客户端的超时、重试、错误码和序列化分支；理解进程内 Mock 的边界 | **选修，L2** |
| [pytest-xdist](https://github.com/pytest-dev/pytest-xdist) | pytest 多进程分发、worker 管理和并行策略 | 让测试并行并暴露共享数据、端口、账号和顺序依赖；先保证隔离再追求速度 | **工程化选修，L2** |

推荐组合：

```text
pytest + Requests + JSON Schema
        ↓
Schemathesis 补充契约边界
        ↓
Responses/WireMock 注入失败
        ↓
Testcontainers 验证真实依赖
```

## 三、Java、CLI 与声明式接口测试

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [REST Assured](https://github.com/rest-assured/rest-assured) | Java DSL、请求/响应规范、JSON/XML 断言和认证支持 | 在 Java/JUnit 项目中写可读 API 测试；学习 specification 复用和 Hamcrest 断言 | **Java 岗主线，L1→L2** |
| [Karate](https://github.com/karatelabs/karate) | API DSL、Mock、数据驱动、并行执行，以及 UI/性能扩展 | 快速构建 Java 生态中的声明式 API 回归；比较 DSL 可读性与复杂逻辑维护成本 | **按团队选修，L1→L2** |
| [Hurl](https://github.com/Orange-OpenSource/hurl) | 纯文本 HTTP 请求、捕获、JSONPath/XPath 断言、轮询和 JUnit/HTML 报告 | 用接近 curl 的文本保存 REST、GraphQL、SOAP 流程；适合轻量 smoke 和 CI 契约检查 | **轻量选修，L1** |
| [Bruno](https://github.com/usebruno/bruno) | Git 友好的 API 客户端、文本集合、环境和 CLI | 学习团队如何版本化接口探索资料；与 Postman 集合做可审查性和协作比较 | **接口探索选修，L0→L1** |
| [Newman](https://github.com/postmanlabs/newman) | Postman Collection v2.1 命令行运行器、报告器和 CI 接口 | 接手存量 Postman 流水线；新项目同时核对 Postman CLI 和集合格式的当前路线 | **存量兼容，L1** |

不要仅因为 DSL 更短就选择框架。选型时比较：

- 能否表达鉴权、幂等、异步任务和复杂数据准备；
- 调试失败是否方便；
- 与团队语言、IDE、CI、报告和依赖治理是否一致；
- 是否能写单元测试验证自定义扩展；
- 测试数据和密钥是否能安全分层。

## 四、OpenAPI、Schema 与契约

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [OpenAPI Specification](https://github.com/OAI/OpenAPI-Specification) | HTTP API 的机器可读描述规范、Schema 和演进记录 | 学路径、参数、鉴权、响应、示例和可空语义；把契约当可验证接口而非装饰文档 | **核心规范，L1→L2** |
| [JSON Schema](https://github.com/json-schema-org/json-schema-spec) | JSON 数据结构、类型、组合、条件和引用规范 | 验证响应结构和配置；理解“结构合法”不等于“业务正确” | **核心规范，L1→L2** |
| [Pact Python](https://github.com/pact-foundation/pact-python) | Python 消费者契约、Provider 验证和 Pact Broker 流程 | 模拟消费者期望、验证提供者兼容性、理解版本发布和 can-i-deploy 思想 | **契约专题，L2→L3** |
| [Pact JVM](https://github.com/pact-foundation/pact-jvm) | Java/JVM Pact DSL、JUnit 集成和 Provider 验证 | 为 Java 微服务建立消费者驱动契约；学习跨团队独立发布的质量门禁 | **Java 契约专题，L2→L3** |
| [Prism](https://github.com/stoplightio/prism) | 基于 OpenAPI 的 Mock Server、请求校验和响应生成 | 契约先行开发、前后端并行、验证请求是否符合规范 | **选修，L2** |

契约测试适合多服务、独立发布和接口兼容风险明显的系统。小型单体项目不必为了“先进”强行引入 Broker。

## 五、Mock、服务虚拟化与真实依赖

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [WireMock](https://github.com/wiremock/wiremock) | HTTP Stub、匹配器、场景状态、延迟、故障、录制和扩展 | 模拟第三方 API、SSE/流式异常、429、超时和坏响应；建立 Stub 生命周期 | **核心专题，L2** |
| [MockServer](https://github.com/mock-server/mockserver) | HTTP/HTTPS Mock、Expectation、Proxy、回调和请求验证 | 在 JVM 或容器中搭建复杂服务替身；学习期望、验证、重置和隔离 | **Java 选修，L2** |
| [Mockoon](https://github.com/mockoon/mockoon) | 桌面/CLI Mock API、路由、模板、场景和环境文件 | 让小白快速构建本地 API；随后把配置纳入版本控制和 CI | **入门选修，L0→L1** |
| [Testcontainers Python](https://github.com/testcontainers/testcontainers-python) | pytest 中启动 PostgreSQL、Redis、Kafka 等容器 | 用临时真实依赖做集成测试；掌握就绪、隔离、镜像固定和清理 | **测试开发核心，L2→L3** |
| [Testcontainers Java](https://github.com/testcontainers/testcontainers-java) | JUnit 与 Java 生态的容器化真实依赖 | 对数据库、消息队列、浏览器和服务做可重复集成测试 | **Java 测试开发核心，L2→L3** |
| [Toxiproxy](https://github.com/Shopify/toxiproxy) | 在 TCP 链路注入延迟、断连、限带宽和抖动 | 验证超时、重试、熔断、连接池和恢复；不要只 Mock 一个 500 | **韧性专题，L2→L3** |

选择原则：

```text
函数/客户端分支          → Responses 等进程内 Mock
独立 HTTP 边界          → WireMock / MockServer / Prism
跨团队接口兼容          → Pact
数据库/队列真实行为     → Testcontainers
网络抖动、断连和恢复     → Toxiproxy
```

## 六、建议形成的作品

### 作品一：可维护的接口自动化工程

- pytest + Requests；
- 配置、密钥、测试数据和日志分层；
- 鉴权、CRUD、幂等、分页、并发和错误映射；
- JSON Schema 与业务断言；
- JUnit/Allure 报告和 CI；
- 对 `demo-shop` 运行，不依赖公司系统。

### 作品二：契约与失败注入实验

- OpenAPI + Schemathesis；
- WireMock 模拟 429、500、超时、坏 JSON 和断流；
- Testcontainers 启动真实数据库；
- Toxiproxy 注入网络故障；
- 报告区分客户端缺陷、契约缺陷、服务端缺陷和环境故障。

### 作品三：Python 与 Java 框架对比

使用同一公开 API 分别完成：

- `pytest + Requests`；
- `JUnit + REST Assured`；
- 可选 Hurl 或 Karate。

比较代码量、可读性、调试、并行、报告、团队技能和维护成本。结论应基于实验，不写“某工具绝对最好”。
