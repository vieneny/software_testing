# 人工智能应用与智能体开发开源项目

本页面向完成测试主线后，希望转向 AI 应用开发、RAG、Agent 或评测平台开发的学习者。更完整的 24 周路线、课程拆解和作品验收见[测试转人工智能开发模块](../../docs/10-测试转人工智能开发/README.md)。

最适合测试工程师的切入点不是从零预训练大模型，而是开发“可测试、可评测、可观测、权限受控”的 AI 应用。

## 一、系统课程与样例

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [AI Agents for Beginners](https://github.com/microsoft/ai-agents-for-beginners) | Agent 概念、工具、RAG、规划、多 Agent、MCP/A2A、记忆、Computer Use、部署和安全课程 | 建立 Agent 全景和设计模式，判断什么时候不该用 Agent | **入门课程，L1→L2** |
| [Generative AI for Beginners](https://github.com/microsoft/generative-ai-for-beginners) | 生成式 AI、Prompt、RAG、Function Calling、UX、安全和应用示例 | 补 LLM 应用基础，不把框架 API 当原理 | **基础课程，L1→L2** |
| [OpenAI Cookbook](https://github.com/openai/openai-cookbook) | API、结构化输出、工具、RAG、评测和应用样例 | 阅读可运行模式并迁移到自己的 Provider/Mock；示例版本要重新核对 | **样例参考，L2** |
| [Spring AI Examples](https://github.com/spring-projects/spring-ai-examples) | Spring AI 官方场景和集成参考；当前 `main` 可能使用 Spring Boot 4 与 Spring AI 2.0 Snapshot | 按自己选定的稳定 Spring AI 版本寻找匹配的 tag、分支或 commit，再加入测试和异常治理 | **官方参考样例，L2；不要直接照抄 main** |

课程和示例用于理解，不是毕业作品。最终项目必须有自己的需求、架构、测试、评测和复盘。Spring AI Examples 仓库根目录当前没有明确的 `LICENSE` 文件，因此本仓库只链接和讲解，不复制、打包或再分发其中代码；使用前再次核对仓库状态。

## 二、Java AI 应用主线

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [Spring AI](https://github.com/spring-projects/spring-ai) | 模型 API、流式响应、结构化输出、Advisor、Memory、RAG、工具、MCP 和向量库集成 | 开发 Java REST AI 服务；学 Spring 配置、BOM、异常、超时、结构化对象和企业集成 | **Java 主线，L2→L3** |
| [LangChain4j](https://github.com/langchain4j/langchain4j) | JVM 模型/向量库抽象、AI Services、RAG、工具、Agent 和 MCP | 在 Spring/Quarkus 中构建 AI 应用；与 Spring AI 做一次小型对照 | **Java 备选，L2→L3** |
| [LangChain4j Examples](https://github.com/langchain4j/langchain4j-examples) | 官方集成和用法示例 | 对照当前版本理解 AI Services、RAG 和工具；不混用旧依赖 | **样例参考，L2** |
| [Spring AI Alibaba](https://github.com/alibaba/spring-ai-alibaba) | Agent Framework/Graph、顺序/并行/路由/循环、上下文、HITL、MCP、A2A、Admin 和观测 | 学国内 Java Agent 技术栈、状态图、多 Agent 和人工审批 | **Java Agent 进阶，L3** |

### Java 选型

- Spring Boot/企业 Java 岗：Spring AI 主学；
- Quarkus/Jakarta 或偏库式集成：LangChain4j 可作为主线；
- 国内 Java Agent/Graph 岗：基础稳定后学习 Spring AI Alibaba；
- 不同时完整重写三套相同项目。

Spring AI 的主分支、稳定分支与 Spring Boot 版本线可能不同。创建项目时按官方兼容矩阵选稳定版本并使用 BOM，不能混抄不同大版本教程。当前学习时尤其要区分 Spring AI 1.1.x + Spring Boot 3.5 与 Spring AI 2.x + Spring Boot 4 两条版本线；示例仓库的 `main` 可能使用 Snapshot，不能自动等同于生产基线。

## 三、Python Agent 与服务主线

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [FastAPI](https://github.com/fastapi/fastapi) | 类型化 API、依赖注入、OpenAPI、异步、WebSocket 和测试支持 | 给 RAG/Agent 提供稳定后端；学校验、错误、认证、流式和可测试性 | **Python 后端核心，L1→L3** |
| [PydanticAI](https://github.com/pydantic/pydantic-ai) | 类型安全 Agent、依赖注入、结构化输出、工具、MCP、模型适配、OTel 和 eval | 用熟悉的 Pydantic/FastAPI 风格开发可验证 Agent | **Python 推荐，L2→L3** |
| [OpenAI Agents SDK](https://github.com/openai/openai-agents-python) | Agent、tool、handoff、guardrail、session、MCP、tracing、Realtime 和 sandbox 示例 | 用较少抽象理解 Agent 原语、交接、约束和 Trace | **Agent 基础选修，L2→L3** |
| [LangGraph](https://github.com/langchain-ai/langgraph) | 状态图、持久化、checkpoint、暂停恢复、人机协同、记忆和长任务 | 构建确定性、可恢复、有上限的 Agent 工作流 | **Python Agent 主线，L3** |
| [Google ADK](https://github.com/google/adk-python) | Code-first Agent、工具、工作流、评测和部署 | 学另一套生产 Agent 组织方式和内置评测；按目标岗位选修 | **生态选修，L3** |
| [Microsoft Agent Framework](https://github.com/microsoft/agent-framework) | Python/.NET Agent、顺序/并发/handoff/群组工作流、checkpoint、HITL 和 OTel | 学生产型多 Agent、Middleware、持久化和治理 | **企业生态选修，L3→L4** |
| [AutoGen](https://github.com/microsoft/autogen) | 历史多 Agent、AgentChat、消息路由和 Studio 生态 | 阅读多 Agent 设计与迁移；官方已进入维护模式，新项目优先 Microsoft Agent Framework | **迁移/历史参考** |

Google ADK 官方 `main` 已进入 2.0 路线，Agent API、事件模型和 Session Schema 与 1.x 存在破坏性变化。学习项目必须固定 1.x 或 2.x 之一，并把教程、依赖和示例保持在同一大版本。

初学顺序：

```text
FastAPI 普通接口
→ Pydantic/结构化输出
→ 单 Agent + 两个只读工具
→ LangGraph 状态与人工审批
→ MCP
→ Trace、评测、安全和性能
→ 目标岗位需要时再做多 Agent
```

## 四、RAG 与编排框架

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [LangChain](https://github.com/langchain-ai/langchain) | 模型、Embedding、Retriever、工具、Agent 和大量集成 | 快速组合 LLM 应用并理解统一抽象；复杂 Agent 转 LangGraph | **生态基础，L2** |
| [LlamaIndex](https://github.com/run-llama/llama_index) | 数据连接器、解析、索引、检索、重排、查询引擎和文档 Agent | 学文档型 RAG、引用、检索和数据管道 | **RAG 推荐，L2→L3** |
| [Haystack](https://github.com/deepset-ai/haystack) | 显式组件、Pipeline、检索、路由、Agent 和生产编排 | 学可组合、可测试的 RAG Pipeline；适合与 LlamaIndex 对照 | **RAG 选修，L2→L3** |

RAG 框架不会自动解决：

- 文档版权与数据边界；
- 解析、去重、切块和版本；
- 召回、重排和权限过滤；
- 冲突、过期和无答案；
- 引用真实性；
- Prompt Injection；
- 评测集和线上反馈。

## 六、可视化工作流与完整产品

| 项目 | 里面有什么 | 可以做什么、学什么 | 许可与定位 |
|---|---|---|---|

| [Langflow](https://github.com/langflow-ai/langflow) | 可视化组件、Playground、RAG/Agent、Python 自定义组件、API 和 MCP | 快速做可演示原型，理解节点怎样映射到代码 | **快速原型，L2→L3** |

Dify 采用修改版 Apache 2.0 许可：提供多租户服务需要取得书面商业许可，前端 Logo 和版权信息不能自行删除或修改。LiteLLM 的开源核心与 `enterprise` 路径、Langfuse 的开源核心与 `ee` 路径也存在不同许可边界；任何二次开发、分发或托管都必须读当前仓库许可证，而不是根据项目名称推断。Coze Studio 仅建议在本地或隔离环境学习，默认配置不能直接暴露公网。

低代码平台适合：

- 产品原型；
- 流程与失败模式观察；
- 平台测试；
- API 集成；
- 架构阅读。

它不替代编程、数据库、权限、测试、评测和部署能力。

```text
→ 大规模分布式岗位再研究 Milvus
```

## 九、评测与可观测性组合

开发作品的核心组合是：

- pytest/JUnit 单元测试；
- WireMock 或 Testcontainers 集成测试；
- Promptfoo、DeepEval 或 Ragas 中一种与项目目标匹配的质量评测；
- OpenTelemetry 加 Phoenix 或 Langfuse 中一种可观测方案。

再按风险选择 AIPerf/k6 性能测试，以及 garak/PyRIT 的本地小范围安全测试。初学项目不要求一次安装全部工具；先形成“功能正确 + 一种质量评测 + 一条可诊断 Trace”的闭环。

相关项目详见：

- [人工智能测试与模型评测](06-人工智能测试与模型评测.md)；
- [智能体测试安全与评测基准](07-智能体测试安全与评测基准.md)。

## 十、推荐毕业项目

### 公开软件测试知识助手

```text
公开测试文档
→ 清洗/切块/Embedding
→ pgvector/Qdrant
→ Spring AI（Java）或 FastAPI + PydanticAI/LlamaIndex（Python）
→ 有引用的 RAG
→ Ragas/DeepEval
→ OTel + Phoenix/Langfuse
```

验收：Recall@5、引用正确、无答案拒答、冲突资料、注入、安全、延迟和成本。

### 合成缺陷分诊 Agent

```text
合成缺陷
→ 结构化分类
→ 检索公开知识
→ MCP 只读工具
→ 人工批准
→ 写入本地模拟工单
→ Agent 终态评测
```

验收：工具/参数、任务成功、步骤上限、重复写、恢复、越权、注入和 Trace。

## 十一、不要作为新主线的项目

- AutoGen：进入维护模式，阅读历史设计，新项目优先 Microsoft Agent Framework；
- Semantic Kernel Agent：官方生态正在向 Microsoft Agent Framework 演进，按存量/.NET 需求再学；
- 同时学习五个 Agent 框架；
- 同时部署多个向量数据库；
- 没有最大步数、时间、Token 和工具上限的自由循环；
- 能任意执行 shell、读取本机或访问真实系统的演示 Agent；
- 只有聊天界面、没有评测和测试的“AI 项目”。
