# 智能体测试、安全与评测基准开源项目

Agent 与普通聊天应用不同：它会选择工具、修改环境、记忆状态、循环、恢复，甚至影响外部系统。Agent 测试必须同时检查：

- 任务是否完成；
- 工具选择与参数是否正确；
- 环境最终状态是否正确；
- 轨迹是否合规、高效、可解释；
- 多次运行是否稳定；
- 失败、超时、取消和恢复是否安全；
- Prompt Injection、越权和副作用是否被阻断。

## 一、工具、环境和任务成功基准

| 项目 | 里面有什么 | 可以做什么、学什么 | 定位 |
|---|---|---|---|
| [τ³-bench](https://github.com/sierra-research/tau2-bench) | 客服 Agent 仿真、领域政策、工具、任务、用户模拟、文本/语音和知识检索场景 | 学政策遵循、用户-Agent-工具交互、终态判分、多次运行和环境重置 | **Agent 测试主线参考，L3→L4** |
| [BFCL](https://github.com/ShishirPatil/gorilla/tree/main/berkeley-function-call-leaderboard) | 单/多/并行函数调用、拒绝调用、多轮、多步骤、状态、Live 和 Agentic 任务 | 学工具选择、参数 Schema、格式、执行结果和状态化评分 | **工具调用主线，L3** |
| [AgentBench](https://github.com/THUDM/AgentBench) | OS、数据库、知识图谱、ALFWorld、WebShop 等多环境，当前包含 Function Calling/容器化路线 | 学跨环境任务、轨迹、成功率和容器执行；资源消耗较高 | **综合 Benchmark，L4** |
| [BrowserGym](https://github.com/ServiceNow/BrowserGym) | 基于 Playwright/Gym 的 Web Agent 环境，集成 MiniWoB、WebArena、VisualWebArena、WorkArena 等 | 学网页任务、动作空间、观察、奖励、复位、录像和自定义环境 | **Web Agent 主线，L3→L4** |
| [AgentLab](https://github.com/ServiceNow/AgentLab) | 可扩展 Agent 实验、并行 Benchmark、结果和复现基础设施 | 学如何在 BrowserGym 上开发、测试、比较 Agent；新实验优先于直接拼旧 WebArena 脚本 | **Web Agent 平台，L4** |
| [OSWorld](https://github.com/xlang-ai/OSWorld) | Windows/Linux/macOS 桌面任务、虚拟机/云环境、状态恢复、多模态观察和自动判分 | 学 Computer Use Agent 的跨应用任务、隔离、截图、动作、恢复和安全 | **桌面 Agent 高阶，L4→L5** |
| [SWE-bench](https://github.com/SWE-bench/SWE-bench) | 真实 GitHub Issue、代码仓库、补丁、Docker Harness、Verified 和多模态版本 | 学 Coding Agent 任务构造、容器隔离、补丁验收和可复现评测 | **Coding Agent 高阶，L4→L5** |

### τ-bench 2026 状态

- 当前官方仓库名仍是 `sierra-research/tau2-bench`；
- 项目内容已经升级到 **τ³-bench**；
- 新版加入知识检索、全双工语音和大量任务修正；
- 旧结果可能因任务修复不可直接比较；
- 学习文档必须固定 release，并保存任务和评分器版本。

### WebArena 路线

[WebArena](https://github.com/web-arena-x/webarena) 仍适合阅读自托管网站、任务和端到端判分设计。新实验优先从 BrowserGym/AgentLab 进入，因为它们提供更统一的环境、Agent 和评测编排。不要把公共网页当 Web Agent 靶场。

个人作品不需要同时部署六个平台。先在 Phoenix 或 Langfuse 二选一完成：

1. 一次完整 Agent Trace；
2. Prompt、模型、工具和环境版本；
3. 错误工具调用定位；
4. 数据集与离线实验；
5. 线上失败转回归样本；
6. 脱敏、采样、权限和保留期。

## 四、Agent 测试模型

### 分层 Oracle

| 层次 | 检查内容 | 示例 |
|---|---|---|
| 输入 | Schema、身份、权限、恶意内容 | 用户没有写权限；工具参数必须满足 JSON Schema |
| 计划 | 步数、循环、预算、策略 | 最大 8 步；禁止绕过人工审批 |
| 工具 | 选择、参数、顺序、超时 | 应调用查询工具，不应调用删除工具 |
| 环境 | 最终状态和副作用 | 模拟工单只创建一次；余额未被错误修改 |
| 输出 | 事实、格式、引用和解释 | 结果与环境一致；无虚构执行成功 |
| 恢复 | 重试、checkpoint、取消和幂等 | 第 3 步失败后可恢复；重复请求不重复写 |
| 安全 | 注入、越权、泄漏、恶意工具返回 | 文档中的指令不能改变系统目标 |
| 统计 | 多次运行、稳定性、成本和延迟 | success@1、success@3、步骤分布和 p95 |

### 可控 Mock 环境必须有

- 固定初始数据库；
- `reset()`；
- 只读和写入工具分离；
- Schema 与权限；
- 调用日志与唯一 id；
- 失败、延迟、超时和脏结果注入；
- 最大调用次数、时间和 Token；
- 幂等键和副作用审计；
- 合成 canary secret，用于检测泄漏；
- 任务结束后计算最终状态，不只检查最后一句话。

## 五、推荐实战

### 实战一：工具调用评测

- 10 个只读工具和 3 个写工具；
- 50 条公开/合成任务；
- 正确工具、参数、顺序、拒绝调用和终态评分；
- 参考 BFCL 的可执行评分思想；
- 比较两个模型和两个 Prompt；
- 输出工具混淆矩阵。

### 实战二：客服 Agent

- 参考 τ³-bench 的 policy + tools + tasks + user simulator；
- 构造虚构零售/预订领域；
- 正常、冲突、越权、取消和升级人工任务；
- 每条任务运行至少多次；
- 输出任务成功、政策遵循、步骤、成本和失败类型。

### 实战三：间接 Prompt Injection

- 本地 Mock 邮件/文档/网页；
- 正常用户任务与恶意外部内容；
- AgentDojo/Promptfoo/PyRIT 思路；
- 比较无防护、工具过滤、内容隔离和人工审批；
- 同时报正常效用和攻击成功率；
- 不使用真实邮件、公司文档或第三方系统。

### 实战四：Web/Computer Use Agent

- 本地 TodoMVC 或 `demo-shop`；
- BrowserGym/Playwright 环境可重置；
- 明确任务终态和动作上限；
- 记录截图、DOM/可访问性树、动作和视频；
- 测弹窗、网络慢、布局变化和恶意页面内容；
- 只有在隔离虚拟机中才研究 OSWorld 类任务。

## 六、资源和安全分级

- **个人电脑可做**：自建 Mock 工具、Promptfoo、少量 DeepEval、AgentDojo 小样本、Phoenix 本地；
- **需要 Docker/较多资源**：τ³-bench、BrowserGym、AgentBench 部分环境；
- **需要虚拟机/大量磁盘**：OSWorld、SWE-bench；
- **可能产生模型费用或有害内容**：多轮 PyRIT、garak 全量、HarmBench；
- **只在有授权时做**：任何真实工具写入、公共网页 Agent、外部邮箱/工单/云资源。

先完成最小安全闭环，再扩任务数量。不能为了跑 Benchmark 给 Agent 任意 shell、本机目录、公司账号或云权限。
