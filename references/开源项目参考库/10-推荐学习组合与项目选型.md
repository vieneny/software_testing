# 推荐学习组合与开源项目选型

这个目录的目标不是让学习者安装所有工具，而是从开源生态中选出一条能完成、能解释、能复现、能用于求职的主线。

## 一、按人群选择

### 计算机专业小白

```text
demo-shop
→ pytest + Requests
→ Playwright Python
→ Appium Android
→ k6
→ Allure + 简单 CI
```

暂不学习：Pact Broker、Kubernetes Chaos、复杂评测平台、多 Agent、GPU 推理。

毕业证据：

- 一份风险与用例设计；
- 一套接口自动化；
- 2～4 条 Web 关键旅程；
- 一条 Android 真机路径；
- 一份小规模性能报告；
- 一条可运行 CI。

### 功能测试转自动化

```text
测试设计
→ pytest fixture/参数化
→ OpenAPI/Schema
→ WireMock
→ Playwright
→ Appium
→ 失败诊断与 CI
```

重点不是“会调用 API”，而是数据、环境、隔离、稳定性、报告和维护。

### 自动化测试/测试开发拔高

```text
Schemathesis
→ Pact
→ Testcontainers + Toxiproxy
→ Playwright 并行与 Trace
→ k6/JMeter + OpenTelemetry
→ ReportPortal/测试平台
```

毕业证据：

- 契约和集成测试分层；
- 可重置环境；
- 网络故障和恢复；
- 性能与服务端证据；
- 可执行质量门禁；
- 一份工具选型报告。

### AI 应用测试

```text
普通 API/自动化底座
→ Promptfoo 或 DeepEval
→ Ragas
→ Phoenix 或 Langfuse
→ garak/Promptfoo Red Team
→ AIPerf
```

毕业证据：黄金集、RAG 分层指标、安全切片、Trace、质量-延迟-成本报告和 CI 阈值。

### 模型与多模态评测

```text
数据与统计基础
→ Lighteval/lm-eval
→ Inspect AI
→ VLMEvalKit/LMMS-Eval
→ 人工标注与 Judge 校准
```

毕业证据：版本化任务、逐样本结果、切片、置信度/方差、错误分类和评测限制。

### Agent 测试

```text
工具 Schema 与 Mock 环境
→ BFCL 思路
→ τ³-bench/BrowserGym
→ AgentDojo
→ OTel + Phoenix/Langfuse
→ PyRIT/garak
```

毕业证据：终态 Oracle、工具/参数、轨迹、重复运行、越权/注入、恢复和副作用审计。

### 评测/测试平台开发

```text
FastAPI/Spring Boot
→ 数据集与任务 API
→ 异步执行器
→ Inspect AI/Promptfoo Adapter
→ PostgreSQL/对象存储

```

毕业证据：可插拔 Provider/Grader、任务队列、版本比较、失败重试、审计和质量门禁。

### 测试转 AI 应用/Agent 开发

## 二、六套作品组合

### 组合一：接口自动化质量工程

| 层次 | 项目 |
|---|---|
| 目标 | 本地 `demo-shop` 或 Restful Booker |
| 功能/接口 | pytest + Requests |
| 契约 | OpenAPI + JSON Schema + Schemathesis |
| 依赖 | WireMock + Testcontainers |
| 韧性 | Toxiproxy |
| 结果 | Allure + CI |

验收：

- 鉴权、CRUD、边界、幂等、分页、并发和错误；
- 正常/异常/超时/坏响应；
- 测试可乱序、重复和并行；
- 日志脱敏；
- 故意注入缺陷时测试会失败。

### 组合二：Web 与移动跨端商城

| 层次 | 项目 |
|---|---|
| 目标 | 本仓库 `demo-shop`；按上游许可边界可选 Practice Software Testing 或 My Demo App |
| API | pytest + Requests |
| Web | Playwright |
| Android/iOS | Appium + UiAutomator2/XCUITest |
| 可访问性 | axe-core |
| 结果 | Allure + CI |

验收：

- API 建数、UI 验证和清理；
- Web/Android/iOS 共用业务任务而非共用所有定位代码；
- Android 真机实际运行；
- Practice Software Testing 是受限许可练习项目；My Demo App 仓库未声明许可证，只做许可范围内的个人练习，不复制、公开托管或再分发；
- iOS 有环境则运行，无环境则明确 Mock/Simulator 范围；
- 失败有 Trace、截图、page source 和设备日志。

### 组合三：可观测性能与韧性

| 层次 | 项目 |
|---|---|
| 目标 | QuickPizza 或 Petclinic |
| 负载 | k6；JMeter 做对照 |
| 指标 | Prometheus + Grafana |
| Trace | OpenTelemetry + Jaeger |
| 故障 | Toxiproxy；进阶 Chaos Mesh |

验收：

- 业务负载模型；
- p95、错误、吞吐和资源；
- 找到拐点并有服务端证据；
- 验证超时、重试、降级和恢复；
- 写清实验环境，结果不外推生产。

### 组合四：RAG 质量回归平台

| 层次 | 项目 |
|---|---|
| 应用 | FastAPI/Spring AI + pgvector |
| 数据 | 公开测试文档和合成问题 |
| 评测 | DeepEval + Ragas |
| 回归 | Promptfoo |
| 观测 | Phoenix 或 Langfuse |
| 安全/性能 | garak 小样本 + AIPerf |

验收：

- 数据版本、解析、切块和权限；
- Recall@k、引用、忠实度、拒答；
- 正常/无答案/冲突/过期/注入切片；
- Judge 与人工标签校准；
- 质量、延迟、Token 和成本联合门禁。

### 组合五：Agent 全链路测试

| 层次 | 项目 |
|---|---|
| Agent | LangGraph 或 Spring AI Alibaba |
| 工具 | MCP 只读工具 + 本地 Mock 写工具 |
| 评测思想 | BFCL + τ³-bench |
| 安全 | AgentDojo + Promptfoo/PyRIT |
| 观测 | OpenTelemetry + Phoenix/Langfuse |

验收：

- 工具、参数、顺序和终态；
- 最大步数、时间、Token 和调用次数；
- checkpoint、恢复、取消和幂等；
- 人工审批前不能写；
- 正常效用与攻击成功率同时报告；
- 多次运行而不是一次演示。

### 组合六：AI 测试提效实验

| 层次 | 项目 |
|---|---|
| 用例生成 | 任一受控模型 + 人工基准 |
| UI | Playwright 基线 + Midscene/Stagehand 实验 |
| 代码 | Aider 或 OpenHands |
| PR | 自定义 AI check；可用社区维护的 PR-Agent 做历史对照 |
| 分诊 | 合成失败集 + 人工真值 |

验收：

- 采纳率、正确率、误报、漏报和返工；
- 有效缺陷而非生成数量；
- 成功率、p95、成本和人工接管；
- 所有 AI 生成代码经过 lint/test/diff 审查；
- 只有公开/合成内容。

## 三、项目选型评分卡

每项 0～2 分：

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 岗位适配 | 与目标岗位无关 | 可迁移概念 | JD/作品直接需要 |
| 方法价值 | 只提供界面/包装 | 有部分通用方法 | 能学习核心协议/模型/架构 |
| 可运行性 | 无法本地运行 | 条件较多 | 有稳定最小示例 |
| 可测试性 | 无测试/不可注入失败 | 可观察部分行为 | 有测试、Mock、日志和 CI |
| 维护状态 | 归档/无迁移说明 | 维护信号一般 | release、文档和 issue 清晰 |
| 许可证 | 不明或与用途冲突 | 有附加限制 | 清晰且适合当前用途 |
| 资源成本 | 当前设备不可承受 | 需较多配置 | 个人电脑可完成最小实验 |
| 数据安全 | 必须上传敏感数据 | 可配置本地/脱敏 | 完全公开/合成和本地 |
| 作品差异 | 只能复制 Demo | 能小幅扩展 | 能形成完整问题与证据 |
| 学习重叠 | 与主线重复 | 有部分新能力 | 填补明确能力缺口 |

建议：

- **16～20 分**：可进入当前主线；
- **11～15 分**：按岗选修；
- **6～10 分**：只做架构阅读或小实验；
- **0～5 分**：暂不投入。

评分不是永久结论。版本、许可证、岗位和个人目标变化后重新评估。

## 五、贡献开源项目的路径

1. 先完整跑通官方最小示例和测试；
2. 阅读 `CONTRIBUTING.md`、`CODE_OF_CONDUCT.md` 和 `SECURITY.md`；
3. 从文档、示例或小型可复现 Bug 开始；
4. 先搜索 Issue/PR，避免重复；
5. 添加最小测试证明问题和修复；
6. 安全问题走私下披露；
7. 遵守 DCO/CLA 和许可证。

一次被合并的文档或测试贡献，比收藏一百个仓库更能证明工程能力。

## 六、季度维护清单

普通测试生态每季度、AI/Agent 生态每月轻量核对：

- 官方仓库是否迁移或归档；
- 默认分支、稳定 release 和安装入口；
- 运行时与主版本要求；
- 许可证或企业版边界；
- deprecated、maintenance mode 和继任项目；
- 官方示例是否还能运行；
- 本仓库链接、命令和定位是否需要更新；
- 是否仍与 BOSS 当前岗位能力匹配；
- 是否产生新的云端数据上传、遥测或账号要求。

发现变化时，不只替换链接，还要更新学习定位。例如：

- PyRIT 从 `Azure/PyRIT` 迁到 `microsoft/PyRIT`；
- Ragas 当前仓库为 `vibrantlabsai/ragas`；
- τ-bench 当前内容进入 τ³-bench；
- Giskard v3 重写且 v2 不再积极维护；
- HELM 与 AutoGen 进入维护模式；
- GenAI-Perf 不再作为新性能主线；
- 新项目优先 Microsoft Agent Framework 而非 AutoGen。

## 七、最终原则

- 一条主线做到能设计、运行、失败、诊断和迁移；
- 工具数量不等于能力；
- Star 不等于维护质量或岗位适配；
- Demo 成功不等于生产可用；
- AI 评分不等于人工真值；
- 本地部署不等于数据绝不会外发；
- GitHub 可见不等于许可证无限制；
