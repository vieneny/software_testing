# 社区问答系统功能与测试清单

这份清单既是产品路线图，也是测试训练题库。状态说明：

- ✅ 已实现：可以直接运行和测试；
- 🟡 已留接口或基础设施：需要完成业务实现；
- ⬜ 规划：适合作为后续完整迭代。

## 1. 当前基线

| 领域 | 能力 | 状态 | 建议验证 |
|---|---|---:|---|
| 系统 | 健康检查和数据库探活 | ✅ | 正常、数据库断开、恢复、响应时间 |
| 问题 | 创建问题 | ✅ | 必填、长度、Unicode、标签上限、重复提交 |
| 问题 | 列表分页与倒序 | ✅ | page/page_size 边界、空页、稳定排序 |
| 问题 | 标题和正文关键词搜索 | ✅ | 大小写、空格、中文、通配符、恶意输入 |
| 问题 | 标签过滤 | ✅ | 大小写归一、JSON 查询、组合条件 |
| 问题 | 详情与浏览量 | ✅ | 不存在、连续访问、并发丢更新 |
| 问题 | 关闭与重新开放 | ✅ | 重复关闭、关闭后回答 409、重新开放 |
| 回答 | 发布与详情展示 | ✅ | 外键、长度、排序、问题不存在 |
| 回答 | 采纳、切换与取消采纳 | ✅ | 回答归属、单选约束、事务 |
| 幂等 | 问题和回答安全重试 | ✅ | 原样重放、异内容冲突、唯一约束 |
| 投票 | 赞成、反对、切换和 MySQL 行锁串行化 | ✅ | 重复票、改票、唯一约束、并发一致性 |
| AI | 摘要、严格契约与 25 秒总预算 | ✅ | v1、响应 ID、截断、非法 2xx→502、默认/覆盖超时、慢响应 |
| 错误 | 统一 404/409/422/502 与关联 ID | ✅ | code、request_id、兼容 trace_id、非法头不回显 |
| 前端 | 列表、搜索和分页 | ✅ | 加载、空态、错误态、移动端 |
| 前端 | 发布、详情、回答、投票、AI | ✅ | 表单校验、重复提交、上游失败 |
| 数据库 | 双模式、LONGTEXT/TEXT、UTC 响应映射 | ✅ | 大型 Unicode、迁移、持久化后时间必须带 Z/+00:00 |
| 缓存 | Redis 编排和配置 | 🟡 | 未接业务，作为第二阶段任务 |

## 2. 第二阶段：用户与权限

| 需求 | 状态 | 验收重点 | 测试重点 |
|---|---:|---|---|
| 注册、登录、刷新 Token、退出 | ⬜ | 密码哈希、短期访问令牌、令牌轮换 | 暴力破解、重放、过期、并发刷新 |
| 用户资料和头像 | ⬜ | 默认隐私、文件类型和大小 | 越权、恶意文件、对象存储故障 |
| 角色：用户/版主/管理员 | ⬜ | 最小权限、后台接口隔离 | 水平/垂直越权、角色变化缓存 |
| 封禁与解封 | ⬜ | 有期限、有原因、可审计 | 边界时间、已登录会话、申诉 |
| 设备和登录历史 | ⬜ | 可撤销单设备会话 | 伪造设备、日志脱敏 |

推荐实现：OIDC 或 FastAPI OAuth2；不要在练习项目中自创不安全加密算法。

## 5. AI 能力路线

| 能力 | 状态 | 必测维度 |
|---|---:|---|
| 问题摘要和风险提示 | ✅ | 相关性、事实性、空回答、失败降级 |
| 标题与标签建议 | ⬜ | 格式约束、稳定性、无关标签 |
| 相似问题与重复检测 | ⬜ | Top-K、阈值、误报/漏报、向量漂移 |
| 回答质量辅助检查 | ⬜ | 引用、幻觉、偏见、不可替代人工 |
| 内容审核建议 | ⬜ | 只建议不自动处罚、误杀、可申诉 |
| RAG 检索公开知识库 | ⬜ | 召回、上下文忠实、引用、权限过滤 |
| AI 搜索问答 | ⬜ | 多轮、拒答、提示词注入、成本 |
| 测试用例辅助生成 | ⬜ | 需求覆盖、可执行性、去重、人工确认 |

AI 验收不能只断言字符串非空。建议建立 50～100 条完全合成的黄金数据集，至少计算：

- JSON/Schema 合法率；
- 关键点覆盖率；
- 不支持事实率；
- 安全拒答率与误拒率；
- P50/P95 延迟；
- 单次成本或 Token 数；
- 同一版本相对基线的回归变化。

## 7. React UI 自动化任务

建议使用 Playwright：

1. 打开空问题列表并验证空态；
2. 发布问题，跳转详情，返回列表可搜索；
3. 发布回答并验证回答数量；
4. 采纳回答、切换采纳、取消采纳；
5. 关闭问题后回答表单消失，再重新开放；
6. 模拟创建响应丢失，复用幂等键重试并验证无重复数据；
7. 赞成后刷新页面，分数保持；
8. 相同投票显示可理解的冲突信息；
9. 后端 500/超时显示错误态和重试；
10. AI 中间件未启动时，核心页面仍可用；
11. 使用窄视口验证移动端布局；
12. 键盘完成导航和表单提交；
13. axe 扫描可访问性严重问题。

稳定性原则：优先角色、标签和可访问名称定位，测试数据使用唯一前缀，不依赖固定数据库顺序。

## 8. 性能与可靠性任务

推荐初始目标仅作为学习基线，需要通过实测调整：

| 场景 | 负载 | 初始目标 |
|---|---|---|
| 问题列表 | 100 并发，持续 5 分钟 | P95 < 300ms，错误率 < 0.1% |
| 问题详情 | 200 并发，热点 20/80 | P95 < 250ms，无数据库连接耗尽 |
| 创建问题 | 20 RPS | P95 < 500ms，无重复和半成功 |
| 投票 | 同一问题 50 并发 | 记录唯一，聚合分数可对账 |
| AI 摘要 Mock | 20 并发 | P95 < 800ms，超时按契约返回 |

故障演练：

- MySQL 延迟、只读、连接断开和恢复；
- Redis 断开时核心读写降级；
- AI 中间件超时、429、500、非 JSON 和连接拒绝；
- 容器重启期间前端错误展示；
- 数据迁移中断和重新执行；
- 磁盘空间不足、连接池耗尽、慢查询。

## 10. 数据测试设计

只生成合成数据，可用以下前缀识别和清理：

- 用户：`学习者001`、`synthetic-user-001`；
- 标题：`[E2E-时间戳] 如何测试……`；
- 标签：`api`、`pytest`、`性能测试`；
- AI 内容：不包含真实公司、客户、域名、Token 和日志。

测试数据分层：

1. 单元测试：内存对象；
2. 接口测试：每用例重建 SQLite；
3. 集成测试：Testcontainers MySQL；
4. UI 测试：API 创建独立数据，结束后按前缀清理；
5. 性能测试：专用数据库与批量合成数据；
6. AI 测试：版本化黄金集，不使用工作资料。

## 11. 完成一个迭代的定义

一个新功能不能只以“页面能点”为完成标准，至少应包含：

- 中文需求和验收标准；
- API 与错误契约；
- 数据模型和可回滚迁移；
- 正常、边界、异常和权限测试；
- 前端加载、空态、错误态；
- 日志、指标和 Trace ID；
- 性能与安全影响说明；
- 合成测试数据；
- README 或架构文档更新；
- CI 中自动运行。
