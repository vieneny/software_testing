# 技术版本基线与升级策略

核对日期：**2026-07-27**。本页记录的是这套学习项目的可复现基线，不等于要求真实团队无条件追逐最新版本。

## 一、当前基线

| 领域 | 项目基线 | 选择理由 |
|---|---|---|
| Python | 3.12 | 类型、性能和生态成熟度均适合初学与测试开发；两个 Python 服务使用同一主版本 |
| FastAPI | 以各自 `uv.lock` 为准；本次锁定 0.140.x | 小于 1.0 的 minor 可能有兼容变化，因此以锁文件和回归测试控制升级 |
| Java | 21 LTS | 兼顾现代语法、企业岗位和长期维护 |
| Spring Boot | 3.5.16 | 采用仍在维护的 3.5 稳定线；暂不把首版迁移复杂度扩大到 4.x |
| Node.js | 22 | 满足 Vite 8 的 `20.19+` 或 `22.12+` 要求，并与两个前端统一 |
| React | 19.2.x | 当前稳定主线；依赖锁文件固定补丁版本 |
| Vue | 3.5.x | 当前稳定线；不把 3.6 预发布版本作为教学基线 |
| Vite | 8.1.x | 当前稳定构建基线，React/Vue 使用各自 6.x 官方插件 |
| TypeScript | 5.9.x | 两个前端保持相同语言版本，降低对照学习噪声 |
| MySQL | 8.4 | LTS 数据库基线，练习事务、索引、锁和迁移 |
| Redis | 7.4 | 稳定缓存基线；首版只提供基础设施，业务接入是后续测试任务 |
| Nginx | 1.30.4 | 使用官方稳定 Alpine 镜像承载两个前端并反向代理 API |

官方核对入口：

- [Spring Boot 3.5.16 发布说明](https://spring.io/blog/2026/06/25/spring-boot-3-5-16-available-now/)
- [Vite 8.1 发布说明](https://vite.dev/blog/announcing-vite8-1)
- [React 当前版本与补丁列表](https://react.dev/versions)
- [Vue Core Releases](https://github.com/vuejs/core/releases)
- [FastAPI Release Notes](https://fastapi.tiangolo.com/release-notes/)
- [Starlette TestClient 文档](https://www.starlette.io/testclient/)
- [Nginx Docker Official Image](https://hub.docker.com/_/nginx)

> 2026 年的 Starlette `TestClient` 已优先使用 `httpx2`，所以两个 Python 项目的测试依赖同时出现 `httpx2` 是有意的；业务服务间调用仍显式使用 `httpx`。两者不要机械互换，迁移前应先阅读 Starlette/HTTPX 的发布说明并跑消费者契约测试。

## 二、为什么不把所有组件都换成最大版本号

“最新”包含不同含义：最新稳定版、最新 LTS、最新维护分支、最新预发布版并不是一回事。学习项目优先满足：

1. 有官方维护；
2. 依赖彼此兼容；
3. 本仓库测试已经通过；
4. 初学者可以获得相同结果；
5. 能对应当前岗位能力；
6. 有明确升级路径。

因此：

- Spring Boot 4.x 留作后续迁移实验，先保证 Spring Boot 3.5、Springdoc、Resilience4j、JPA 和测试链路稳定；
- Vue 3.6 在成为稳定版且插件验证完成前不进入主线；
- Python 运行时不因发布新版本就立即跨主版本，先检查二进制依赖、框架和 CI；
- MySQL、Redis 优先使用稳定/LTS 基线，不在没有数据迁移与恢复验证时追新。

## 三、锁定位置

| 技术 | 锁定文件或机制 |
|---|---|
| Python | `pyproject.toml` 声明兼容范围，`uv.lock` 固定完整依赖图 |
| React/Vue | `package.json` 声明范围，`package-lock.json` 固定安装结果，Docker 使用 `npm ci` |
| Java | Spring Boot parent/BOM 管理依赖，`pom.xml` 只显式固定第三方版本 |
| 容器 | Compose 固定数据库主次版本，升级时审查镜像摘要与发布说明 |

不要删除锁文件后声称“本机能跑就是可复现”。新增依赖后应同时更新声明和锁文件，并检查 diff 中是否混入未知安装脚本或异常来源。

## 四、升级验证流程

```text
阅读官方发布与安全公告
→ 单独升级一个依赖簇
→ 更新锁文件
→ 静态检查和单元测试
→ 数据库迁移与真实 MySQL 集成测试
→ Python/Java ↔ AI 消费者契约测试
→ React/Vue 构建与关键 UI 测试
→ Docker Compose 健康检查
→ 性能、安全、降级基线对比
→ 更新本文核对日期和已知限制
```

出现失败时先确认是源码、锁文件、运行时还是上游行为变化，不要用扩大版本范围、跳过测试或反复重试掩盖问题。

## 五、建议的定期维护

- 每月检查安全公告和停止维护通知；
- 每季度评估 minor/major 升级；
- 紧急安全修复不等待季度窗口，但仍必须完成最小回归；
- 保留一次 Spring Boot 3.5 → 4.x、Vite 8 → 下一稳定主版本的迁移练习，记录破坏点与回滚方案；
- 招聘信息只影响“学习优先级”，不能替代兼容性和安全证据。
