# 系统间接口契约

这份文档区分两种约定：

- **必须字节级一致**：论坛/客服调用 Python AI 中间件的 JSON 和关联 ID；
- **语义一致、编码可不同**：两个独立业务后端的错误响应。契约测试应使用各自的
  Profile 解析，再断言共同语义，不能假设 Java 与 Python 的全部业务响应长得一样。

## 一、通用 HTTP 约定

- 论坛与客服业务 API 前缀：`/api/v1`；`/health`、`/api/health` 和 Actuator
  这类运行探针不纳入业务版本；
- JSON 使用 UTF-8；
- 请求可携带 `X-Request-ID`，仅接受 `[A-Za-z0-9._:-]{1,128}`；非法或缺失时生成
  新 ID；
- 成功和错误响应都回传规范的 `X-Request-ID`；
- 论坛暂时兼容旧 `X-Trace-ID`，但新代码统一使用 `X-Request-ID`；
- 时间使用带时区 ISO 8601；
- 列表必须显式返回分页元数据；
- 已接入幂等的写操作统一使用 `Idempotency-Key`：
  社区问题/回答、客服会话/消息/会话状态/工单创建；同键同内容安全重放，同键异内容
  返回 409。投票、工单状态流转与分配仍使用各自的唯一约束或 `expectedVersion`，
  不得误写成所有写接口都已支持幂等键；
- 客服工单的状态流转与分配必须提交上次读取的 `expectedVersion`；过期版本返回
  `409 CONCURRENT_MODIFICATION`，成功响应返回递增后的新版本；
- 不在错误文本中回显 Secret、SQL、堆栈或其他租户数据。

## 二、错误响应 Profile

共同必需语义是 `code`、安全的 `message`、`request_id` 和可机器处理的细节；当前编码：

- 论坛：`{"error":{"code":"...","message":"...","request_id":"...","details":{}}}`；
- 客服：`{"code":"...","message":"...","request_id":"...","fieldErrors":{}}`；
- AI 中间件：
  `{"api_version":"v1","request_id":"...","error":{"code":"...","message":"...","retryable":false,"details":{}}}`。

共享测试先根据服务 Profile 取出逻辑字段，再执行共同断言：ID 必须与响应头一致，
5xx 不得出现堆栈/内部 URL，字段错误不得包含其他租户或上游原始响应。

| HTTP | code 示例 | 说明 |
|---:|---|---|
| 400/422 | `VALIDATION_ERROR` | Java Bean Validation 当前用 400；Pydantic Schema 当前用 422 |
| 401 | `UNAUTHENTICATED` | 未认证或会话失效 |
| 403 | `FORBIDDEN` | 已认证但无权限 |
| 404 | `RESOURCE_NOT_FOUND` | 资源不存在，必要时用于隐藏越权对象 |
| 409 | `CONFLICT` | 状态、版本、唯一约束或幂等冲突 |
| 422 | `SCHEMA_ERROR` | 请求 Schema 无法解析 |
| 429 | `RATE_LIMITED` | 频率或配额超限 |
| 503 | `DEPENDENCY_UNAVAILABLE` | 必需依赖不可用 |

## 三、AI 通用响应元数据

AI 中间件的通用能力端点采用下面的外层结构：

```json
{
  "api_version": "v1",
  "request_id": "req_demo_001",
  "result": {},
  "provider": {
    "name": "mock",
    "model": "deterministic-rules",
    "version": "2026.07",
    "attempts": 1
  }
}
```

论坛摘要与客服建议为了消费者兼容使用扁平业务响应，但仍必须带 `api_version`、
`request_id` 和 `model`。消费者必须做到：

- 忽略新增的可选字段；
- 对缺失必需字段、非法类型和未知枚举给出可诊断错误；
- 设置连接和读取超时；
- 消费者总读取超时必须覆盖中间件合法的顺序操作与一次重试预算：当前论坛默认
  `25s`，客服默认 `20s`；调整分块数、Provider 单次超时或重试次数时必须同步重算；
- 只对幂等请求做有限重试；
- AI 错误时返回明确 degraded，不伪装成正常模型结果；
- 不因 AI 摘要/建议失败而回滚已经成功的核心业务事务。

## 四、论坛摘要兼容契约

请求：

```json
{
  "title": "如何设计接口幂等测试？",
  "content": "这是完全虚构的学习问题。",
  "answers": ["可以从幂等键、重复消息和状态机开始。"]
}
```

响应核心字段：

```json
{
  "summary": "问题讨论接口幂等的测试设计。",
  "risk_hints": ["重复提交", "并发冲突"],
  "model": "mock/deterministic-rules@2026.07"
}
```

论坛保存正文的上限可以大于 AI 请求上限。消费者发送前必须只对临时 AI 副本做
确定性字符预算：标题不超过 300、正文不超过 10000、最多 100 条回答且单条不超过
5000，三类文本总计不超过 20000；不得截断或写回数据库中的原帖与回答。
中间件会把组合文本按 10000 字符、128 字符重叠分块，并对每块都执行摘要与审核；
`processing.input_truncated` 必须为 `false`。任一块失败时整体失败且不得返回部分摘要，
尾部或跨分块边界的风险必须进入 `risk_hints`。`provider` 与 `processing` 是可选扩展
元数据，旧消费者可忽略，新契约测试可用它们核对实际调用次数和显式截断状态。

## 五、客服建议兼容契约

请求：

```json
{
  "tenant_code": "demo",
  "ticket_id": "TKT-DEMO-001",
  "title": "合成演示账号无法登录",
  "description": "这是合成账号场景，不对应真实客户。",
  "category": "ACCOUNT",
  "priority": "HIGH",
  "customer_level": "NORMAL",
  "tone": "professional",
  "language": "zh-CN",
  "knowledge_context": [
    {
      "title": "公开演示账号排查说明",
      "category": "ACCOUNT",
      "content": "先确认演示账号状态，再尝试重置演示密码。"
    }
  ]
}
```

响应核心字段：

```json
{
  "summary": "用户咨询合成演示账号登录问题。",
  "suggested_reply": "建议先确认演示账号状态，再尝试重置演示密码。",
  "suggested_category": "ACCOUNT",
  "suggested_priority": "HIGH",
  "confidence": 0.82,
  "risk_flags": [],
  "knowledge_references": ["公开演示账号排查说明"],
  "suggested_actions": ["核对演示账号状态"],
  "must_verify": ["发送前由坐席核对账号与知识引用"],
  "degraded": false,
  "degradation_reason": null,
  "api_version": "v1",
  "request_id": "req_demo_001",
  "model": "mock/deterministic-rules@2026.07"
}
```

约束：

- `tenant_code` 只允许作为隔离上下文，AI 中间件不得自行访问业务数据库；
- `knowledge_context` 由 Java 服务完成租户与发布状态过滤，Python 服务仍要把它视为不可信输入；
- `suggested_category` 只允许
  `ACCOUNT/BILLING/TECHNICAL/SECURITY/PRODUCT/OTHER`；
- `suggested_priority` 只允许 `URGENT/HIGH/MEDIUM/LOW`，中间件内部 `P0`
  必须映射为 Java 领域的 `URGENT`；
- `suggested_actions` 与 `must_verify` 必须贯穿 Java DTO 和坐席界面；
  `must_verify` 至少一项，不能被消费者静默隐藏；
- 响应只是坐席草稿，不能直接发送、退款、补偿、改工单状态或执行其他副作用；
- Python 服务超时、断路或返回非法 Schema 时，Java 服务返回 `degraded=true` 的安全草稿，工单查询和状态流转继续可用；
- 枚举语义变更必须升级契约；新增可选字段时消费者应忽略未知字段。
