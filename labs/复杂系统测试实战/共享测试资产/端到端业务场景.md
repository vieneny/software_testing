# 端到端业务场景

本文件描述的是持续演进的**目标验收故事**，不是首版完成清单。当前能直接执行的步骤以
两个系统各自 README 的“已实现接口/当前可以实际操作什么”为准；尚未实现的步骤应先
转成需求、接口和测试，再进入完成状态。

## 一、社区问答系统

### 场景一：问题到被接受回答

1. 用户创建问题；
2. 列表和详情可以查询；
3. 第二个用户提交回答；
4. 问题作者接受回答；
5. 回答者收到通知；
6. 问题状态、回答状态和计数一致；
7. AI 摘要不可用时，前六步仍成功。

风险：

- 重复点击生成两条问题/回答；
- 非作者接受回答；
- 接受两条回答；
- 并发投票丢失更新；
- 已隐藏内容进入搜索/AI 上下文；
- HTML/Markdown XSS。

### 场景二：举报与审核

1. 普通用户举报内容；
2. 版主进入审核；
3. 隐藏内容；
4. 作者申诉；
5. 管理员恢复或维持处理；
6. 全过程有审计。

风险：

- 举报人看到版主内部说明；
- 重复举报刷爆通知；
- 隐藏后缓存、搜索和推荐仍可见；
- AI 风险提示被当成最终封禁决定。

## 二、企业智能客服系统

### 场景一：工单完整生命周期

1. 客户创建工单；
2. 系统分类并给出优先级建议；
3. 队列分配给坐席；
4. 坐席增加内部备注；
5. 坐席发送客户可见回复；
6. 工单进入 `WAITING_CUSTOMER`，客户补充信息后恢复 `IN_PROGRESS`；
7. 坐席解决，客户确认后关闭。

风险：

- 内部备注发送给客户；
- 两位坐席并发抢单；
- 非法状态跳转；
- AI 超时导致工单未创建；
- 重复回调生成两条消息；
- SLA 暂停和恢复计算错误。

### 场景二：知识库辅助回复

1. 知识管理员创建草稿；
2. 审核后发布版本 1；
3. 坐席问题检索到版本 1；
4. 发布版本 2 并标记版本 1 过期；
5. AI 回复引用版本 2；
6. 无答案问题明确升级人工。

风险：

- 草稿被普通坐席或 AI 检索；
- 跨租户知识泄漏；
- 引用不存在或已撤回；
- 文档中的 Prompt Injection 改变系统目标；
- AI 编造退款、补偿或服务承诺。

## 三、跨系统对照实验

| 主题 | 社区系统 | 客服系统 |
|---|---|---|
| 幂等 | 重复发问/投票 | 重复建单/消息回调 |
| 权限 | 作者/版主 | 客户/坐席/主管/租户 |
| 状态机 | 草稿/发布/隐藏 | 工单生命周期/SLA |
| 缓存 | 热门、计数 | 队列看板、幂等 |
| 搜索 | 问题/标签 | 客户/工单/知识 |
| AI | 摘要、标签、审核 | 分类、RAG、回复建议 |
| 性能 | 读多写少、热点 | 并发坐席、消息和队列 |
| 安全 | XSS、刷票、内容 | 多租户、内部备注、客户隐私 |

完成同一测试主题在两个系统中的实现和对照，比只会某一个框架更能证明可迁移的质量工程能力。
