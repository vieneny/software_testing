# 全链路验收指南

这套验收把三个服务当作真正的黑盒系统，使用一次性合成数据验证两个项目的核心纵向
链路。脚本只使用 Python 标准库，不读取公司文件，也不需要真实模型密钥。

## 一、先启动三个服务

终端一，启动默认离线 Mock AI：

```bash
cd ../人工智能中间件
uv sync --extra test --locked
uv run --frozen uvicorn ai_middleware.app:app --host 127.0.0.1 --port 8090
```

终端二，启动社区后端：

```bash
cd ../社区问答系统/backend
uv sync --dev --locked
AI_BASE_URL=http://127.0.0.1:8090 uv run --frozen uvicorn app.main:app \
  --host 127.0.0.1 --port 8000
```

终端三，启动客服后端。JDK 必须为 21 或更高版本：

```bash
cd ../企业智能客服系统/backend
AI_BASE_URL=http://127.0.0.1:8090 mvn spring-boot:run
```

以上命令默认使用 SQLite/H2 和项目内合成种子数据，不要求 MySQL、Redis 或云模型。

## 二、执行验收

回到本目录：

```bash
python3 ./全链路接口验收.py
```

脚本依次验证：

1. 社区问题与回答的幂等重放；
2. 回答采纳、投票、问题关闭和重新开放；
3. 社区 AI 摘要及关联 ID；
4. 客服会话创建和幂等重放；
5. 内部备注不会出现在默认客户视图；
6. 坐席公开回复推动会话状态；
7. 会话升级工单并保留双向关联；
8. 客服 AI 建议必须包含人工核验项；
9. 会话合法关闭。

如果只想验证 AI 不可用时核心业务是否仍能运行：

```bash
python3 ./全链路接口验收.py --skip-ai
```

也可以用环境变量覆盖地址：

```bash
COMMUNITY_BASE_URL=http://127.0.0.1:18000 \
CUSTOMER_SERVICE_BASE_URL=http://127.0.0.1:18080 \
AI_BASE_URL=http://127.0.0.1:18090 \
python3 ./全链路接口验收.py
```

## 三、数据与安全说明

- 每次执行都会生成随机运行标识，标题、正文、客户消息和工单全部是合成数据。
- SQLite/H2 本地模式适合学习和快速回归；提交前仍要用 Compose 的 MySQL 模式补一次
  集成验证。
- 脚本不会删除数据。SQLite/H2 练习环境可以通过停止服务和删除被 Git 忽略的本地
  练习数据库来重置；容器练习数据只能在确认可丢弃后使用 `docker compose down -v`。
- 不要把该脚本地址改成公司内网、预生产或生产环境；它会真实创建问题、会话和工单。
