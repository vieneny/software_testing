# 分阶段实现路线

目标是先得到可运行、可测试的纵向切片，再持续扩展。每一阶段都必须有代码、测试、数据和验收证据。

## 当前落点

截至当前版本：

- 阶段 0 已完成；
- 阶段 1 的社区问题/回答闭环，以及客服会话/消息/工单闭环已完成；
- 阶段 2 已完成写请求幂等、客服多租户查询边界和并发版本保护，但正式认证、RBAC
  与社区作者权限仍未实现；
- 阶段 3 已具备 MySQL/Redis 编排和数据库迁移，Redis 业务接入、消息队列、对象存储
  与搜索仍未实现；
- 阶段 4 已具备离线确定性 Mock、真实 OpenAI-compatible 安全调用和消费者降级，
  完整 RAG、黄金集统计报告与模型路由仍未实现；
- 阶段 5～6 仍以训练任务为主。

可执行能力和残余边界见[当前实现与后续边界](当前实现与后续边界.md)。

## 阶段 0：骨架与契约

交付：

- FastAPI + React 社区骨架；
- Spring Boot + Vue 客服骨架；
- Python AI 中间件及离线 Mock；
- 三个服务的 health/ready；
- Dockerfile、环境变量示例和 Compose；
- API 错误、request id、AI 版本和降级契约；
- 最小单元/API 测试。

验收：

- 不配置云模型密钥也能运行测试；
- 社区和客服核心服务在 AI 停止时仍能工作；
- 没有公司数据、真实客户信息和硬编码 Secret；
- 所有标准命令在 README 中可复制执行。

## 阶段 1：两个业务闭环

### 社区

```text
创建问题 → 查询列表/详情 → 创建回答 → 投票 → AI 摘要建议
```

### 客服

```text
创建工单 → 查询/分配 → 状态流转 → AI 回复建议 → 解决/关闭
```

验收：

- 正常、重复、非法状态、目标不存在和分页边界；
- 数据可重置；
- 前端能完成关键旅程；
- API 测试可独立运行。

## 阶段 2：身份、权限与多租户

社区：

- JWT、刷新、退出、作者权限、版主审核；
- XSS、CSRF/CORS、暴力破解、账号枚举；
- 投票/收藏/关注幂等。

客服：

- tenant_id 强制过滤；
- 客户、坐席、主管、知识管理员和租户管理员；
- 内部备注与客户可见消息严格分离；
- 跨租户对象 id 越权测试。

验收：

- 权限以服务端为准；
- 401、403、404 的策略一致；
- 缓存键、日志、导出和 AI 检索也不能跨租户。

## 阶段 3：数据与基础设施

- MySQL 迁移、唯一约束、索引和事务；
- Redis 缓存、限流、幂等键；
- MinIO/S3 附件；
- 搜索引擎；
- RabbitMQ/Kafka + Outbox；
- 合成数据生成器。

重点实验：

- 双写失败；
- 重复消息；
- 缓存穿透/击穿；
- 大偏移分页；
- 数据库死锁和乐观锁冲突；
- 附件上传后业务事务失败产生孤儿文件。

## 阶段 4：AI 与 RAG

社区：

- 内容风险提示；
- 摘要与标签建议；
- 相似问题；
- 回答辅助与引用。

客服：

- 工单分类和优先级；
- 会话摘要；
- 知识库检索与引用；
- 坐席回复建议；
- 质检与升级人工。

AI 验收：

- 全部使用公开/合成黄金集；
- 确定性规则 + LLM Judge + 人工校准；
- 按语言、长度、类别、风险和租户切片；
- Prompt Injection、越权检索、敏感信息和不安全承诺；
- success rate、p95、成本、降级率和人工采纳率；
- 模型、Prompt、知识库和评分器版本可追溯。

## 阶段 5：实时、性能与可靠性

- 客服 WebSocket 实时消息；
- 社区热门内容与通知；
- k6/JMeter 业务负载；
- Redis、AI、消息队列、对象存储故障；
- 超时、重试、断路、限流和恢复；
- OpenTelemetry + Prometheus/Grafana。

验收不只看平均响应时间，还要包括：

- p50/p95/p99；
- 错误率和业务失败率；
- 队列堆积；
- 数据库连接、慢 SQL 和锁；
- AI 吞吐、首 Token/总耗时；
- 降级期间核心业务是否仍可用；
- 恢复后是否重复写入或遗漏事件。

## 阶段 6：安全、交付与作品化

- OWASP API/Web 基线；
- 依赖、容器、Secret 和 IaC 扫描；
- 审计日志和数据保留；
- CI 分层与发布门禁；
- 蓝绿/滚动发布兼容；
- 数据库向前/向后兼容迁移；
- 故障演练与回滚；
- 作品说明、演示脚本和面试问答。

## 推荐节奏

| 周期 | 目标 |
|---|---|
| 第 1～2 周 | 骨架、契约和两个后端测试 |
| 第 3～4 周 | 两个业务闭环和前端关键页 |
| 第 5～6 周 | 认证、权限、多租户 |
| 第 7～8 周 | MySQL、Redis、迁移和集成测试 |
| 第 9～10 周 | AI 黄金集、RAG 与安全 |
| 第 11～12 周 | 性能、故障、可观测和作品验收 |

如果时间有限，优先完成一个系统到阶段 5，再让另一个系统完成阶段 2。两个半成品不如一个有完整质量证据的作品。
