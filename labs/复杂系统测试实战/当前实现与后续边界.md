# 当前实现与后续边界

这份说明回答两个问题：

1. 现在下载仓库后，哪些能力已经有真实代码、页面和自动化测试？
2. 哪些仍然是后续训练需求，不能被误认为已经达到生产级？

“完成”在当前版本中的含义是：两个项目各自具备可启动、可操作、可断言、可故障注入
的核心纵向链路，并且统一 AI 服务既能完全离线运行，也保留安全的真实模型接入路径。
它不表示一次提交就实现所有成熟论坛和企业客服产品功能。

## 一、当前可以直接学习和验收

| 项目 | 已打通的核心链路 | 关键质量能力 |
|---|---|---|
| Python + React 社区 | 创建/搜索问题 → 幂等重试 → 回答 → 采纳 → 投票 → 关闭/重开 → AI 摘要 | 输入边界、SQLite/MySQL 迁移、统一错误、LIKE 转义、AI 严格契约 |
| Java + Vue 客服 | 创建会话 → 客户消息/公开回复/内部备注 → 关闭/重开 → 升级工单 → 分配/流转 → AI 建议 | 多租户过滤、内部可见性、幂等、乐观/悲观锁、状态机、降级 |
| Python AI 中间件 | 论坛摘要、客服分类/摘要/回复/知识引用、安全检查 | 默认离线 Mock、超时重试、结构化输出、真实 Provider 默认断网 |

三类入口分别承担不同验证：

- 各项目单元/组件测试：快速定位领域和契约缺陷；
- `一键质量检查.sh`：统一执行 Python、Java、React、Vue 和 Compose 静态验收；
- `共享测试资产/全链路接口验收.py`：启动服务后，以黑盒方式验证跨服务主链路。

## 二、真实模型接入的安全定义

OpenAI-compatible Provider 已包含真实 HTTP JSON 调用实现，但必须同时满足以下条件
才会联网：

1. `AI_PROVIDER=openai-compatible`；
2. `AI_OPENAI_NETWORK_ENABLED=true`；
3. 使用 HTTPS；
4. 目标主机在显式白名单中；
5. 模型名和运行时 API Key 均已提供。

默认配置不联网、不读取浏览器登录态、不使用系统代理，也不会跟随重定向。测试使用
MockTransport，不消耗 Token。真实联调只能使用个人授权的公开模型账号和合成数据，
禁止发送公司需求、日志、客户对话、知识库或内网地址。

## 三、明确没有伪装成已完成的能力

以下能力仍是后续阶段，不应从当前目录名或 Compose 服务推断为已实现：

- OIDC/JWT、Spring Security、RBAC、版主/坐席/主管的正式授权；
- Redis 业务缓存、限流和分布式幂等；
- 消息队列、事务 Outbox、异步通知和死信恢复；
- WebSocket 实时会话、离线消息、附件和对象存储；
- 向量数据库、完整 RAG 索引、知识审批和权限检索；
- OpenTelemetry、指标告警、生产日志脱敏和审计保留策略；
- 完整 Playwright UI 回归、真实 MySQL Testcontainers、性能与安全门禁；
- 高可用、备份恢复、灰度发布和生产运维。

这些不是“忘记写”的占位，而是下一轮可以独立完成需求分析、开发、测试和复盘的训练
主题。每次只选择一个纵向增量，并按功能、接口、UI、性能、安全、AI 和可靠性补齐
证据，比一次性加入大量无法验证的组件更有学习价值。

## 四、进入下一阶段前的验收门槛

新增功能至少需要：

- 需求与状态/权限说明；
- 可回滚的数据迁移；
- API、错误、幂等和并发契约；
- 正常、边界、异常、隔离和恢复测试；
- 前端加载、空状态、失败与重复提交处理；
- 只使用公开或合成数据；
- 更新 README、功能清单和全链路验收；
- 推送前通过敏感信息扫描。
