# 接口说明

本文档描述 `v1` HTTP 契约。默认服务地址示例：

```text
AI_BASE_URL=http://127.0.0.1:8000
```

所有示例均为合成数据。

## 通用约定

### 请求 ID

- 调用方可发送 `X-Request-ID`，允许字符为英文字母、数字、`. _ : -`，长度 1–128。
- 合法值会原样写入响应头和响应 JSON。
- 未传或不合法时，服务生成 32 位十六进制 ID。
- 同一次业务链路应复用同一个 ID；不要把邮箱、手机号、工单正文等个人数据放进 ID。

### 版本

- `api_version` 表示 HTTP 字段契约，目前为 `v1`。
- `/health`、`/ready` 的 `service_version` 表示部署的软件版本。
- 推理响应中的 `provider.version` 或兼容响应中的 `model` 表示规则/模型版本。
- `v1` 只允许增加可选字段；删除字段、改变类型或改变既有枚举语义必须发布新主版本。

### 超时与重试

每个 POST 请求都可带：

```json
{
  "execution": {
    "timeout_ms": 1500,
    "max_retries": 1
  }
}
```

- `timeout_ms` 范围 100–30000，表示每次 Provider 尝试的上限。
- `max_retries` 范围 0–3；总尝试次数等于 `1 + max_retries`。
- 字段缺省时使用服务环境变量配置。
- 只重试 Provider 临时失败与超时；验证失败、永久错误和业务审核结果不重试。
- 服务间调用建议总超时略大于
  `(max_retries + 1) × timeout_ms + 退避时间`。
- 客户端只应按 `error.retryable=true` 决定是否重试，并设置自己的总重试预算。
- 当前端点不产生写操作；将来如加入写操作，必须另加幂等键，不能直接复用本策略。

### 成功响应

通用能力采用统一信封：

```json
{
  "api_version": "v1",
  "request_id": "learning-001",
  "result": {},
  "provider": {
    "name": "mock",
    "model": "deterministic-rules",
    "version": "2026.07",
    "attempts": 1
  }
}
```

论坛和客服兼容路由使用更扁平的 JSON，方便既有 Python/Java DTO 直接接入，但仍保留
`api_version`、`request_id` 和 `model`。

### 统一错误

```json
{
  "api_version": "v1",
  "request_id": "learning-001",
  "error": {
    "code": "provider_timeout",
    "message": "AI Provider 在约定时间内未返回",
    "retryable": true,
    "details": {
      "timeout_ms": 1000,
      "attempts": 2
    }
  }
}
```

| HTTP 状态 | 典型 code | 是否可能重试 |
|---:|---|---|
| 404 | `http_error` | 否 |
| 422 | `validation_error` | 否，先修复请求 |
| 500 | `internal_error` | 默认否，先排查 |
| 502 | `provider_error` | 否 |
| 503 | `provider_temporarily_unavailable` | 看 `retryable` |
| 503 | `provider_unavailable` | 否，配置或实现未就绪 |
| 504 | `provider_timeout` | 是，但必须受总预算限制 |

错误不会回显密钥、堆栈、提示词或完整输入。

## 运行状态

### `GET /health`

只表示 HTTP 进程存活：

```json
{
  "api_version": "v1",
  "service_version": "0.1.0",
  "request_id": "generated-id",
  "status": "ok"
}
```

### `GET /ready`

默认 Mock 返回 200 和 `status=ready`。OpenAI-compatible 未显式开启网络时返回 503：

```json
{
  "api_version": "v1",
  "service_version": "0.1.0",
  "request_id": "generated-id",
  "status": "not_ready",
  "provider": "openai-compatible",
  "reason": "网络调用默认关闭；需显式设置 AI_OPENAI_NETWORK_ENABLED=true"
}
```

只有 Provider、网络开关、HTTPS base URL、主机白名单、模型与运行时密钥全部校验通过，
OpenAI-compatible 才返回 200 和 `status=ready`。就绪只代表配置可发起请求，不替代
对上游服务的持续可用性监控。

容器编排的存活探针用 `/health`，流量就绪探针用 `/ready`。

## 内容审核

### `POST /api/v1/moderation`

请求：

```json
{
  "text": "请勿在公开帖子中发送身份证信息",
  "context": "forum",
  "execution": {"timeout_ms": 1500, "max_retries": 1}
}
```

`context` 可为 `forum`、`customer_service`、`general`。

`result`：

```json
{
  "allowed": false,
  "decision": "review",
  "risk_score": 0.65,
  "categories": ["privacy"],
  "matched_terms": ["身份证"],
  "reason": "离线规则命中：privacy；需结合上下文人工复核"
}
```

Mock 只是可测试规则，不可替代真实政策引擎。`review`、`block` 都必须进入人工流程。

## 工单分类与优先级

### `POST /api/v1/tickets/classify`

请求：

```json
{
  "subject": "演示订单重复扣款",
  "content": "合成用户反馈支付后出现两条扣款记录，当前无法使用。",
  "channel": "android"
}
```

`channel` 可为 `web`、`ios`、`android`、`api`、`email`、`other`。

`result`：

```json
{
  "category": "billing",
  "priority": "P1",
  "confidence": 0.9,
  "reasons": [
    "命中离线分类词：扣款, 支付",
    "优先级规则输出 P1，生产环境必须由人工确认"
  ]
}
```

分类枚举：`account`、`billing`、`technical`、`security`、`product`、`other`。
优先级：`P0`–`P3`，数值越小越紧急。

## 有依据的知识问答

### `POST /api/v1/knowledge/answer`

请求必须显式携带 1–20 个公开或合成文档：

```json
{
  "question": "测试订单如何申请退款？",
  "documents": [
    {
      "source_id": "public-demo-refund-v1",
      "title": "公开演示商城退款说明",
      "content": "测试订单可在订单详情页点击申请退款，状态会变为审核中。"
    }
  ]
}
```

有匹配依据时：

```json
{
  "answer": "依据《公开演示商城退款说明》：测试订单可在订单详情页点击申请退款，状态会变为审核中。",
  "grounded": true,
  "confidence": 0.95,
  "citations": [
    {"source_id": "public-demo-refund-v1", "title": "公开演示商城退款说明"}
  ],
  "must_verify": ["发送给客户前核对原文版本和适用范围"]
}
```

无匹配依据时必须拒绝猜测：`grounded=false`、`citations=[]`。

## 论坛 FastAPI 兼容路由

### `POST /api/v1/forum/summarize`

这是论坛暂定契约：

```json
{
  "title": "如何学习接口测试",
  "content": "我正在使用公开演示 API 练习。",
  "answers": ["先覆盖正常、异常和边界场景。"]
}
```

响应：

```json
{
  "api_version": "v1",
  "request_id": "forum-001",
  "summary": "标题：如何学习接口测试 正文：我正在使用公开演示 API 练习。",
  "risk_hints": [],
  "model": "mock/deterministic-rules@2026.07",
  "provider": {
    "name": "mock",
    "model": "deterministic-rules",
    "version": "2026.07",
    "analysis_calls": 1,
    "moderation_calls": 1,
    "total_attempts": 2
  },
  "processing": {
    "source_chars": 52,
    "chunk_size": 10000,
    "chunk_overlap": 128,
    "chunk_count": 1,
    "input_truncated": false,
    "summary_truncated": false,
    "risk_hints_truncated": false,
    "model_truncated": false
  }
}
```

`title/content/answers` 合计最多 20000 个 Unicode 字符。兼容路由不会再截掉第
10000 字符后的内容，而是按最多 10000 个 Python Unicode 字符分块。相邻块固定重叠
128 个字符，确保风险词、账号模式或提示注入短语即使横跨分块边界，也会完整出现在至少
一个审核块中。服务依次对每一块执行：

1. 摘要分析；
2. 内容审核；
3. 全部块成功后才聚合结果。

多块摘要以 `[分块 n/总数]` 标识并最多返回 800 字符；仅摘要展示发生缩短时
`summary_truncated=true`，但每个输入块仍已完整分析和审核。`input_truncated` 当前固定
为 `false`；超出请求总量上限会返回 422，而不是静默截断。

`provider.analysis_calls` 和 `provider.moderation_calls` 应各等于 `chunk_count`；
`total_attempts` 包含重试。它们与 `processing` 一起让调用方确认尾部确实经过处理。

响应主动遵守论坛消费者的硬约束：

- `summary` 非空且不超过 10000 字符；当前聚合器进一步限制为 800 字符；
- `model` 非空且不超过 200 字符；
- `risk_hints` 最多 20 项，每项去除首尾空白后非空且不超过 500 字符；
- Provider 返回重复类别时按稳定顺序去重；类别过多时保留人工复核和封顶提示，并设置
  `processing.risk_hints_truncated=true`；
- Provider 模型标识超过边界时做确定性缩短，并设置
  `processing.model_truncated=true`。

这些限制在响应模型和聚合器两层同时执行，避免中间件返回 2xx 后又被论坛消费者判为
畸形上游响应。

当第 2 块命中暴力规则时，风险提示示例为：

```json
[
  "chunk=2;decision=block",
  "chunk=2;category=violence",
  "离线规则结果仅供分流，发布前必须人工复核"
]
```

调用方不得把空列表解释为“绝对安全”。

论坛聚合采用全有或全无语义：任一块的分析或审核失败，就返回统一错误，不返回部分摘要。
错误 `details` 会说明失败阶段、块序号、总块数以及未返回部分结果：

```json
{
  "api_version": "v1",
  "request_id": "forum-002",
  "error": {
    "code": "provider_temporarily_unavailable",
    "message": "AI Provider 暂时不可用",
    "retryable": true,
    "details": {
      "attempts": 1,
      "operation": "moderation",
      "chunk_index": 2,
      "chunk_count": 2,
      "partial_result_returned": false
    }
  }
}
```

每个块有两次独立的 Provider 操作。调用方总超时预算应至少覆盖：
`块数 × 2 × (最大重试次数 + 1) × 单次超时 + 退避时间`，并保留网络余量。

FastAPI 调用示意：

```python
import httpx


async def summarize_forum(ai_base_url: str, payload: dict, request_id: str) -> dict:
    timeout = httpx.Timeout(25.0, connect=0.5)
    async with httpx.AsyncClient(base_url=ai_base_url, timeout=timeout) as client:
        response = await client.post(
            "/api/v1/forum/summarize",
            json=payload,
            headers={"X-Request-ID": request_id},
        )
        response.raise_for_status()
        return response.json()
```

调用方要在自己的测试中 mock 此 HTTP 边界，不能依赖互联网服务。

## 客服 Spring Boot 兼容路由

### `POST /api/v1/customer-service/suggest`

请求：

```json
{
  "tenant_code": "demo",
  "ticket_id": "SYNTHETIC-002",
  "title": "演示账号无法登录",
  "description": "纯合成描述：公开演示账号收不到验证码，当前无法使用。",
  "category": "ACCOUNT",
  "priority": "HIGH",
  "customer_level": "VIP",
  "tone": "professional",
  "language": "zh-CN",
  "knowledge_context": [
    {
      "title": "公开演示账号登录故障排查",
      "category": "ACCOUNT",
      "content": "演示账号收不到验证码时，先核对测试环境认证服务状态。"
    }
  ],
  "execution": {"timeout_ms": 1500, "max_retries": 1}
}
```

字段说明：

| 字段 | 约束与用途 |
|---|---|
| `tenant_code` | 租户路由标识；示例只能使用 `demo` 等合成值 |
| `ticket_id` | 工单标识，禁止填真实生产 ID |
| `title` / `description` | 当前 Java DTO 的标题与描述 |
| `category` | 调用方已有分类，例如 `ACCOUNT`、`BILLING`、`OTHER` |
| `priority` | Java 领域值为 `URGENT/HIGH/MEDIUM/LOW`；入参仍兼容旧别名 `CRITICAL` |
| `customer_level` | 例如 `VIP/NORMAL`；Mock 不据此自动承诺差异化权益 |
| `tone` | `professional/empathetic/concise`，未知值安全降级为 professional |
| `language` | 语言标签；Mock 只提供固定中文模板 |
| `knowledge_context` | 0–20 条本次请求显式携带的公开/合成知识 |

兼容早期学习调用的 `subject/customer_message/channel/context` 仍可使用；新 Spring Boot
客户端应按上表传输。`tenant_code` 不参与提示文本和日志，不能作为鉴权依据。

Java 友好的扁平响应与现有 `AiMiddlewareResponse` record 对齐：

```json
{
  "summary": "演示账号无法登录 纯合成描述：公开演示账号收不到验证码，当前无法使用。",
  "suggested_reply": "您好，我们已记录您的反馈……",
  "suggested_category": "ACCOUNT",
  "suggested_priority": "HIGH",
  "confidence": 0.9,
  "risk_flags": ["HIGH_PRIORITY"],
  "knowledge_references": ["公开演示账号登录故障排查"],
  "degraded": false,
  "degradation_reason": null,
  "api_version": "v1",
  "request_id": "customer-002",
  "suggested_actions": ["核对账号标识与登录时间", "检查认证服务状态"],
  "must_verify": ["不得承诺退款、赔偿、修复时间或最终结论"],
  "model": "mock/deterministic-rules@2026.07"
}
```

核心 Java record 字段是从 `summary` 到 `degradation_reason`；其余是中间件提供的可选链路
元数据。`risk_flags` 使用稳定的大写标识，例如 `HIGH_PRIORITY`、
`CONTENT_PRIVACY`、`HUMAN_REVIEW_REQUIRED`。正常 Mock 响应
`degraded=false/degradation_reason=null`；当 HTTP 调用失败时，现有 Java 客户端继续
负责生成自己的 degraded fallback。

优先级映射固定为：`P0 → URGENT`、`P1 → HIGH`、`P2 → MEDIUM`、
`P3 → LOW`。`CRITICAL` 只作为历史入参别名解析为 P0，响应永远使用 Java 领域值
`URGENT`，避免消费者枚举反序列化失败。

Spring WebClient 示意：

```java
public record KnowledgeContext(
    String title,
    String category,
    String content
) {}

public record AiSuggestRequest(
    String tenant_code,
    String ticket_id,
    String title,
    String description,
    String category,
    String priority,
    String customer_level,
    String tone,
    String language,
    List<KnowledgeContext> knowledge_context
) {}

public record AiSuggestResponse(
    String summary,
    String suggested_reply,
    String suggested_category,
    String suggested_priority,
    double confidence,
    List<String> risk_flags,
    List<String> knowledge_references,
    boolean degraded,
    String degradation_reason
) {}

Mono<AiSuggestResponse> result = webClient.post()
    .uri(aiBaseUrl + "/api/v1/customer-service/suggest")
    .header("X-Request-ID", requestId)
    .bodyValue(request)
    .retrieve()
    .bodyToMono(AiSuggestResponse.class)
    .timeout(Duration.ofSeconds(4));
```

Java 字段名按当前 JSON 原样声明，避免学习项目额外引入命名策略。生产接入应为错误响应
单独建立 DTO，并按 `retryable` 和调用总预算处理。
