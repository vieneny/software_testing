# 安全控制与风险测试

本章说明人工智能中间件的输入控制、网络边界、权限与失败处理。

## 当前实现实际会做什么

默认 `mock` Provider：

- 只在当前进程内处理请求；
- 不发网络请求；
- 不读取文件、数据库、剪贴板或环境中的业务内容；
- 不持久化请求与响应；
- 不启用请求正文日志；
- 同样输入产生同样输出，便于断言与回归。

OpenAI-compatible Provider 已具备真实 HTTP JSON 调用能力，但默认关闭：

- 只选择 Provider 或只配置密钥仍不会联网，必须显式开启网络总开关；
- 未通过配置校验时 `/ready` 返回 503，推理接口返回 `provider_unavailable`；
- base URL 必须为 HTTPS，且主机必须位于显式白名单；
- 禁用环境代理与自动重定向，限制超时、输出 token 和 HTTP 响应字节数；
- 只接受严格 JSON 契约，知识引用不得超出请求携带的资料；
- 429/5xx 等临时故障可有限重试，鉴权、契约与安全错误不盲目重试；
- 密钥从对象 repr 中排除，但仍禁止在测试、异常和版本库中写入真实值。

## 威胁与控制

| 风险 | 当前控制 | 真实接入前还要做什么 |
|---|---|---|
| 敏感输入外发 | 默认离线；限制请求正文 | 数据分级、授权、DLP、供应商数据协议 |
| SSRF | HTTPS + 固定主机白名单；禁重定向和环境代理 | 固定 DNS/出口与 egress 策略 |
| 密钥泄漏 | 环境变量占位；错误不回显；repr 隐藏 | 密钥管理服务、轮换、最小权限和泄漏扫描 |
| 提示注入 | Mock 标记简单关键词；知识问答只用显式文档 | 指令/数据分离、工具白名单、沙箱和攻击评测 |
| 越权工具调用 | 当前无工具、无数据库写入 | 独立授权层、最小权限、逐动作确认和审计 |
| 幻觉 | 无依据时拒答；返回 citation 与 must_verify | 检索版本、引用验证、置信门槛和人工升级 |
| 自动决策伤害 | 回复始终要求人工复核 | RBAC、双人复核、申诉与回滚机制 |
| 拒绝服务/成本放大 | 字段长度、超时、重试上限 | 网关体积限制、限流、配额、熔断和成本告警 |
| 日志泄漏 | 应用不记录正文 | 网关/APM 同样脱敏，限制访问和留存周期 |
| 供应链风险 | 依赖范围受限、非 root 容器 | 锁文件、SBOM、签名镜像、漏洞和许可证扫描 |

## 输入规则

1. 网关和应用都要限制请求体大小；Pydantic 字段限制不是完整的网关防护。
2. `X-Request-ID` 不能包含用户个人信息；非法格式会被替换。
3. 文档 `source_id` 使用公开、稳定、无隐私的标识。
4. 知识问答只接收调用方显式提供的资料，不隐式扫描本机目录。
5. 论坛 `answers` 与客服 `context` 都有限制，避免无边界批量输入。
6. 真实接入前必须在进入 Provider 前完成数据分类、必要性判断和字段级脱敏。

## 输出规则

- `risk_score` 和 `confidence` 是 Mock 测试值，不是概率真值。
- `allowed=true` 只表示离线规则未命中，不表示内容绝对安全。
- `summary` 可能遗漏上下文，不能替代原文或审核记录。
- `grounded=true` 仍要核对引用的版本、有效期与适用范围。
- `suggestion` 只是草稿，不能自动发送；`must_verify` 不能被调用方隐藏。
- 不向外暴露堆栈、系统提示、密钥、模型原始调试数据或完整敏感输入。

## 超时与重试安全

- 只对超时和 `ProviderTransientError` 重试。
- 重试次数最多 3 次，并采用短退避。
- 422、永久 Provider 错误、审核 block/review 不能通过重试“绕过”。
- 下游调用方必须有比单次 Provider 超时更高但有界的总超时。
- 同一业务链路应透传请求 ID，用于关联指标；请求 ID 不是鉴权凭据。
- 未来若接口产生副作用，必须增加独立幂等键和服务端去重。

## 启用真实模型前的安全门

网络实现存在不等于可以绕过输入审查。任何环境启用外发前，至少完成：

- [ ] 明确数据所有者、处理目的、法律依据、允许字段和禁止字段。
- [ ] 确认供应商是否训练使用输入、数据保存时长、删除机制和数据驻留区域。
- [ ] 为模型服务使用独立最小权限密钥，接入密钥管理与轮换。
- [ ] 固定 base URL、主机、端口和路径；禁止用户输入控制目标地址。
- [ ] 禁止自动跟随跨域重定向，设置连接、读取、写入和总超时。
- [ ] 配置并发、速率、预算、熔断、降级和可观测性。
- [ ] 日志只记录请求 ID、耗时、状态和版本；正文默认不记。
- [ ] 建立提示注入、越狱、隐私泄漏、偏见、幻觉和拒答回归集。
- [ ] 对内容审核、客服回复和工具调用分别设置人工升级规则。
- [ ] 用合成数据完成安全测试，经过代码审查后才允许在受控环境试运行。

## 建议的测试场景

建议覆盖以下测试内容：

- 超长输入、空字符串、未知字段和非法枚举；
- 非法请求 ID、错误 JSON、404 和 405；
- Provider 首次临时失败后成功；
- 每次尝试超时、重试预算耗尽和 Provider 未就绪；
- 提示注入文字、个人信息关键词和暴力关键词；
- 无检索依据时拒答、引用冲突和过期文档提示；
- 回复中不得承诺退款、赔偿或修复时间；
- 相同输入跨运行结果稳定；
- 并发下请求 ID 不串线、错误不包含其他请求内容。

这些测试验证的是系统边界，不证明 Mock 具备真实模型效果。真实模型上线前还需建立经批准
的数据集、人工标注准则、基线、阈值、漂移监控与回滚机制。
